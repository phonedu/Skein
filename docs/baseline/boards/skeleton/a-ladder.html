断点不是新造的，是 5.4 那条规则的必然结果

设计语言已经写死：每个面板最多占窗口 45%，文档至少留 360。把它往下推，就得到四个断点。顺序固定：先让 Agent，再让列表，最后才动文档。

轨道 48 / 侧栏 198–528
Agent 330–792 / 文档 ≥360
≥ 1280四区满配
  • 列表 264、Agent 440，都能拖。
  • 文档占 47.8%，仍在 720 阅读宽度内。
  • 证据、来源链、历史在 Agent 面板的标签里，不占第五列。
1024 – 1279四区压缩
  • 列表收到 224、Agent 收到 330（都是下限）。
  • 文档先拿回宽度，不让编辑变窄。
  • 再窄就触发下一档：48+198+360+330 ≈ 936 是物理下限。
760 – 1023Agent 转覆盖
  • Agent 从常驻变右侧覆盖层，440 宽，Esc 关闭。
  • 队列与文档并排；列表仍可拖。
  • 平板横屏落在这里，竖屏退成两栏。
< 760单列
  • 列表变成整页 sheet，底栏四个入口接管切换。
  • Agent 变成整页，入口是悬浮按钮。
  • 这是现有 760 查询的边界，不新加平台分支。
四条等宽；块内百分比是该断点下各区的实际占比（轨道 / 列表 / 文档 / Agent），不是绝对像素。
