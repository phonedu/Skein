# Textus 下游工作仓 · 基线文档地图

> 给人，也给 AI 代理：**在这个仓库里做的每一件事，规划只看本目录（`docs/baseline/`），不看上游。**
> 成因：本目录的规矩修订过两次（2026-11-16），因为代理先后把上游文档当成本仓规划、把未批准方向稿当成已批准画板、把旧实现当设计参照。本文件就是防这三件事的。

## 一、三条定位（先记住这三句）

1. **软件在这里改。** 本仓是 `CatVinci-Studio/Textus` 的**下游工作仓**：`src/`、`src-tauri/` 就是要改的软件本体，不是只读镜像。上游只跟 **release tag**（现 v1.4.2），它的 main、rc、路线图与我们无关。
2. **规划只在 baseline。** 产品方向、界面目标、任务进度、全部裁决，唯一来源是 `docs/baseline/`。**与任何上游文档冲突时，baseline 赢**——不许用"上游是这么做的"替代本目录已裁的事项。
3. **上游文档只当工具书。** 仓库根 `AGENTS.md` → `CONTRIBUTING.md`、`docs/dev/*`（怎么跑门禁、怎么加字符串、测试分层）和 `docs/design/design-language.md`（token 体系）照常有效，但它们只回答"**工程上怎么做**"，不回答"做什么、做成什么样"。

## 二、界面主线（当前工作）

**目标界面 = [`boards/screens/`](boards/README.md) 十屏画板（已批准）。界面任务 = 逐屏把实现做成画板的样子，现在开工。**

- 现有实现是宿主：写代码查它的机制没问题，但**不许把它当设计或审美参照，不许再为它画对照稿、施工稿**。
- 屏的开工顺序与数据依赖见《改造任务清单》§4：不依赖新数据层的屏（笔记、设置）先做，今天 / 资产 / 确认中心等屏等 D1 数据落地。
- 除 `screens/` 外**不存在任何画板**：方向稿（directions）、骨架（skeleton）、配色对照（skins）、旧实现截图（shots）已于 2026-11-16 从仓库删除——别去找，更别把它们当目标。

## 四、给 AI 代理的读法（最小集）

接手界面 / 产品任务时，按序读：**本文件 → 《改造任务清单》（进度与顺序）→ 任务相关基线文档**（界面任务必读《界面改造方案》§4 裁决 + 目标画板的源文件）→ 只有涉及工程落地时才进上游 `docs/dev/*`。

**三个"不要"（历次出错都出在这）**：

1. **不要把上游文档当成本仓的规划或任务**——上游的 roadmap、release notes、进行中的重构都不是我们要跟的东西；
2. **不要把现有实现当设计目标**，也不为它画任何新稿——目标是 `boards/screens/` 十屏；
3. **不要自行"沿用上游做法"替代 baseline 已裁的事项**——组件库选 Base UI、设置页是浮层、编辑区单岛平铺等已裁（见《界面改造方案》§4），推翻任何一条 = 改裁决并留档，不是悄悄换做法。

## 五、两条纪律

1. **进度与裁决只写下游文档。** 上游文档是语境，B 组 rebase 时它们会变，写进去的结论会丢。
2. **冲突时的优先级：工程门禁按上游规矩跑；产品与界面决策按 baseline**（裁决以《界面改造方案》§4 为准）。改任务先改出处文档，再改清单。
