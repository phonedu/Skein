# 安装包与插件上传流程

> 本页只回答一件事：**一次 Skein 发版，构建什么、传什么、插件放哪里**。
> 裁决与进度不在这里；发版时点按 2026-11-24 的约定：改动攒批，由用户点名或一批收口时发布。

## 一句话

**安装包不打包任何插件。** APK 与 NSIS 只装应用本体；我们自己的插件
`skein.collect` 作为**独立资产**，以 `.textusplugin` 上传，用户装完应用后再装它。
官方目录里的插件不归我们发布，也不许塞进安装包。

## 一次发版传什么

以 `skein-1.4.6-slate.N` 为例，资产目录里只放这些：

| 资产 | 来源 | 命名 | 是否每次 |
| --- | --- | --- | --- |
| Android APK | release + debug 证书签名 | `Skein-1.4.6-slate.N-arm64.apk` | 每次 |
| Windows 安装包 | NSIS 构建 | `Textus_1.4.6_x64-setup.exe`（Tauri 原名，不改） | 每次 |
| 校验和 | 上面两件 + 插件 | `SHA256SUMS.txt` | 每次 |
| 插件包 | `skein-plugins/skein-collect` | `Skein-collect-<插件版本>.textusplugin` | 每次跟着带；没改就原样复用 |

**绝不出现的资产**：

- 打包进 APK / NSIS 里的插件（任何插件都不进安装包）；
- 官方目录（`textus-plugins`）里的插件——它们有自己的仓库和发布；
- `latest.json`（Levis 的）与 `textus-latest.json`（Textus 更新器的）——fork 的
  debug 构建没有更新签名，也不该被应用内更新器认领；
- `.sig` 文件；
- 源码 zip / tar（GitHub 自己会给）。

## 为什么插件不打包

- 应用与插件**各自版本**：插件升版本不该逼应用再发一版，反之亦然。
- 插件是运行时安装的：清单、平台、权限都在安装时确认；塞进安装包等于绕过
  权限流程，也绕过了插件目录。
- 官方目录由 `textus-plugins` 维护；我们只有 `skein.collect` 一个自己的插件。
- 体积：APK 已经 30MB 级，插件再进去只会让每次应用更新都重下插件。
- 测试口径：安装包装应用，`.textusplugin` 装插件，两个失败点分开定位。

## 构建

发版前先确认工作树与台账：`git status` 只包含本批改动；`npm run docs:wrap`
通过；本批的 `docs/releases/next/*.md` 片段已写。然后逐件构建。

### Android：release 构建 + debug 证书签名

```bash
# 清掉旧 APK、确保主题 accent（幂等）
node scripts/android-accent.mjs

# Tauri 的 release 产物是 *-unsigned.apk，签名在下一步
npm run tauri android build -- --apk --target aarch64 --split-per-abi
```

产物：`src-tauri/gen/android/app/build/outputs/apk/arm64/release/app-arm64-release-unsigned.apk`
（约 **29.6MB**）。未签名，**不能直接上传**；用本机的 Android debug 证书签一次：

```bash
apksigner sign \
  --ks "$USERPROFILE/.android/debug.keystore" \
  --ks-key-alias androiddebugkey \
  --ks-pass pass:android --key-pass pass:android \
  --out /c/tmp/slate.N/Skein-1.4.6-slate.N-arm64.apk \
  src-tauri/gen/android/app/build/outputs/apk/arm64/release/app-arm64-release-unsigned.apk
```

验证签名与可安装：

```bash
apksigner verify --print-certs /c/tmp/slate.N/Skein-1.4.6-slate.N-arm64.apk
# 期望：Signer … CN=Android Debug
adb install -r /c/tmp/slate.N/Skein-1.4.6-slate.N-arm64.apk
```

**不要**上传 `*-unsigned.apk`：本检出没有正式 release 签名配置，未签名的包装不上
（这正是过去几次“APK 传了但装不了”的原因）。也不要用 `--debug` 的 APK 作为
发布资产：那是给开发/CDP 调试用的 70MB、可调试包，不是测试者要装的包；本流程的
“测试包”是 **release 构建 + debug 证书签名**，发布说明里写“test build,
debug-signed”，不要写成 debug build。

### Windows：NSIS

```bash
npm run tauri build -- --bundles nsis \
  --config '{"bundle":{"createUpdaterArtifacts":false}}'
```

产物：`src-tauri/target/release/bundle/nsis/Textus_1.4.6_x64-setup.exe`
（约 **11–12MB**）。`createUpdaterArtifacts:false` 是必须的：fork 没有
`TAURI_SIGNING_PRIVATE_KEY`，开着它会在签名步骤失败；fork 的发布是手动安装包，
不需要更新器工件。构建后确认文件时间戳是本次。

### 插件：只在改过时重建

源码：`C:\Project\skein-plugins\skein-collect`（不在本仓）。

1. 改了插件：先升 `textus-plugin.json` 的 `version`，同步 README 与语言串；
   没改就跳过这一步，直接用上一版的 `.textusplugin`（文件名与字节都不变）。
2. 跑插件的两层检查（在插件目录）：
   ```bash
   node --test *.test.mjs
   node C:/Project/textus-plugins/packages/textus-plugin/cli.mjs check .
   ```
   期望：测试 `pass` 全绿、CLI 输出 `.: ok`。
3. 打包。本机没有 `zip` 命令，用 Python 的 `zipfile`（2026-11-24 实测与已发布的
   0.7.2 逐字节一致：15 个文件、67,187 字节）：
   ```bash
   python -I - <<'EOF'
   import glob, os, zipfile
   out = r"C:\tmp\Skein-collect-0.7.2.textusplugin"   # 按实际版本改
   files = ["textus-plugin.json", "README.md"]
   files += [f for f in glob.glob("*.js") + glob.glob("*.css") + glob.glob("*.html")
             if not f.endswith(".test.mjs")]
   with zipfile.ZipFile(out, "w", zipfile.ZIP_DEFLATED) as z:
       for f in files:
           z.write(f, os.path.basename(f))
   print(out, len(files), os.path.getsize(out))
   EOF
   ```
   包内是 `textus-plugin.json` 在根、README 与运行文件；**不打包** `*.test.mjs`。
4. 装一次验收：桌面扩展页“加载插件文件…”选这个包；手机同样从文件装一次，
   确认 `plugin_install` 返回的 manifest 里有 `android`。
5. 资产名：`Skein-collect-<版本>.textusplugin`。

## 上传

1. 提交并推送工作分支（推送会过 fork 闸门）：
   ```bash
   git push origin base-ui-settings
   ```
2. 把四件资产放进一个空目录，改名，生成校验和：
   ```bash
   mkdir -p /c/tmp/slate.N
   cp <apk> /c/tmp/slate.N/Skein-1.4.6-slate.N-arm64.apk
   cp <nsis> /c/tmp/slate.N/Textus_1.4.6_x64-setup.exe
   cp <plugin> /c/tmp/slate.N/Skein-collect-0.7.2.textusplugin
   cd /c/tmp/slate.N
   sha256sum *.apk *.exe *.textusplugin > SHA256SUMS.txt
   ```
3. 写 release 正文：首行写 `A debug build from <分支> at <commit>.`；从
   `docs/releases/next/` 的本批片段拼 **New / Improved / Fixed**，加一段
   **Platform notes**（debug 签名、NSIS 未签名、无更新签名）和 **Assets**
   清单；标题用 `Skein 1.4.6 — <本批一句话> (debug)`。片段不删，下一批继续用。
4. 建 release（tag、分支、四件资产一次给全）：
   ```bash
   gh release create skein-1.4.6-slate.N \
     -R phonedu/Skein \
     --target base-ui-settings \
     --title "Skein 1.4.6 — <本批一句话> (debug)" \
     --notes-file /c/tmp/slate.N/notes.md \
     /c/tmp/slate.N/Skein-1.4.6-slate.N-arm64.apk \
     /c/tmp/slate.N/Textus_1.4.6_x64-setup.exe \
     /c/tmp/slate.N/Skein-collect-0.7.2.textusplugin \
     /c/tmp/slate.N/SHA256SUMS.txt
   ```

## 传完必须验

```bash
gh release view skein-1.4.6-slate.N -R phonedu/Skein --json assets \
  -q '.assets[].name + " " + (.size|tostring)'
```

逐个对照：名称、大小、四件数量。然后下载回来校验并装一次：

```bash
mkdir -p /c/tmp/slate.N/check && cd /c/tmp/slate.N/check
gh release download skein-1.4.6-slate.N -R phonedu/Skein
sha256sum -c SHA256SUMS.txt
apksigner verify --print-certs Skein-1.4.6-slate.N-arm64.apk   # Signer: CN=Android Debug
adb install -r Skein-1.4.6-slate.N-arm64.apk   # 真机；确认能装、能开
```

再确认没有禁品：

```bash
gh release view skein-1.4.6-slate.N -R phonedu/Skein --json assets \
  -q '.assets[].name' | grep -E '^latest\.json$|^textus-latest\.json$|\.sig$' && echo WRONG
```

## 常见传错（都发生过）

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| APK 下载后装不上 | 传了 `*-unsigned.apk`，没签 | 用 `apksigner` + debug 证书签后重传 |
| 测试机装完没有“记一句”的插件 | 插件没随发版带上，或版本没升 | 传对应的 `.textusplugin`；升了版本就带新包 |
| APK 70MB、能调试 | 把 `--debug` 开发包当成了发布包 | 换成 release 构建 + debug 签名（约 30MB） |
| 插件装了被拒 “No platform android” | 插件清单缺 `android` | 修 `textus-plugin.json` 的 platforms，重打包 |
| 页面出现更新提示/更新器报签名错 | 传了 `textus-latest.json` 或 `.sig` | 删掉这些资产；fork 不走应用内更新 |
| 校验和文件对不上 | 校验和在改名/重打之前生成 | 在最终资产目录生成，再一起上传 |
