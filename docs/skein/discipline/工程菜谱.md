# 工程菜谱（本仓操作步骤）

> 日期：2026-11-20
> 性质：**操作步骤，不是裁决**。与《AI协作纪律》或任何裁决冲突时，以纪律/裁决为准。
> 上游的通用菜谱（加设置、菜单、后端命令、UI 字符串、插件 API、e2e）在 `docs/dev/recipes.md`；本页只写本仓多出来的、反复做的操作，不重复上游步骤。
> 每次做菜前先按《[AI协作纪律](AI协作纪律.md)》§一写任务六行；收尾按 §二/§四交证据。

## R1 加/改同步命令

**何时用**：改同步协议、store、merge/conflict、设置页、多库、E2EE、移动端同步。

**先读**：

- [同步协议 v1](../specs/同步协议-v1.md) §5–§8：写入不变量、发布顺序、锁、删除/冲突；
- [同步方案](../specs/同步方案.md) §3/§7：分层与一次运行的算法；
- [同步评审 README](../research/同步评审/README.md)；多库再读 `06-多库同步设计.md`；
- [STATUS](../STATUS.md) 同步行；
- [薄 fork 魔改原则](薄fork魔改原则.md)。

**分层**（不要把算法往上挪）：

```text
UI  src/settings/pages/SyncPage.tsx
IPC src/platform/ipc-sync.ts
命令 src-tauri/src/commands/sync.rs
适配 src-tauri/src/sync/（只做 I/O、设置、事件）
核心 src-tauri/crates/textus-sync/（无 Tauri，可 cargo test）
传输 S3 / WebDAV / LAN
```

**步骤**：

1. 先判是**协议内行为**还是**协议变更**。v1 已冻结；改字段含义/路径/块布局/加密参数 = 开 v2（协议 §13），不悄悄改 v1。
2. 核心逻辑写 `textus-sync`；适配层只读设置、开文件、发事件；命令写 `commands/sync.rs`，同时注册 `bindings.rs` 与 `invoke_handler.rs`；前端加 `ipc-sync.ts`；UI 只发命令、收事件。
3. 守住不变量：fail closed，不发布半份清单；发布顺序 = 锁 → 读 head/history → 缺块 → snapshot → history → head → 读回 → 放锁；`create` 必须条件写，412 读回 owner，不抢别人的锁；删除进 history，冲突 = 两份文件；路径是身份，v1 没有 rename；空扫描不得当作「远端全删」。
4. 测试：`textus-sync` 单测/向量；JS↔Rust 差分；真实 WebDAV/S3（有凭据时）；built app 验原生行为。
5. 记录：STATUS 同步行写证据；协议文档只在协议变更时改；用户可感知的变化加 release note。

**验证**：

```sh
cargo test -p textus-sync
npm run check:native
npm run check:quick
```

**不要**：把算法放适配层/UI；按窗口复制 service；跳过锁或 head 顺序；静默覆盖冲突；新代码继续写 `trash`（仅旧兼容）；只改 UI 不改事件。

## R2 加插件承载的页面/动作/确认流

**何时用**：资产闭环、侧栏页、确认卡、插件动作、插件设置。默认先问「能不能做成插件」。

**先读**：

- [插件 API 要点](../research/插件API要点.md)；
- 上游 `docs/dev/plugins/guide.md`、`pages.md`、`ui.md`（只读工具书）；
- [改造方案](../specs/Textus-改造方案.md) §5/§7；界面改动先过 [decisions/](../decisions/README.md)。

**步骤**：

1. 先定宿主还是插件：功能优先插件；宿主只做「功能挡路」的小改，且要有裁决。
2. 选面：侧栏列表 `contributes.sidebarTabs` + `views.registerList`；自绘页用 webview；确认用 `ui.confirm/pick/form/withProgress`；文件级提案用 `files.process`（token 版本化，冲突即停），不落盘提案存 `ctx.storage.project`。
3. Manifest 写清 `engines.textus`、`permissions`、`platforms`；权限按最小集。
4. 插件代码在 `textus-plugins` 仓库；用 `packages/create-textus-plugin` 脚手架，`cli.mjs check` 先静态检查。
5. 测试：`test.mjs` 替身写领域单测；Textus e2e 需要 `textus-plugins` 检出（或 `TEXTUS_PLUGINS_DIR`）。
6. 记录：STATUS D1 行；用户可感知的变化加 release note；宿主界面不改，除非另有裁决。

**验证**：`cli.mjs check`、插件单测、Textus e2e、桌面/手机真机按影响面。

**不要**：改编辑器 schema/渲染；读别的插件数据；跑原生代码；绕开 `propose_edit`/确认；为插件功能新开宿主页面。

## R3 加设置项/菜单项/字符串/测试

**通用步骤以上游为准**：`docs/dev/recipes.md` 的 Add a setting / Add a menu item and a shortcut / Add a UI string / Add an e2e test。本页只记本仓差异：

- 设置页是**浮层**（Base UI），不是页签；导航、搜索、Escape 按《界面改造方案》§3 与 [decisions/](../decisions/README.md)。
- 颜色、圆角、字号只走 token；间距 4 点网格；不写裸值。
- 每条用户可见字符串进**十个语言文件**（`src/i18n/locales/`），新 key 放在功能相邻位置；不会的语言先写英文并在 PR 说明。
- 首次点击/按键后才用的模块走 `lazyModule`；入口 chunk 预算以 `vite.startup-budget.ts` 当前值为准，变大要在 PR 说明为什么不能等。
- 测试放最低层；不为过检查改测试或 CI。

**验证**：`npm run check:quick`；相关测试；窗口栏/快捷键/输入法等原生行为在 built app 里看。

**不要**：把上游步骤抄一遍；只补一种语言；用裸色/裸字号；为过检查改 `eslint.config.js`、`playwright*.config.ts`、`scripts/check-*.mjs` 或测试期望。

## R4 界面小改/新增裁决

**何时用**：改宿主界面、手机界面、推翻旧裁决、决定某功能走宿主还是插件。

**先读**：[裁决索引](../decisions/README.md)；[界面现状盘点](../research/界面现状盘点.md)；手机任务加读手机两册；[STATUS](../STATUS.md)。

**步骤**：

1. 先找现行裁决。没有裁决就新增 `decisions/NNNN-<标题>.md`（下一编号），写清改什么、为什么、取代哪条；**用户批准后才施工**。
2. 选宿主还是插件：桌面是「小改宿主 + 插件优先」；手机是 Android 线，iOS 归上游。
3. 实现最小的宿主改动；tokens/Base UI；不碰已封存画板。
4. 证据：可见改动给截图/录屏；原生行为在 built app 验；tokens/4px/对比度按 `decisions/` 里现行裁决与现有组件检查。
5. 更新 `STATUS.md`；用户可感知的变化加 release note；旧画板已删除，不更新（裁决 29）。

**不要**：复活旧画板当目标（2026-11-20 已删除）；复活 `docs/design/design-language.md` 或 `docs/images/`；悄悄推翻旧裁决；用平台判断隐藏功能（只门控平台做不到的事）。

## R5 跟上游 tag 并线

**何时用**：下一个 release tag（最近一次：v1.4.6，合并 `457f6693`，[记录](../archive/2026-11-22-b3-v1.4.6.md)）。上游 PR 只在用户明说时按 [publishing-gate](publishing-gate.md) 的全新克隆流程做。

**先读**：[publishing-gate](publishing-gate.md)、[薄 fork 魔改原则](薄fork魔改原则.md)、[STATUS](../STATUS.md) 上游跟随行、上游该 tag 的 release notes。

**步骤**：

1. `git fetch upstream --tags`；**不追 main、不追 rc**（v1.4.6 预发布 rc.3 是已记录的清账例外，稳定 tag 发布后仍按本节走）。
2. 从工作分支新开**临时同步分支** `sync/upstream-X.Y.Z`，在它上面 `git merge vX.Y.Z --no-ff`；工作分支在这期间保持可发布。
3. 解冲突时保住 patch 清单：同步/宿主新增接入点（`Cargo.toml`、`lib.rs`、`invoke_handler.rs`、`bindings.rs`、Settings 页、移动端原生 API），以及 `docs/dev/plugin-api.md`、`docs/dev/plugins/pages.md`、`docs/dev/plugins/ui.md` 里删掉 `design-language` 链接的三处 fork-clean；不动 CI、不放宽测试、不删 fork 补丁，`docs/dev/*` 以上游 tag 为准，只保留那三处链删。
4. 跑 `npm run check`、`npm run check:native`、built app 冒烟；e2e 插件流程需要 `textus-plugins` 检出。e2e 按上游壳写的用例与 H0 壳冲突时记录差异，不为变绿改断言。
5. 验证通过后回到工作分支 `git merge --ff-only sync/upstream-X.Y.Z`，删临时分支（长期只留 `main` + 工作分支；`main` 不并）。
6. 更新 `STATUS.md` 的上游跟随行与证据，写 [archive 合并记录](../archive/README.md)（tag、合并提交、取舍、验证、未做项）；上游发布说明不搬进我们的 changelog，用户可感知的 fork 变化另写 `docs/releases/next/` 片段。

**不要**：追 main/rc；删 fork 补丁；在临时分支外直接解合并冲突；改签名/发布/商店流程；把测试指向真实用户数据。

## R6 写 release note / 收尾

**Release note**：新文件 `docs/releases/next/<slug>.md`，英文；节标题 New / Improved / Fixed / Platform notes；一条一个变化，动词开头，说用户看到什么，末尾带 issue/PR；**不改** `docs/releases/X.Y.Z.md`。

**状态**：`STATUS.md` 只写未完成 / 进行中；完成的项当日删除，证据写命令/截图/commit；里程碑收尾才在 `archive/` 留一页。

**汇报**：按《AI协作纪律》§二写完成四行；按 §四分四块写门禁读数 / AI 审查 / 人工验收 / 未验证项；文档改了就跑：

```sh
npm run docs
```

（`npm run docs` 重写 `STATUS.md` 与全部索引并检查；只想检查用 `npm run docs:check`。）

**不要**：把「未验证」写成「通过」；用一句「都通过」合并四块；把 release note 写进历史版本文件。

## R7 改文档 / 跑任务

**何时用**：新增或修改 `docs/skein/` 下的任何文档；开始、推进或关闭一个任务。

**步骤**：

1. **新建**：`npm run docs:new -- decision "标题"`（`spec` / `research` 同理）。脚本自动给裁决编号、填 front-matter、重建索引，不用手抄模板。
2. **开工**：`npm run docs:task -- brief <id> --problem … --expected … --standard … --not … --scope … --evidence …` 写入任务六行；`npm run docs:task -- start <id>` 开始时缺项会被拒绝。
3. **拿上下文**：`npm run docs:context -- <id>` 输出任务、六行、规格节、相关裁决和工程规矩；不再手工拼上下文。
4. **改完**：`npm run docs` 生成 `STATUS.md` / `INDEX.md` / 裁决索引并跑全部文档检查；只想检查用 `npm run docs:check`。
5. **完成**：`npm run docs:task -- done <id> --evidence "命令 / 输出 / commit"` 删 STATUS 行、写 `archive/` 证据、重建索引。
6. **找东西 / 体检**：`npm run docs:find -- "关键词"`；`npm run docs:doctor` 报过期规格、重复标题、缺六行的任务。

**不要**：手改 `STATUS.md` / `INDEX.md` / `decisions/README.md`；把同一事实再写进 README 地图；用修订记录代替 `git log`。
