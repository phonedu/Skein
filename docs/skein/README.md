# Skein fork · 文档入口（docs/skein/）

> 给人，也给 AI 代理：**在这个仓库里做的每一件事，规划只看本目录（`docs/skein/`），不看上游。**
> 成因：代理先后把上游文档当成本仓规划、把未批准方向稿当成已批准画板、把旧实现当设计参照、把上游界面截图当审美来源——本文件就是防这四件事的（规矩修订 2026-11-16；2026-11-17 由 docs/baseline/ 与 docs/ryugi/ 合并重组而来，编号 = 阅读顺序）。

## 一、三条定位（先记住这三句）

1. **软件在这里改。** 本仓是 `CatVinci-Studio/Textus` 的下游工作仓（fork 名 Skein）：`src/`、`src-tauri/` 就是要改的软件本体，不是只读镜像。上游只跟 **release tag**（现 v1.4.5，2026-11-18 已并线；下一节拍 v1.4.6），它的 main、rc、路线图与我们无关；跟随与发布流程见 [01-纪律/publishing-gate.md](01-纪律/publishing-gate.md)。
2. **规划只在 skein。** 产品方向、界面目标、任务进度、全部裁决，唯一来源是 `docs/skein/`。**与任何上游文档冲突时，skein 赢**——不许用"上游是这么做的"替代已裁事项。
3. **上游文档只当工具书。** 仓库根 `AGENTS.md` → `CONTRIBUTING.md`、`docs/dev/*`（怎么跑门禁、怎么加字符串、测试分层）照常有效，但只回答"**工程上怎么做**"。上游的 `docs/design/`、`docs/images/`（产品设计标准与界面截图）已从本 fork 删除——别去找，更别按它改。

## 三、界面路线（当前工作）

**桌面 = 小改宿主（v1.4.5 现状为基）；功能（笔记 Agent ＋资产闭环）= 插件承载（D1 打头）。十屏画板已封存（裁决 29，《界面改造方案》§4.6）：非权威、不施工、不勘误，待上游停止维护或 D0.5 验证通过后再议重启。**

- 改宿主界面只做「功能挡路才改」的小改，逐处裁决落《界面改造方案》§4；
- 做功能前读两份：[03-调研/界面现状盘点.md](03-调研/界面现状盘点.md)（宿主真值：每个面板的功能 / 实现 / 交互位置；手机段以 2026-11-19 后的规格为准）＋[03-调研/插件API要点.md](03-调研/插件API要点.md)（七工具 ↔ 插件 API 通道）；

- 手机端界面已开工（裁决 30/31）：**Android 线**，当前 PH1 格式工具栏；iOS 归上游；
- 同步：评审已完成、`06` 部分已定；S 组按任务清单走，**S0a 正式裁决前不改同步代码**。

## 五、给 AI 代理的读法（最小集）

接手界面 / 产品任务时，按序读：**本文件 → 《改造任务清单》（进度与顺序）→ 任务相关 skein 文档**（界面任务必读《界面改造方案》§4 裁决 +《界面现状盘点》；手机任务必读手机两册；同步任务必读 `03-调研/同步评审/README.md` + `06`；做功能必读《插件API要点》；画板已封存不作参照）→ 只有涉及工程落地时才进上游 `docs/dev/*`。开工前按 [AI协作纪律.md](01-纪律/AI协作纪律.md) 写任务六行，收尾按它交报告。

**三个"不要"（历次出错都出在这）**：

1. **不要把上游文档当成本仓的规划或任务**——上游的 roadmap、release notes、进行中的重构都不是我们要跟的东西；
2. **不要把已封存的画板当目标**（含凭空 / 错位成分）——界面以宿主现状为基，功能走插件；
3. **不要自行"沿用上游做法"替代已裁的事项**——组件库选 Base UI、设置页是浮层、编辑区单岛平铺、小改宿主＋插件优先等已裁（见《界面改造方案》§4），推翻任何一条 = 改裁决并留档，不是悄悄换做法。

## 六、两条纪律

1. **进度与裁决只写 skein 文档。** 上游文档是语境，rebase 时它们会变，写进去的结论会丢。
2. **冲突时的优先级：工程门禁按上游规矩跑；产品与界面决策按 skein**（裁决以《界面改造方案》§4 为准）。改任务先改出处文档，再改清单。
