# 同步方案（内置）

> **状态**：设计定稿，2026-11-19（S0d）；S2 主体与验收已完成（2026-11-20：本机 WebDAV built app、真实 S3 导入/增量、20k/128 MiB/失败恢复、华为真机插件互通）；S2a 多库、S2b E2EE、S6 迁移/双开均已完成；S3 内置移动端 v1 已完成（Android 构建、App Documents/普通路径、手机状态行、真机五项/App trash/杀进程/断网恢复/多库上限；content:// SAF 与后台自动同步不在 v1）；第三方 WebDAV 与七牛/阿里云真桶待外部凭据；S4 LAN Hub、S5 硬化未做。本文是内置同步的架构、边界、迁移与验收的唯一设计件；进度以任务清单为准。
> **协议**：远端读写规则以 [同步协议 v1](同步协议-v1.md) 为准；本文不重复常量与 JSON 形状。
> **前置**：S0a supersede、S0b 协议冻结、S0c spike 计划、H1–H8 宿主就位。
> **不做**：v1 不做后台同步、不做无服务器 P2P、不做多用户共享仓库、不做 CDC、不做强制签名。

## 1. 目标

- 一个库可以在多台设备（桌面/手机）之间同步 Markdown 与附件，冲突不丢。
- 多库：工作/个人/资产各一库；一库一仓库；连接可共享、密码每库一个。
- 手机前台可读写；局域网（同一 Wi-Fi）可用。
- 与官方 Cloud Sync 插件 `/1` 兼容：旧插件仍可读写同一远端，内置可迁移。
- 数据安全优先于自动化：宁可停下，不误删。

## 2. 非目标

- 不做云端服务端；只用用户自己的 S3/WebDAV/NAS。
- 不做实时协同编辑；冲突按文件副本处理。
- 不做系统级文件同步（只同步库内 Markdown 与附件）。
- 不把资产库做成第二个仓库；它是主库子目录。

## 3. 分层

```
┌────────────────────────────────────────────┐
│ UI：设置 › 同步 / 状态 / 冲突中心 / 手机   │
├────────────────────────────────────────────┤
│ 适配层 src-tauri/src/sync（Tauri 命令/事件）│
├────────────────────────────────────────────┤
│ SyncService：全局队列、runner、状态聚合     │
├────────────────────────────────────────────┤
│ 核心 crate textus-sync（无 Tauri）          │
│  planner / merge / history / publish / lock │
├────────────────────────────────────────────┤
│ Transport：S3 / WebDAV / LAN Hub            │
│ LocalFiles：普通路径 / App trash / SAF 可选  │
└────────────────────────────────────────────┘
```

- **核心 crate 不依赖 Tauri**：可用 `cargo test`、Node CLI/fixture 驱动，便于 golden vectors 与差分互通。
- **适配层只做 I/O 与事件**：读设置、开文件、写文件、trash、发进度；不放同步算法。
- **UI 只发命令、收事件**：不按窗口复制 service。

## 4. 实体与多库模型

| 实体                | 作用             | 关键字段                                                                                              |
| ------------------- | ---------------- | ----------------------------------------------------------------------------------------------------- |
| `ConnectionProfile` | 一个存储服务账号 | id、provider、endpoint、bucket、region、凭据引用、默认 prefix、网络策略                               |
| `Vault`             | 一个本地库       | `vaultId`、显示名、本地路径                                                                           |
| `SyncBinding`       | 库 ↔ 连接        | `vaultId`、`connectionId`、effective prefix、`repositoryId`、同步密码引用、自动同步、排除、暂停、只读 |
| `Repository`        | 远端 `/1` 仓库   | effective prefix 定位；head/history/lock/blocks                                                       |
| `Device`            | 本安装           | `deviceId`、设备名；base 按 `(vaultId, deviceId, repositoryId)` 隔离                                  |

规则：

- **一库一仓库**；新库 `<prefix>/<slug>-<id8>/`；迁移库沿用原 prefix。
- **连接共享**：一个连接可绑多个库；凭据一份；每个库独立密码/排除/状态。
- **库身份**：`.textus/sync-vault.json`（不参与同步）；App 数据里存镜像；库移动/改名跟着走。
- **副本检测**：同设备两个路径同一 `vaultId` → 提示分叉；不默认同时同步同一仓库。
- **一个库同时只一个远端**：切换远端是显式动作，会重建 base。
- **并发**：桌面 2 库、手机 1 库；连接级限流；同一 prefix 只一个 runner。
- **资产库**：主库子目录，随主库同步，不单独绑定。

### 4.1 远端目录：WebDAV 的真实目录与 S3 的扁平键

两个 transport 写入**完全相同的一套键**；区别只在服务端如何呈现：

```text
<连接默认前缀>/<库的 effective prefix>/
  v1/
    head.json              # 当前清单；提交点
    history.json           # 历史版本索引
    lock.json              # 这个仓库的锁
    blocks/<hash 前 2 位>/<内容 hash>
    snapshots/<revision>.json
```

多库示例（连接默认前缀 `notes`）：

```text
notes/
  work-1a2b3c4d/           # 库 Work 的仓库根
    v1/head.json
    v1/history.json
    v1/lock.json
    v1/blocks/ab/abcd...
    v1/snapshots/6f3a....json
  personal-9f8e7d6c/       # 库 Personal 的仓库根
    v1/...
old-plugin-prefix/         # 从插件迁移的库沿用原 prefix，不搬
  v1/...
```

- **WebDAV**：上面是真实目录；`v1/`、`blocks/ab/` 由 transport 逐级 MKCOL。
- **S3**：没有目录对象，`notes/work-1a2b3c4d/v1/head.json` 只是一个完整 key；控制台的“文件夹”是按 `/` 分组显示。同步只按明确 key 读写，不靠列举目录发现文档。
- `notes/` 只是连接的默认前缀，**不是仓库**；每个库的 effective prefix 才是仓库根。
- 同一连接下不同 prefix 的库互不影响，锁也各自独立。

### 4.2 仓库身份

- 明文 v1 里**没有全局 repositoryId**；仓库身份 = `connectionId + effective prefix`。
- 同 prefix 的两台设备 = 同一个仓库；同连接、不同 prefix = 两个独立仓库。
- 本地 `vaultId` 写在 `.textus/sync-vault.json`，不参与同步；新库的子仓库名带它的前 8 位。
- 加密仓库（v2）的描述符会带 `repositoryId`；明文 v1 仍以 prefix 为准。
- 本地绑定不允许两个库指向同一连接 + 同一 prefix（`repositoryInUse`），否则会争同一个 head 和锁。
- 复制库：同一 `vaultId` 出现在另一个**现存**路径时，保存返回 `vaultCopied`；设置页确认后写新 `vaultId` 并生成新子仓库，不静默共用原库身份。
- 本地 base 按 `(vaultId, repositoryId)` 命名；设备由 app 数据目录隐式隔离。库文件夹移动、身份文件跟随时，绑定与 base 跟随新路径；连接/prefix 变化则换新 `repositoryId` 并重建 base。
- 并发：桌面最多 2 个库同时同步、手机 1 个；同一库同进程只允许一个 runner（`busy` / `alreadyRunning`）。
- 删除连接不设单独危险按钮：逐个库“断开”，最后一个库断开时连接与凭据自动删除；连接默认 prefix 可在共享连接编辑中修改，只影响之后新加入的库。

### 4.3 文档身份：路径，不是哈希

- `head.json` 是 `相对路径 -> Entry` 的映射；**路径是文档身份**，`Entry.hash` 只是这份内容的身份。
- 改内容后路径不变，Entry 的整文件 hash 和块列表更新；未改的块按块哈希继续复用。
- 旧内容进入 `history.json` 的 `versions["<路径>"]`；历史、恢复和冲突副本都按路径组织。
- 两个不同路径即使内容相同，也是两个文档条目，只是共享块对象（同一仓库内按内容哈希去重）。

### 4.4 移动 / 改名 / 移动后修改

v1 协议**没有 rename 操作**，所以：

| 场景                                | 行为                                              | 结果                                                                    |
| ----------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------- |
| 同设备把 A 移到 B（内容不变），同步 | 旧路径删除 + 新路径新增；块复用                   | 远端只剩 B；其他设备看到“同哈希的远端新路径”，可把本地 A 直接 move 到 B |
| 同设备把 A 移到 B **并改内容**      | 仍是旧路径删除 + 新路径新增（哈希变了，无法配对） | 内容正确到 B；**历史留在 A**，B 从头开始                                |
| 本机移动+修改，另一设备同时改了 A   | A 在远端相对 base 变了 → 下载 `A'`；B 上传        | 两台设备同时有 `A'` 和 `B`；不丢数据，但留下两份，需要人工合并          |
| 两台设备都改到同一个 B              | 冲突副本                                          | 两份都保留                                                              |
| 先改名，另一设备编辑旧路径 A        | 编辑优先于删除 → A 上传；B 下载                   | A 与 B 并存，同样是两份                                                 |

- 同哈希的**远端改名**会被 `moves()` 识别成本地 move，避免重复下载；**本地改名**没有这个优化，按删除+新增发布。
- 历史按路径存，不跟随改名。要真正做到“改名后历史续上”，需要 v2 的文件身份或 rename 记录；只靠路径+哈希，改名+改内容与“删除+新建”不可区分。
- 因此“正确同步”的含义是**内容不丢、最终收敛**，不是“系统一定知道这是同一个文档的改名”。

### 4.5 用户如何认出哪个字符串是哪个库

- 设置 › 同步里，连接下拉显示 `provider · 主机或 bucket · 连接默认 prefix`。
- 当前库的“远端目录”就是它的 effective prefix，例如 `notes/work-1a2b3c4d`。
- 设置页的“已同步的库”列出每个本地文件夹 → 连接 → effective prefix，直接回答“哪个库写哪个字符串”。
- 子仓库名 = 文件夹 slug + `vaultId` 前 8 位：
  - `work` 来自文件夹名（非 ASCII 回退为 `vault`）；
  - `1a2b3c4d` 稳定不变，同名文件夹靠它区分；
  - 本地改文件夹名不会改远端 prefix（v1 不做远端子仓库改名），列表会用新名字显示同一个 prefix。
- 想换成更好认的 prefix，应在首次同步前改“远端目录”；已同步后再改会重建 base。

## 5. 传输

三种方式是 **transport**，不是三套协议：

| 方式              | 说明                                                       | 阶段               |
| ----------------- | ---------------------------------------------------------- | ------------------ |
| S3                | 对象存储；SigV4/条件写；AWS/R2/MinIO/B2                    | S1 spike → S2 内置 |
| WebDAV            | 对象存储；Basic/坚果云/Nextcloud；服务器差异大             | S1 spike → S2 内置 |
| LAN（WebDAV/NAS） | 对方是 WebDAV 就是 WebDAV；只是预设 + 局域网 TLS/HTTP 策略 | S2/S4              |
| LAN Hub           | 桌面内嵌本地 WebDAV/ObjectStore 服务 + 发现/配对           | S4                 |
| 真 P2P            | 无服务器直连                                               | **不做 v1**        |

- 三方式共用 planner/merge/history/冲突；transport 只实现 `ObjectStore`（get/has/put/create/remove/now）。
- `create` 必须支持「仅当不存在才创建」；WebDAV 差异在 transport 内吸收，不污染核心。
- 重定向：默认拒绝跨 host；同源重定向最多 3 次；跨 host 不转发 `x-amz-security-token`/body（H7）。

## 6. 宿主钩子（H 组）

内置同步依赖宿主提供：

| 钩子                     | 用途                                            | 任务 |
| ------------------------ | ----------------------------------------------- | ---- |
| App Documents 默认库     | 手机首次打开即可用；普通路径、原子写、mtime     | H1   |
| App 管理 trash           | 移动端删除可恢复；桌面系统回收站                | H2   |
| 空扫描/大批删除保护      | 防远端被清空                                    | H3   |
| 锁 create 修复           | 412 读回 owner；旧锁不自动抢                    | H4   |
| 状态修正                 | `deferred` 不算已同步；最后结果持久化           | H5   |
| 打开文件处理             | 干净 tab 原地重载；脏 tab defer；不丢未保存     | H6   |
| S3 403/ListBucket/重定向 | 可操作错误；安全策略                            | H7   |
| 手机插件入口/状态/事件   | `open-docs`、`file-saved`、sync→window 文件事件 | H8   |

**文件事件**：同步写入成功后发 `FILE_WRITTEN_EVENT`；打开该文件的干净 tab 原地重载（一次 undo），脏 tab 继续 defer。插件与内置共用同一事件。

**插件 API**：`open-docs` 注册表让插件打开文档；`file-saved` 让插件知道保存；同步层不直接调用插件内部。

## 7. 同步算法

### 7.1 一次运行

1. **scan**：`LocalFiles.scan()` 返回路径→Entry；空扫描保护先判。
2. **base**：读本地 base（path→hash）；没有则空。
3. **remote**：读 head/history；校验 `history.head === head.revision`。
4. **plan**：三路比较（local/base/remote）→ upload/download/delete/conflict/defer。
5. **execute**：
   - 上传缺失块（按字节 hash 校验；已存在但坏 → 重写）。
   - 下载先落临时文件，再原子替换；附件可先 trash 旧文件。
   - 删除只删本地/远端一侧；另一侧按 base 判断。
   - 冲突保留两份；不覆盖。
6. **publish**：按 S0b 顺序 snapshot → history → head；读回校验。
7. **saveBase**：只有发布成功才写 base；失败保留 pending。

### 7.2 Base 与 base 文本

- 插件 base 只有 hash；内置 base 同样以 hash 为主，但**本地 base 文本缓存**用于三方合并：
  - 缓存路径 `App data/sync/<vaultId>/<deviceId>/base-text/`；
  - 只在需要合并时读；缺失则退化为冲突副本，不猜。
- base 按设备隔离；不同设备不共享 base。

### 7.3 冲突

- 两端都改：远端保留原路径，本地写 `Sync conflicts/<path> (<device>) <time>.<ext>`。
- 冲突副本参与文件数/大小上限；不静默覆盖。
- 删除 vs 修改：修改胜出，删除进历史；不产生两份（除非内容也冲突）。
- 冲突中心（S2 UI）：列表、diff/证据、保留/删除/稍后；手机只读列表 + 处理。

### 7.4 删除与历史

- 删除 = 从 head 移除；旧内容进 history；按 `keepDays` 淡出。
- 移动端本地删除进 App trash（H2）；远端删除不回收到本地 trash，只从 base 移除。
- 空扫描/大批删除先停（H3）；用户确认后才发布删除。

### 7.5 排除

- `.gitignore` 语义；被排除路径不传、不拉、不删。
- `parked` 保存排除前 hash；重新纳入时按 base 判断。
- 资产库随主库；`asset-library/` 不是排除项。

## 8. 安全

- **E2EE 默认开**：新连接默认加密；旧明文远端保持可读，不强制改。
- **凭据**：桌面 Keychain/Credential Manager；移动 Keystore/EncryptedSharedPreferences；不写日志；Auto Backup 排除。
- **描述符 pin**：首次见到的加密描述符 hash 记住；变化 → `encryptionChanged`。
- **重定向/TLS**：禁跨 host；自签/HTTP 仅显式允许；不转发敏感头。
- **签名**：v1 best-effort；S5 加 signed head + 本地 `lastRevision`，拒绝非上次/非后代。
- **时钟**：服务器时间优先；回拨 clamp；不因设备时钟删历史。
- **诊断包**：脱敏；不含 token/密码/密钥/文件内容。

## 9. UX

### 9.1 设置 › 同步

- 顶部：全局状态（“2 个库同步中 / 1 个冲突”）+ 同步全部 + 全部暂停。
- 列表：每库一行（库名、连接、prefix、状态、最后同步、冲突数）。
- 选中库：连接、加密、排除、自动同步、历史、冲突中心、解绑。
- 新库默认**不自动同步**；“同步全部”不是默认行为。

### 9.2 状态词

- 已是最新 / 同步中 / 部分完成（deferred）/ 有冲突 / 需要处理 / 已暂停 / 未配置。
- `deferred` 不显示“已同步”；最后结果持久化；失败可重试。
- 手机首页脚注/库切换 sheet 显示当前库状态点；编辑器可看状态。

### 9.3 冲突中心

- 列表：路径、时间、设备、两份大小；可 diff/打开/保留/删除/稍后。
- 手机：列表 + 打开 + 保留/删除；diff 可只读。
- 不静默覆盖；冲突中心入口在设置 › 同步与状态条。

### 9.4 只读

- `SyncBinding.readOnly`：手机可只下载不上传；冲突副本也不产生。
- 默认关闭；用户可在库设置开启。

## 10. 迁移、共存、回滚

### 10.1 从插件迁移

1. 扫描 App 已知 recent folders + 当前库；对每个 root 计算插件配置 key。
2. 列出可迁移库；用户勾选；每库独立 dry-run（上传/下载/冲突/大小）。
3. 导入连接/凭据与 base（用户同意）；插件 base 只有 hash，base 文本缓存不存在时标记“合并退化”。
4. 停用该库插件 → 首次内置同步 → 验证。
5. 迁移成功后才卸载插件；卸载会永久删插件 base/secrets。

### 10.2 双开阻断

- 已实现（S6，2026-11-20）：同步页每次加载读两处——`plugins/state.json` 里插件是否启用，以及该 root 的插件 kv 是否有 `config:<sha256(root)>`。
  - 插件启用且配置存在 → 危险提示：先停用插件对该库的同步、验证内置首次同步、再卸载；提供「打开插件」；手动同步前再确认一次。
  - 插件已停用但配置仍在 → 提示可以卸载（卸载只删插件本地记录，云端不动）。
  - 不自动停用插件；不自动改插件设置；不删插件数据。
- 内置目前只有手动同步，没有自动同步。自动同步落地时必须在每次运行前重查；仍双开则跳过自动运行（手动同步允许）——“宁可慢，不可乱”。

### 10.3 回滚

- 已实现（S6）：同步页「断开」删除内置 binding/base/last（连接仅在无其他库使用时删除）；插件配置、凭据、base 与云端对象都不动。
- 插件配置仍存在时页面常显回退说明；首次同步失败或验证不满意时，点「断开」再重新启用插件即可。两套 base 不同，回退后第一次插件同步预期做一次对账，可能产生少量冲突副本。
- 若插件已卸载：重装并重输连接与密码，作为新设备加入；远端仍是 `/1`，数据不受影响。
- 回滚不自动执行；由用户点「断开」并自行启用插件。

## 11. LAN Hub

- 桌面内嵌本地 WebDAV/ObjectStore 服务（只服务已配对设备）。
- **v1 配对方式（已定）**：桌面显示本地地址（如 `http://192.168.1.20:7419`）与一次性 6 位配对码；手机在“连接局域网库”里输入地址 + 码。**不做 mDNS/自动发现**（权限与跨平台成本高），二维码作为后续便利项，不是 v1 发现机制。
- 防火墙/休眠：Hub 只在局域网监听；睡眠/退出时手机同步失败要可操作。
- 不新造 P2P 协议；手机连 Hub 就是 WebDAV transport。
- 安全：每设备 token；只读/读写权限；只绑定 RFC1918 地址，不暴露公网；LAN 明文 HTTP 只在显式开启且带一次性配对码时允许，TLS 在 S5 补。

## 12. 验收矩阵

| 场景                  | 预期                                                   |
| --------------------- | ------------------------------------------------------ |
| 桌面单库首次/增量     | 远端文件正确；旧插件可读                               |
| 手机前台单库          | 新建/改/删/改名/冲突通过；杀进程/弱网收敛              |
| 两设备同一库          | base 按设备；冲突两份；状态可见                        |
| 两库同连接不同 prefix | 独立同步；状态分别可见；一个 401 不影响另一个          |
| 同设备复制库          | 提示分叉；不允许同时同步同一仓库                       |
| 库改名/移动           | binding 跟随；远端 prefix 不变                         |
| 解绑                  | 远端不动；其他库继续                                   |
| 插件 + 内置同一库     | 显示双开警告；自动同步（未实现）须跳过；手动同步前确认 |
| 空扫描/大批删除       | 中止/二次确认；远端不误删                              |
| 锁被占                | `locked`；不自动抢                                     |
| 清单损坏              | 只停该库；不反复重试                                   |
| LAN Hub               | 手机同 Wi-Fi 直连；睡眠/防火墙错误可操作               |
| 加密仓库              | 新连接默认开；旧明文可读；描述符变化拒绝               |
| 迁移                  | dry-run → 导入 → 停插件 → 验证；失败可回滚             |

## 14. 已收口的决定

| #   | 决定               | 结论                                                                 |
| --- | ------------------ | -------------------------------------------------------------------- |

| 2   | 新库布局           | `<prefix>/<slug>-<id8>/`；迁移库沿用原 prefix                        |
| 3   | 加密密码           | 每库一个；同连接可不同；可复用非强制                                 |

| 6   | 解绑               | 不删远端；删远端是单独危险动作                                       |
| 7   | 同步全部           | 不默认自动；用户明确开启                                             |
| 8   | 资产库             | 主库子目录，随主库同步                                               |
| 9   | 库身份             | `.textus/sync-vault.json`，不参与同步；App 数据镜像                  |
| 10  | 同一库多远端       | 不允许同时；切换远端显式重建 base                                    |
| 11  | 后台               | v1 仅前台；后台单独立项                                              |
| 12  | 多用户共享仓库     | 不支持；共享桶用不同 prefix                                          |
| 13  | 只读               | binding 可选；默认关闭                                               |
| 14  | 远程子仓库改名     | 第一版不做                                                           |
| 15  | 同一仓库多设备     | 必须同 provider/prefix/密码；不同 provider 不能指向同一仓库，UI 拒绝 |
| 16  | 多用户共享仓库     | 不支持；共享桶请用不同 prefix                                        |
| 17  | 同步全部用哪个连接 | 按每库自己的 binding；不需要全局默认连接                             |
| 18  | LAN 配对           | 地址 + 一次性 6 位码；不做 mDNS/自动发现                             |

## 15. 风险

| 风险                | 影响               | 缓解                                            |
| ------------------- | ------------------ | ----------------------------------------------- |
| history/head 非原子 | 旧客户端读到不一致 | 读侧 `history.head` 校验；不拿坏 history 做删除 |
| 锁无 lease          | 崩溃留锁           | 手动 unlock；v2 lease                           |
| base 文本缺失       | 合并退化           | 冲突副本优先；不猜                              |
| SAF 非原子/无 mtime | 手机本地丢文件     | H9 条件任务；v1 默认 App Documents              |
| 插件双开            | 同一库两套 base    | 绑定阶段检测/阻断                               |
| S3 权限/重定向      | 同步失败或泄露     | H7 文档 + 策略                                  |
| 大库性能            | 首次慢/超时        | 分块、并发、进度；20k 基准                      |
| 测试覆盖不足        | 数据事故           | golden vectors + 真机矩阵 + 差分互通            |

## 16. 测试与基准

- 单元：planner 三路矩阵、merge、history 淡出、锁 412、空扫描、冲突命名。
- 向量：S0b §12；fake store + Node CLI。
- 差分：官方插件 ↔ 内置，双向读写同一 `/1`。
- 性能：20k 文件/128MB 单文件/32MB 传输预算；记录首次/增量/内存。
- 真机：华为 PKT0220512001548；杀进程/弱网/锁屏。
- 安全：重定向、TLS、凭据、诊断脱敏。

## 17. 一句话

**一库一仓库、连接共享、每库密码、前台优先；协议冻结 `/1`，内置 Rust 只做 transport 与宿主钩子；先插件拿真机数据，再逐步接管。**
