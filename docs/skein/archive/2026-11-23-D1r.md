## 2. 发现与处置

| 严重度 | 发现 | 处置 |
| --- | --- | --- |
| **阻断** | 详情页的 `_history` 版本路径可以按“包含本卡历史目录文本”通过校验；页面再交回宿主时可能作为绝对路径 / 带前缀路径被 `layout.open` / `readText` 解析到本卡目录之外。 | **已修**：`loadHistory` 只把 finder 的 **vault-relative `rel`** 交给页面；`inHistory` 只接受**相对**路径、且必须是本卡 `_history/<id>/` 的**直接子文件**（拒绝绝对路径、`..`、子目录、别的卡、前缀卡号）；`openDetailFile` 按这个 `rel` 重新 `find` 出 finder 的绝对路径再给 `layout.open`（窗口的 open 需要绝对路径）。补测试覆盖 `..`、绝对、嵌套、`A-10`/`A-1-old`、斜杠/盘符。桌面与 Android 模拟器实测“对比 / 打开”均通过。 |
| **重要** | 关闭详情标签页后再从列表选另一张卡，会沿用旧标签的 `detailWanted`，打开旧卡。 | **已修**：`detailWanted` 只在“没有已连接详情页”时作为**一次性**目标；`resolve` 取用后立即清空；最后一个详情页 dispose 时清空；`openDetail` 在页面已连接时不再留全局目标。真实桌面复现“A-1 详情 → 关标签 → 点 A-2”现在打开 A-2；单测覆盖。 |
| **重要** | 同一窗口有两个详情视图时，其中一个的来源跳转会通过全局 `detailWanted` 影响另一个。 | **已修**：来源 `show` / `pin` 不再改全局目标，只更新发起页自己的 `page.path`；另一个页面的 refresh 仍按自己的状态。两个 fake view 的单测覆盖。 |
| 小 | `inHistory` 是子串判断：嵌套文件、`A-10` / `A-1-old` 前缀、绝对路径都可能混入。 | **已修**：直接子文件 + 相对路径 + 本卡目录的段比较；`loadHistory` / `versionDiff` / `openDetailFile` 共用。 |
| 小 | `_usage` 行的数组、空对象、无 `at`、对象型 `taskId` 会被当成一次使用或显示 `[object Object]`。 | **已修**：一行必须是带字符串 `at` 的对象；`context` / `taskId` / `result` 非字符串按空处理；坏行计入 `skipped`，页面显示“N 条记录无法读取”。 |
| 小 | 单行超长正文可能卡住 webview；没有总量/行长上限。 | **已修**：宿主正文上限 200k 字符 + `bodyTruncated` 提示；页面单行上限 8k 字符。 |
| 小 | 详情 `<article>` 没有可访问名称。 | **已修**：`aria-labelledby="card-title"`。 |
| 小 | 日期用系统 locale，而不是 Textus 选择的语言（中文 UI 里出现英文日期）。 | **已修**：详情与确认中心的日期改用 `api.language`；模拟器复验中文日期。 |
| 小 | `detailWanted` 跨库：切换文件夹后仍指向旧库的卡。 | **已修**：根变化清空全局目标与各页路径，`pushDetail` 重新取新库第一张卡。 |
| 小 | 触控 40px（App 手机档）、计数西文数字、历史 50 条无截断提示、取消对话框无专门提示。 | **接受**：与 App 现有手机控件/文案一致，不影响 D1e 验收；记 `STATUS.md` §5。 |
| 小 | “围栏代码未受保护 / `_` 被当斜体” | **不复现**：解析器先处理围栏，且行内强调只认 `*`/`**`/反引号，不认 `_`；不改。 |
