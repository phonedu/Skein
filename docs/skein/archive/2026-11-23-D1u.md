# D1u — 插件界面样式对齐宿主（2026-11-23 完成）

> 工作线：D1 · 验收：插件四个页面（收集面板、确认中心、卡片详情、资产列表）与宿主 Slate 皮肤一套视觉；令牌桥接方案有小裁决；桌面 + 手机截图走查；webview 内不写原始颜色/圆角/字号。

## 任务六行

- **problem**：插件 webview 是沙箱 frame，宿主的 --ui-*/--shape-*/--text-* 令牌进不去，页面自带一套浅灰样式，与宿主界面两种观感、非常割裂（用户 2026-11-23 复看指出）。
- **expected**：宿主向 webview 桥接令牌（CSS 变量注入或 postMessage 主题包，方案先裁决），四个页面按界面契约重排，深浅色跟随宿主。
- **standard**：桌面 + 手机 built app 走查截图；webview 内样式只用桥接令牌；手机断点（320dp）可用；插件单测全绿。
- **not**：不改宿主皮肤；不做与主题系统的深度联动（归 T1）；不改插件功能与确认流。
- **scope**：skein-collect 的四个页面、宿主令牌桥接（插件 API 或 view state）、插件 0.6.0。
- **evidence**：走查截图与插件测试输出。

## 证据

插件 0.6.0；node --test 96/96；cli check ok；宿主 e2e collect-plugin 2/2（新增令牌桥断言：frame 的 --ui-bg/--ui-text/--ui-muted/--text-body 与宿主一致）；桌面 harness 浅/深两态截图（C:/Project/d1u-verify/detail-light/dark.png、confirm-light.png）；Android 模拟器详情页截图 emu-10.png（文档纸色+宿主令牌）；裁决 62 落地

## 实现

- 裁决 62：宿主侧 `textus.appearance.colors()`（无权限，API 1.6+）取开环色，`confirm-core.hostTokens()` 推导中间色（muted/border/subtle/hover/surface）并映射 `--doc-*`，随 state/detail 消息的 `tokens` 字段下发；`appearance.onDidChange` 重取重发。页面 `applyTokens(vars)` 只写 CSS 变量。
- 静态档位（字体、字号、间距、圆角、条高）由 `confirm-core.TOKEN_TIERS` 提供，不随宿主界面大小缩放。
- 页面背景改为 `var(--doc-bg, var(--ui-bg))`，与官方插件页（kanban/canvas）同口径。
- 插件 0.6.0；README 记录桥的做法；`e2e/collect-plugin.spec.ts` 新增 frame 令牌断言（宿主与页面同色）。

## 边界

- 主题/配色的实时切换在桌面 harness 验证（emulateMedia 深色后页面即时跟随）；真机只验了浅色态（模拟器）。
- 插件自设色（appearance.setColors）不参与，留给未来的主题工坊联动。
