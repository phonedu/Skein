## 2. S2-2 规模 / 失败恢复

新增 `textus-sync/tests/scale.rs`，4 个引擎测试（2026-11-20，43.6 s）：

| 场景 | 断言 |
| --- | --- |
| 20,000 个文件 | 首轮上传 20,000；改 1 个文件后只上传 1、下载 0；远端 manifest 20,000 项 |
| 128 MiB 单文件 | 首轮上传 1；另一设备下载 1，字节数 134,217,728 |
| 同步中被杀（块上传中丢弃 future） | 远端锁保留；下一轮报 `locked`；手动清锁后完成，history 只有一个 current、一个 head |
| 块上传瞬时失败（5xx/断网同类） | 返回 `httpError`；锁释放；重试上传成功；再编辑一次后 history 只有一个旧版本（无重复） |

另在 `webdav.rs` 增加状态映射单测：401→`permissionError`、429→`rateLimited`、507→`quotaError`、500→`httpError 500`。传输超时由 transport 的 20 s 连接 / 180 s 总超时兜底，未做 180 s 真实挂起测试。32 MiB 传输预算仍是已知缺口，归 S5。

## 3. S2-3 真机 / 真服务器跨端

**设备**：华为 PKT0220512001548（OXF-AN10），Android 版 Textus 1.4.5；官方插件 `catvinci.cloud-sync` 0.6.1 从本地包安装、授权并在真机运行。
**远端**：缤纷云 S3，bucket `textus`，prefix `textus/s23`（明文 `/1`，测试后 12 个对象已清空）。

- **手机插件 → 桌面内置**：手机插件上传 `Notes/a.md`（上传 1）；桌面 Rust 引擎以空 base 读同一仓库，结果 `unchanged 1`、无上传/下载，说明 layout 与清单一致。
- **桌面内置 → 手机插件**：桌面引擎改 `a.md` 上传 1；新增 `Notes/b.md` 上传 1。手机插件下一次同步下载 1（`b.md` 真机文件内容逐字节一致）。
- **冲突副本命名**：手机改 `b.md`、桌面改 `b.md` 后手机同步，报“上传 1、下载 1、保留 1 份冲突副本”；副本为 `Sync conflicts/Notes/b (0a3ba749).md`，与 Rust `path::conflict_path` 的格式一致；本地版本留在原位，远端版本进副本。
- **锁互认**：插件写入的锁让 Rust 引擎报 `locked`；Rust 形状的锁让手机插件报“另一台设备正在同步…”并拒绝。两边都按 `v1/lock.json` 的 `id/startedAt` 互认。
- **清理**：测试 prefix 对象已删除；手机临时凭据文件、测试 vault、插件安装与连接均已移除。
