## 1. 完成内容

| 层 | 落地 |
| --- | --- |
| 描述符 | `v1/head.json` 明文：format、repositoryId(UUID)、PBKDF2-SHA256 600000、32 字节 salt、verifier；pin = 描述符规范 JSON 的 SHA-256 |
| 密钥 | PBKDF2 → master；HKDF-SHA256 按 repositoryId 派生 content(AES-256-GCM) / names(HMAC-SHA256) |
| 对象 | `TCS2` + 12 字节 IV + AES-GCM 密文/tag；AAD = 描述符 JSON + `\n` + 逻辑对象键 |
| 命名 | 块名 = HMAC-SHA256(nameKey, `v1/blocks/..`)，按前 2 位分目录；history/snapshot/probe/pending 映射到 `v2/*.bin` |
| 明文边界 | 只有 `v1/head.json` 描述符和 `v1/lock.json` 锁是明文；旧客户端看到 e2ee format 即拒绝 |
| 越界/损坏 | 密码 12–1024；`legacyRemote`、`invalidEncryptionMetadata`、`invalidSyncPassword`、`encryptionChanged`、`encryptedDataInvalid`、`encryptionMetadataMissing` |
| 初始化 | 探针 → 取锁 → 写描述符 → 读回/pin 校验 → 放锁；绝不写明文 head 兜底 |
| 每库密码 | `sync_secrets.json` 的 `vaults[vaultId]` 存 password + pin；不进连接凭据；库移动跟随；断开/最后库清理 |
| 设置页 | 新库默认“加密此仓库”；密码输入/12 字符提示；已存密码锁定不可改；已有明文库可切到加密并提示不会转换 |
| 命令 | `sync_run_saved`/`sync_history`/`sync_restore` 自动识别描述符并包 `EncryptedStore`；锁命令保持明文；加密仓库的锁不需要密码 |
| 传输 | WebDAV/S3 的传输池 idle 超时 4 秒，避免加密 KDF 停顿后复用服务端已关闭的连接 |

## 2. 验收证据

- **插件 ↔ Rust 加密对象双向互解**：插件生成描述符/密文 → Rust 解锁解密；Rust 生成 → 插件解锁解密（2026-11-20，临时夹具已删）。
- **built app + 真实 WebDAV**：
  - portable `tauri build --debug` 首次加密上传 1 文件，状态“同步完成”；
  - 远端只有 `v1/head.json` 描述符 + `v2/head.bin/history.bin/blocks`，无明文 history；
  - 二次编辑上传 1；云端历史显示并可恢复旧版本；
  - 错误密码显示“加密密码错误，或加密数据已损坏。”
- **真实 S3（缤纷云 S4）**：引擎级两个 `EncryptedStore` 客户端对同一桶/prefix 完成加密上传/下载 round-trip，pin 校验通过；测试 prefix 的已知对象已清理。
- **加密引擎 round-trip**（MemoryStore 两设备）与加密仓库 lock/密文名/重开密码测试。
- 测试：`textus-sync` 39 单测 + 17 引擎 + 4 wire；应用 `sync::` 25；SyncPage 6；十语 69。
