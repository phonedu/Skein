# 同步插件多端 spike 计划（S0c）

> **状态**：已执行轨 0（S1/S1b，2026-11-19）；轨 A/B 未跑。执行前置 = H1–H8 就位、插件 manifest 加 Android、协议 v1 冻结（S0b）。
> **目的**：用华为真机拿到「手机前台能否可靠读写同一 `/1` 仓库」的真实数据，决定内置同步的范围与顺序；不是承诺插件成为长期方案。
> **结论先行**：spike 只证明 **普通路径 + 前台 + 文本与附件 + 冲突不丢**；SAF 任意目录、后台、系统 trash 不在 spike 承诺内。

## 1. 三条轨

| 轨    | 库位置                                                      | 目的                                                | 是否必须 | 预期                         |
| ----- | ----------------------------------------------------------- | --------------------------------------------------- | -------- | ---------------------------- |
| **0** | App Documents（`getExternalFilesDir(Documents)`，普通路径） | 验证数据通路、原子写、mtime、附件、WebView crypto   | 必须     | 除 trash/后台/状态条外全通过 |
| **A** | 所有文件访问 + 用户文件夹（`/sdcard/...`）                  | 验证授权持久化、跨卷 move、华为「所有文件」页面     | 建议     | 通过则作为可选库位置         |
| **B** | SAF `content://`                                            | 只验边界：插件被拒、提示出现、重启后 grant 是否还在 | 只验边界 | **不解禁 gate**；不承诺可用  |

**顺序**：轨 0 → 轨 A → 轨 B。轨 0 失败则停止，先修宿主；轨 A 失败不阻塞轨 0 结论；轨 B 只记录，不据此修改协议。

## 2. 通过标准（任一轨）

必须同时满足：

1. **不误删远端**：空扫描、锁失败、清单损坏时，远端文件数不减少；宁可停在 `needsAttention`。
2. **不半截**：强杀进程/断网后，本地与远端都没有 0 字节或截断文件；重跑能收敛。
3. **冲突两份**：两端同时改同一文件，稳定得到两个文件；不静默覆盖。
4. **旧端可读**：桌面官方插件不升级仍能读写同一远端；手机写入的 head/history 能被桌面读。
5. **错误可操作**：不支持的操作（trash、SAF 二进制、后台）有明确错误，不假装成功。
6. **性能可用**：1000 个 20KB 文本 + 20 张 1MB 图片，首次同步与增量同步在可接受时间/流量内（记录数字，不设硬门槛）。

## 3. 华为真机清单

设备：`PKT0220512001548`（OXF-AN10，Android 12，1080×2400，HarmonyOS）。

前置：

- [ ] 安装 debug APK（`adb push` + `pm install -r -d`，见任务清单装机注记）。
- [ ] 清空测试库；不用用户真实目录。
- [ ] 准备两个远端：MinIO（S3）与 Nextcloud 或坚果云（WebDAV），各一个空 prefix。
- [ ] 桌面装官方插件 0.6.x，能读同一远端。
- [ ] 手机与电脑同一 Wi-Fi（LAN/WebDAV 轨）。

用例（每条记录：步骤、结果、截图/日志、耗时、流量）：

1. 新建库/连接，首次同步空仓库。
2. 新建 10 个 Markdown、2 个子目录；同步；桌面看到。
3. 手机改一个文件，桌面改另一个；同步；两端收敛。
4. 两端同时改同一文件；同步；冲突两份。
5. 手机删一个文件；同步；桌面进入历史/回收语义（见 H2）。
6. 桌面删一个文件；手机同步；本地删除不产生冲突。
7. 手机重命名文件/文件夹；同步；桌面路径更新。
8. 上传 1MB/5MB 图片；附件随主库；桌面可打开。
9. 同步中强杀进程；重开；不出现半截/重复文件。
10. 断网 → 改文件 → 恢复；重试收敛。
11. 锁被另一设备占用；提示 `locked`；不自动抢。
12. 空扫描保护：清空本地测试库（base 非空）→ 同步必须中止，远端文件数不变。
13. 大批删除：删 60% 文件 → 二次确认；拒绝后远端不变。
14. SAF 轨 B：选 `content://` 文件夹；插件入口被拒；提示明确；重启后 grant 状态记录。
15. 后台：锁屏/切后台 30 分钟；记录是否继续/暂停；不承诺。

## 5. 三条轨的判定

### 轨 0（App Documents）

- **通过**：1–14（除 SAF）通过；旧端可读；无远端误删。
- **失败**：任一安全线破 → 停止 spike，先修宿主/协议，不进入内置。
- **结论用途**：确定内置 S2 的 `LocalFiles` 普通路径实现与 H1 默认库。

### 轨 A（所有文件访问）

- **通过**：授权持久化、跨卷 move、华为「所有文件」页面可用；用例 1–10 通过。
- **失败**：记录具体 API（list/stat/move/二进制写）；不阻塞轨 0。
- **结论用途**：决定「所有文件访问」是否作为可选库位置；商店政策另议。

### 轨 B（SAF）

- **只验边界**：插件被拒、提示、grant 留存；**不解禁 gate**。
- 若轨 B 显示 SAF 是唯一可行路径，才启动 H9；否则 H9 关闭，保留 App Documents 普通路径。

## 6. S3 → WebDAV 顺序

1. **S3 先**：SigV4/条件写/对象存储语义最接近协议；用 MinIO 本地验证。
2. **WebDAV 后**：服务器差异大（MKCOL/MOVE/HEAD/If-Match、弱 ETag、坚果云限流）；用 Nextcloud/坚果云验证。
3. **LAN**：只要对方是 WebDAV，就是 WebDAV；内置 Hub 留到 S4，不在 spike 做。

## 7. 记录与产物

- `docs/skein/research/同步评审/spike-报告.md`（新文件）：每轨结果、耗时/流量、失败 API、截图路径、结论。
- 失败项必须给「最小复现 + 期望/实际 + 影响」；不写「大概能用」。
- 数据只进报告，不改协议；协议变更走 S0b 的 v2 硬切条件。

## 8. 停止条件

- 轨 0 出现一次远端误删或本地丢文件，且无法从快照/冲突副本恢复 → 立即停止，回滚测试库。
- 锁/清单损坏导致无法收敛，且修一次需要改协议 → 停止，回 S0b。
- 手机前台单次同步 1000 文件超过 10 分钟或流量异常 → 记录并评估，不直接内置。

## 9. 与内置的关系

- spike 通过 = S2 可以开始；不通过 = 先修宿主/协议，不写 Rust 同步核心。
- spike 的插件分支只在本机/私有 fork，不推上游；报告与结论进 `docs/skein/`。
- 内置发布后插件冻结为 `/1` 参考实现；spike 报告是内置验收矩阵的输入。
