## 1. 完成内容

宿主不动；全部在插件侧：

- **资产详情页**（`skein.collect.detail`，webview）：资产列表的行（点击或右键「查看详情」）打开卡片自己的页面，不再直接打开 Markdown；「打开卡片」保留原行为。
  - **内容**：正文按安全 Markdown 子集渲染（标题 / 列表 / 引用 / 围栏 / 强调，全部用 DOM 节点，不用 innerHTML）；资产显示适用边界、不适用条件、反例、触发（阶段 + 标签）、复用形态；任务显示预期结果、实际结果、偏差。未填字段显示「未填写」，不编造。
  - **证据 / 来源链**：`source_ids` 逐条解析成来源卡（类型、状态、日期；缺失的 id 标「卡片不存在」），并反查引用本卡的卡片（被引用）。点来源卡在同一详情页打开它，页内「返回」沿链回退；详情页记住当前卡（`setState` + `pin`），标签页重建后仍打开同一张卡。
  - **历史**：`use_count` / `verified_count` / `last_used_at` 与复用结果（好于 / 达标 / 不如 / 不评价）分开展示，并明写「用过不等于验证过」；逐行显示 `_usage/<card-id>.jsonl`（时间、场景、结果、任务），坏行跳过；下面是 `_history/<card-id>/` 的快照，「对比」显示旧版本到当前版本的 diff，「打开」打开快照。取历史只认本卡目录，`versionDiff` 与 `openDetailFile` 都拒绝别的卡。
  - **写入仍走 D1b**：请求变更状态、记一次使用走原有 `requestTransition` / `recordUse`；本卡的待确认请求显示在详情头（目标 + 数量），一键进确认中心。详情页自身不写任何文件。
- **确认中心的可见性刷新**：页面用 `api.onDidChangeVisibility`（窗口告诉页面标签是否在眼前）在重新可见时主动要一次队列；确认 / 驳回 / 稍后之后还有一次 1 秒重试。已经打开的确认中心、详情页在切回时不再停在旧状态；打开确认中心的命令/详情按钮也会补一次 `pushState`。
- **列表**：行增加「查看详情」动作；点击行打开详情。
- **手机**：同一页单列渲染（≤720 CSS px 时字段上下排列、按钮到触控高度），从插件启动器（今天 → ⋯ → 插件 → 资产 → 行）全屏打开；确认中心同样可从详情头的「确认中心」进入。
