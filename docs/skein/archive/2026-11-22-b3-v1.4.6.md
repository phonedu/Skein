## 1. 分支流程（以后跟 tag 照这个走）

1. `git fetch upstream --tags`
2. `git switch -c sync/upstream-1.4.6 base-ui-settings`
3. `git merge v1.4.6 --no-ff -m "Merge upstream v1.4.6 into the fork"`
4. 解冲突、`git add`、提交；新提交必须在临时分支上，不直接动工作分支。
5. 验证：typecheck、ESLint、Prettier、`check:repo`、全量 vitest、cargo lib、textus-sync、桌面/Android smoke。
6. `git switch base-ui-settings && git merge --ff-only sync/upstream-1.4.6`
7. `git branch -d sync/upstream-1.4.6`；只留 `main` + `base-ui-settings`；`main` 不并。
8. `git push origin base-ui-settings`（gate 通过后）。

这是**临时同步分支**的用法：合并期间工作分支保持可发布；验证完再快进，避免把未验证的冲突解直接放到工作分支。长期仍只有两条常驻分支。
