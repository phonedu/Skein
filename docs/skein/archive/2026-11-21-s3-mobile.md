# S3 内置移动端归档（2026-11-21）

> **状态：v1 完成**。Android 真机能用内置同步：应用文档库、以及应用有普通路径访问权的文件夹；前台手动同步，App trash、冲突、锁恢复与状态面齐全。
> 设计依据：[同步方案](../specs/同步方案.md) §13、[Android 移动端评审](../research/同步评审/02-Android移动端评审.md)。
> **不在本片**：content:// SAF 任意目录（H9 条件任务）、后台自动同步（U4 已裁 v1 仅前台）、iOS。

## 1. 完成内容

| 层 | 落地 |
| --- | --- |
| Android 构建 | `uuid` 移到共享依赖；`SyncRunners` 在共享 builder 注册（原先只在 desktop builder）；aarch64 debug APK 真机安装 |
| 默认库 | 手机首页无打开文件夹时显示 App Documents 树；空态提供“使用应用文档”；Sync 页从已存 openFolder 解析 folderRoot，不依赖设置层的旧副本 |
| 状态面 | 首页文件树上方显示内置同步行（尚未同步 / 同步完成 / 出错），点击进 Settings › Sync；15 秒刷新 |
| 普通路径任意目录 | 应用有 `MANAGE_EXTERNAL_STORAGE`（用户授权）时，SAF 选的目录以普通路径出现，内置同步可扫描/读/写（真机 4554 目录验证） |
| content:// 授予 | 只能通过 content grant 读写的目录（无“所有文件访问”）显示“系统授权打开，内置同步无法直接读写”，保存/预览/同步禁用，引导用 Cloud Sync 插件 |
| App trash | 远端删除落到手机时，本地文件移到应用私有 trash 并写 record；真机验证 |
| 锁恢复 | 32 MiB 上传中杀进程 → 远端锁保留；重启后 `sync_lock` 可见，解锁后续传成功 |
| 弱网 | 24 MiB 上传中断网 → `networkError`；恢复网络后锁仍在，解锁重试上传 1 成功 |
| 多库 | 同一连接绑定两个库（4554 + App Documents），库列表可见；手机并发上限 1，第二个运行返回 `busy`，第一个结束后可运行 |

## 2. 真机验收证据

**设备**：华为 PKT0220512001548（OXF-AN10），Android 版 Textus 1.4.5（debug，portable 数据），应用有所有文件访问。
**远端**：缤纷云 S3，bucket `textus`，测试 prefix（已清空）。

- **五项**：App Documents 与 4554 普通路径上完成新建/修改/删除/改名/冲突；冲突副本 `Sync conflicts/... (hash8).md`，本地留原位。
- **UI**：手机设置页直接跑同步，App Documents 32 MiB + 其他文件显示“上传 3”；首页状态行随之为“同步完成”。
- **删除**：远端删 `c.md` 后手机同步，`c.md` 与 `record.json` 出现在 `/data/data/com.catvinci.textus/trash/<stamp>/`。
- **杀进程**：32 MiB 上传中 `am force-stop`，重启后锁在；`sync_unlock` 后上传 1 完成。
- **断网**：24 MiB 上传时关 Wi-Fi/数据，返回 `networkError`；恢复网络、解锁后上传 1。
- **多库**：两个库同连接不同 prefix；第二个并发同步返回 `busy`；先后运行均成功；设置页库列表显示两行。
- **content grant**：路径守卫单测覆盖提示与按钮禁用；真机 4554 普通路径不触发守卫。

## 3. 不在本片

- **content:// SAF 任意目录（H9）**：需要 ContentResolver 的 list/stat/二进制写/原子替换/trash 全链路；v1 明确只支持普通路径，content grant 引导用插件。
- **后台自动同步（U4）**：v1 仅前台手动同步；后台 WorkManager/前台服务单独立项。
- **iOS**：S3 是 Android 线；iOS 跟随上游。
- **真实慢速网络**：断网与传输超时已覆盖；限速代理未跑。
