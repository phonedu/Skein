# 裁决 30 — 手机端按成熟移动形态开工

## 决定

| 事项           | 裁决                                                                                                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 开工           | §4.6 说手机端「挂 D0/D3 触发」——本裁决 = **触发提前，现在开工**。成因：用户判宿主手机端是把桌面界面**原样塞进手机**（48px 轨道、推入侧栏、连**文档页签**都搬了过去），完全没有成熟移动应用的形态 |
| 形态原则       | 按成熟移动应用形态重排：底栏导航、全屏页面、移动式浮层 / sheet；**桌面元素（页签、轨道、侧栏）不原样上手机**。具体重排方案 = 现状在模拟器跑起来、截图盘点后再裁（先红后绿的「红」）              |
| 端与验证       | **Android 线**：本机模拟器（Xiaoshidan_API35）+ `tauri android dev` 开发验证；**iOS 不做**（归上游自己，用户不用苹果）；真机验证仍归 D0                                                          |
| 上游           | fork 侧产品形态改造，**默认不提上游**；上游将来若做手机端美化，是否取用我们的形态由他们自己定（用户原话口径）                                                                                    |
| 与裁决 29 关系 | 29 的「小改宿主＋插件优先」对**桌面**不变、插件线继续；本裁决只是把手机端从「挂触发」提前为「开工」，同为 fork 侧形态工作                                                                        |
| 工程前置       | `tauri android init` 已跑（`src-tauri/gen/` 生成物**不入库**，.gitignore 已加——B2 rebase 保持干净）；工具链本机齐备（SDK/NDK 28.2/API 35/Rust 四目标/JDK 17）                                    |
