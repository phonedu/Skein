# 裁决 58 — 图标尺寸回归平台档位

## 决定

**撤掉 56 的 `--icon-growth` 全局倍率和 57 的局部追补，改回“少量档位 + 一次线宽”的平台做法**（2026-11-23 用户复看：当前仍偏大、没有以前协调；只比原来稍大即可，不再参考 Obsidian）。

落地值：

1. **不再有全局图标倍率**：删除 `--icon-growth`；`iconSize()`、`iconMarkup()`、`tx-icon` 遮罩、手机手绘图标都只吃各上下文原有的 `--icon-scale` 和 `--chrome-scale`。
2. **全局档位**：桌面 `--icon-scale` **1.40**（原 1.35 × 1.1 = 1.485），手机 **1.35**（原 1.2 × 1.3 = 1.56）。桌面 16px 设计约 22.4px，手机约 19.6px。
3. **线宽**：`ICON_STROKE` **1.35**（原 1.15；56 的 1.5 再乘全局倍率后约 2.2–2.6px，太重；2026-11-25 由 1.45 再收一档）。绝对线宽下桌面约 1.9px、手机约 1.8–2.1px。
4. **手机同一屏一档，按绘制尺寸而不是倍率对齐**（`--icon-scale` 是总倍率，局部声明会覆盖根值）：
   - 今天/库顶栏的设置、⋯、库图标：局部 **1.6** → 设置/库（15px 设计）约 **21.8px**，⋯（16px）约 **23.3px**；
   - 设置页行图标：局部 **1.55** → 17px 设计约 **24.0px**（Material 的 24dp 量级；56 的 31、57 的 28 都太大）；行尾 chevron 局部 1.2 → 约 19.6px；
   - 库树文件与文件夹图标都 1.6 → 约 **21.8px**（原文件 1.4、文件夹 1.47，两者不齐）；树的 disclosure 1.4 → 约 12.7px；行尾 ⋯ 1.4 → 约 20.4px；
   - 今天行的文件图标 1.55 → 约 **21.1px**；
   - 手机编辑器条：返回箭头 22px 设计 × 1.1 = **22px**，Textus AI 16px × 1.5 ≈ 21.8px，手绘 ⋯ 写入 22px、按 10/11 画约 **20px**。
5. **桌面**：根 1.40，原局部倍率整体保留并微调——文件树 1.2 → **1.25**（约 18.8px），设置导航 1.15 → **1.25**（约 21.3px），设置搜索 1.15 不变（约 19.6px）；其余只吃根档位，16px 设计约 22.4px。比 56 前略大，比 56/57 小。

## 理由

- 主流应用不靠“每个视图一个倍率 + 再叠一个全局倍率”来调图标：它们给界面定义**少量档位**（Material 24dp、iOS 24–28pt、桌面 16/20px），图标的线宽在一个档位内固定，靠留白和字重协调。我们原来的 1.1/1.2/1.24/1.35/1.4/1.43/1.47/1.55/1.6 是历史手调值；再乘一个全局 1.3，等于把历史误差一起放大。
- 用户要的是“比以前稍大一点”，不是“整体放大一档”；24px 手机档位把顶栏、设置行、今天行拉到同一视觉尺度，避免“库图标变了、设置没变”。
- 线宽（裁决时为 1.45，2026-11-25 收到 1.35）比原 1.15 明显加粗，但不至于像 1.5 × 1.3 那样压住文字；24px 档位下约 1.6px 手机线宽，是 Material/iOS 图标常见的比例。

## 影响

- 删除 `--icon-growth` 及其在 `iconSize`、`iconMarkup`、`icon-masks`、`ds-buttons`、手机手绘图标里的乘法；56/57 的局部值按本条归一。
- 手机设置行图标从 1.4 × 1.3（约 28px）→ 1.55（约 24.0px）；今天/库顶栏从 1.47 × 1.3（约 26–28px）→ 1.6（约 21.8–23.3px）；设置行图标契约测试改 1.55，PhoneHome 的 1.43/1.47 契约改 1.4/1.6。
- 不再参考 Obsidian；后续图标评审以“同屏档位是否一致、线宽是否压字”为准，不再加全局倍率。

## 补记（2026-11-25）

用户复看：“我感觉我们现在的图标线条有点粗了。”第 3 条线宽由 **1.45** 收到 **1.35**，其余档位不变：桌面约 1.9px、手机约 1.8–2.1px；仍比裁决 56 之前的 1.15 粗，保留“比原来稍大稍重”的方向。
