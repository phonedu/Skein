# 裁决 68 — D3 手机入口与插件页导航

## 决定

| 事项     | 裁决                                                                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 方案     | D3 的手机入口、插件页导航与冲突入口以 [D3-手机入口与插件页导航](../specs/D3-手机入口与插件页导航.md)为准；分片 D3a–D3e，逐片验收。                                                                 |
| 今天页   | 在「当前交付」与「今日变更」之间加插件组：按插件分组，组标题用插件显示名；行 = 插件状态项的文本与命令，一次点击到目标页。不用固定「资产」标题，不在宿主写死插件名。                                   |
| 资产行   | `skein.collect` 增加 `assets` 状态项（`资产 · N 张卡` → `skein.collect.assets`）与对应命令；只在 `ios` / `android` 发布，桌面状态条不变。                                                             |
| 打开列表 | `layout.showSidebarTab` 对插件 list 页按表面翻译：手机 / 折叠整页，桌面 / 平板右页边；官方插件的同类调用一并受益。                                                                                     |
| 列表行   | 触屏 list 行尾常显 ⋯（打开现有菜单）；鼠标下随行 hover 出现；行本身仍开详情。                                                                                                                         |
| 插件页 ⋯ | 不显示文档动作（大纲 / 查找与替换 / 源码模式 / 分享…）；显示该页的 `view/title` 贡献、命令面板…、插件。关闭页面仍走标题后的页签 sheet。                                                              |
| 启动器   | 页面在前、命令在后；与同插件页面标题相同的命令不单列（确认中心、月度复盘各一次）。                                                                                                                     |
| 返回     | 只给应用内打开的页签记一层来处（`openPluginTab`、插件桥打开的文件 / 未命名页）；返回有来处回来处，否则回今天；不关页签、不新增页面栈。细化裁决 67 的「返回键回 Today」，67 其余不变。               |
| 冲突     | 有冲突或上次失败时今天页一行「同步：N 个冲突」→ 设置 › 同步（维护区展开）；冲突中心的页面与动作归 S14/S15，D3 只接入口与「打开」。                                                                   |
| 不做     | 系统分享收集（默认不做）；桌面小组件 / 通知；第二套插件路由；宿主写资产业务逻辑；文档页 ⋯ 内联全部插件命令。                                                                                         |

## 理由

- 2026-11-27 用户走查 390×844：插件入口要 ⋯ → 插件 → 启动器三次点击，10 项还重复；资产列表的操作只能长按；插件页的 ⋯ 是文档菜单；详情返回回今天。日常闭环「收集 → 次日确认」只剩前半在首页。
- 今天页是手机的唯一日常入口（裁决 34）；状态项本是插件向今天页 / 状态条报「待确认」的既有机制，把资产行也走这条，不新增插件 API。
- 插件页 = 普通标签（裁决 67）不变；返回只记一层来处，修 D1e 的返回栈，不引入第二套页面模型。
- 冲突已有设置页的维护区，D3 不做第二套冲突界面，只保证「有冲突看得见、点得到」。

## 影响

- 宿主：`PhoneToday`、`PhoneEditorBar`、`PluginListView`、`plugin-launcher`、`App` / `useBackStep`、`useSidePanels`（`showSidebarTab`）；新增单测与 phone e2e。
- 插件：`skein.collect` 0.7.x 增加 `assets` 状态项与 `skein.collect.assets` 命令（manifest 命令 + runtime status item）；计数与文案复用现有 l10n。
- 裁决 67 的返回一句由本裁决细化；67 的标签模型、平板 / 桌面规则不变。
- 无插件 API 变更（仍是 `ui.statusItem` / `layout.showSidebarTab`）。

## 来源

2026-11-27 用户指出「插件在移动端不好用：操作全在更多里，点插件才看得到」；同日走查与三项裁决（今天页标题 = 插件名、返回 = 记来处、资产行只手机）。方案见 [D3-手机入口与插件页导航](../specs/D3-手机入口与插件页导航.md)。
