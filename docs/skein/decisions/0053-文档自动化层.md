# 裁决 53 — 文档自动化层

## 决定

- **`status.yaml` 是进度源**，`STATUS.md` 由 `npm run docs:status` 生成，禁止手改。
- **任务六行进数据结构**：`docs:task -- brief <id> …` 写入，`start` 缺项拒绝，`done` 删除 STATUS 行、写 `archive/` 证据并重建索引。
- **新文档用命令创建**：`docs:new -- decision|spec|research "标题"` 自动编号、填 front-matter、重建索引。
- **AI 上下文按任务生成**：`docs:context -- <id>` 输出任务六行、规格节、相关裁决和工程规矩，`--max-chars` 限长；不指定任务时输出全局包。
- **查找与体检**：`docs:find -- "关键词"` 搜标题、摘要和正文；`docs:doctor` 报过期规格、重复标题、缺六行的任务。
- **一键生成与检查**：`npm run docs` 重写 STATUS / INDEX / 裁决索引并跑 `docs:check`；CI 的 docs job 跑同一命令。

## 理由

上一轮重排解决了“文件放哪、索引靠手写、修订记录塞正文”，但日常仍有四类手工：改 STATUS 表、抄裁决模板、拼 AI 上下文、翻目录找文档。把它们变成命令后，人只读生成页，AI 从结构化数据取上下文；流程可重复，也不依赖会话记忆。

## 影响

- `STATUS.md`、`INDEX.md`、`decisions/README.md` 是生成物，不手改；`status.yaml` 由 `docs:task` 维护。
- 任务六行从“汇报里写一遍”变成“先写进 status.yaml，start 时校验”；汇报仍抄一遍给人看。
- 文档改动的最小闭环：`docs:new` / `docs:task` → `npm run docs` → commit。
- 旧的手写 `STATUS.md` 内容已迁入 `status.yaml`；以后只维护 YAML 和任务命令。
