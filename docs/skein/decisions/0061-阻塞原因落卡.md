# 裁决 61 — 阻塞原因落卡

## 决定

**确认转 `blocked` 时，把原因写进卡片 front matter 的 `blocked_reason`；离开 `blocked` 时清空该字段。** 原因不再只活在待确认请求里。

1. `confirmRequest` 对 `target: blocked` 且带原因的请求，`extra` 附 `blocked_reason`（复用 done 阈值的 extra 通道）。
2. 从 `blocked` 转出（`active` / `done` / `archived`）时，`extra` 附 `blocked_reason: ""` 清空，不留陈旧原因。
3. 拒绝（reject）的原因维持现状：随请求记录、确认中心展示，不落卡。
4. 审计不变：confirm 审计仍存 request id，不复制原因。

## 理由

D1d 验收发现 B：阻塞原因在确认前全程可见，确认后 pending 被删除、审计只有 request id，原因随确认动作消失。blocked 的语义就是"卡住 + 为什么卡"，原因不在卡上，复盘（`variance` 对照）与次周回顾都拿不到它。写在卡上与 `actual_outcome` / `variance` 的落卡口径一致。

## 影响

- 插件 `confirmRequest` 的 extra 计算 + `confirm-core.applyTransition` 无需改动（extra 透传）；新增单测：转 blocked 落 `blocked_reason`，转出清空。
- 详情页已有字段渲染通道，`blocked_reason` 随字段显示（如需要单独标签，后续 D1t/样式任务顺带）。
- 确认中心展示逻辑不变。
