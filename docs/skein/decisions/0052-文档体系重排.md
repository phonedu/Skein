# 裁决 52 — 文档体系重排

## 决定

- **单一入口**：`docs/README.md` 是文档总图，`docs/skein/README.md` 是 fork 规划入口；`AGENTS.md` 只做 AI 路由。
- **按用途分目录**：`discipline/`、`specs/`、`decisions/`、`research/`、`archive/`，取消 `01–05` 编号。
- **生成索引**：`INDEX.md` 与 `decisions/README.md` 由 `npm run docs:index` 生成，检查发现过期即失败；不再手写目录。
- **裁决分片**：一条裁决一个不可变文件，编 ID；推翻用 `supersedes`，不改旧文。
- **单一状态页**：`STATUS.md` 只写未完成 / 进行中；完成项当日删除，里程碑才在 `archive/` 留证据。
- **无修订记录**：活文档不写版本号和变更表；`git log` 是历史。
- **归档冻结**：`archive/` 只增不改；活文档需要归档里的结论时，把结论搬回活文档。

## 理由

旧体系把同一事实写在 README 地图、任务清单、方案正文和修订记录里；任务清单 102 KB 中 70 行是变更史，界面方案同时是规格、裁决表、证据和 backlog，裁决 29/30/31 没有可检索的编号行。上游 Textus 的低维护来自“文档低 churn、规则脚本化、索引生成、fragment 化”，本决定把同一套机制用于 fork 的规划文档。

## 影响

- 新方案进 `specs/`，新决定进 `decisions/`，新证据进 `research/`，新规则进 `discipline/`，进度只改 `STATUS.md`。
- 每次文档改动跑 `npm run docs:index && npm run check:skein`；索引文件禁止手改。
- 旧任务清单、旧裁决表和旧修订记录由 git 历史保留，不另建快照。
