# 裁决 67 — 插件页在手机与平板的宿主

## 决定

| 事项 | 裁决 |
| ---- | ---- |
| 标签模型 | 插件页和文档一样，是**普通标签**；`tab.view.kind` 决定画什么，不为插件另造一套页面栈。 |
| 手机 | 插件标签成为当前标签时，手机进入 **doc 表面**，顶部沿用文档页的返回/标题栏；不新增“插件页”第四种 surface。 |
| 平板 | 插件标签在标签行里，与桌面相同；插件自己的列表/侧栏挂在标签内容里，由插件视图渲染，不塞进宿主右栏。 |
| 桌面 | 不变：插件页在标签里，右栏只放 AI 或插件目录。 |
| 触控 | 容器带 `pointer: coarse` 布局，`page-drag.js` / `webview-input.js` 在 frame 内生效；宿主不再按平台关掉插件页。 |
| 不做的 | 不为手机/平板单独维护插件页路由、选择器或第二套标签；不把插件页塞进右栏；不按平台隐藏插件。 |

## 上游怎么做、想达成什么

上游 1.4.7 把插件页当作**普通标签页**：

- 打开插件页 = `openPath`/`openPluginPage` 建一个 `tab.view`，标签行与文档标签同一套。
- 手机/平板只是同一套标签在不同宽度下的布局；插件页不额外 gate。
- 插件自己的 UI（看板、标签、列表）在 frame 内用 `page-drag.js`、`webview-input.js`、`plugin-ui.css` 处理触控，宿主只负责给足容器。
- 目标是**一个标签模型**：插件页和文档页在打开、关闭、切换、触控上走同一条路，不为平台复制逻辑。

## 我们这个壳怎么改

1. **手机**：`phoneView` 由“当前标签是否存在”决定；插件标签也是当前标签，进入 `doc`。`PhoneEditorBar` 的标题/返回对插件页同样有效。
2. **平板**：沿用桌面的标签行与 `PluginTabPane`；插件自己的列表/侧栏由插件视图在标签内渲染，不进宿主右栏。
3. **宿主**：`DocumentIslands` 对手机/平板不再跳过插件 `tab.view`；容器统一带触控布局，frame 运行时照常注入。
4. **验收**：手机/平板 `plugin-touch`、`phone-plugins` 用同一套标签行为；不再出现“手机上插件页打不开、平板上 Tags 找不到”的分叉。

## 影响

- 不再为插件页维护平台分支；后续合并上游插件页改动只跟标签模型走。
- 手机多一个“插件页也是 doc”的入口，返回键回 Today，不新增页面栈。
- 平板的插件侧栏属于插件内容，不属于宿主右栏；右栏仍只放 AI/插件目录。
- B7 遗留的 3 条 plugin-touch 按本裁决一起修，不再逐条打补丁。
