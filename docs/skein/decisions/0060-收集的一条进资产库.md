# 裁决 60 — 收集的一条进资产库

## 决定

**记一句（`skein.collect.capture`）收下的一条写进资产库：`asset-library/inbox/<id>.md`，与 `create_draft` 的任务同一目录、同一套卡生命周期。** 不再写 `<vault>/inbox/`。

1. `notePath` 从 `inbox/<id>.md` 改为 `asset-library/inbox/<id>.md`；收下后打开的相对路径随之调整。
2. 资产库只读 `asset-library/**`，不变；收下的一条即"待整理"卡，进资产列表、确认流与检索。
3. 既有 `<vault>/inbox/` 下的旧收集（开发期测试数据）不迁移、不兼容读取；插件 0.5.x 起目录以此为准。
4. 宿主不参与路径裁决：两端"记一句"都优先走插件命令（App.tsx `captureNote`），改插件一处即覆盖桌面与手机。

## 理由

D1d 验收发现 A：快速收集写 `<vault>/inbox/`，而资产库读 `asset-library/**`，收下的一条保存成功却进不了资产列表、确认流和检索——收集闭环断在第一格。`create_draft` 的任务草稿已经走 `asset-library/inbox/`（裁决 39 的目录），快速收集没有理由另立一套。收下即待整理，是"收集 → 次日确认"理论的第一步。

## 影响

- 插件 `putNote` / `notePath` 一处改动 + 单测；`host.test.mjs` 的收集路径断言更新。
- 手机 Today 的"今天改动"与桌面侧栏 Today 依旧能看到文件（文件树层面），且现在资产列表也可见。
- 旧位置 `inbox/` 不再被插件写入或读取；已有测试数据不迁移。
