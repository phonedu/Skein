# 裁决 51 — 同步 supersede（S0a）

## 决定

- **fork 自建内置同步**，作为 Skein 的产品能力，不要求上游接受这套实现。
- **插件先做多端参考实现，内置随后接管**；插件冻结为 `/1` 参考，不再双维护。
- **手机端前台可读写**；后台同步不作为 v1 承诺，单独立项。
- 不做自建云 / 账号；同步只走用户自己的 WebDAV / S3 / LAN。

## 理由

插件只声明桌面与 iOS，Android 不在 manifest 内；即使补上 Android，`files.trash`、SAF `content://`、二进制写、mtime、原子写、后台同步都补不齐，base 只存 hash 也没有三方合并。手机 ↔ 电脑同步、多库、资产库随主库同步是当前最大痛点，必须由宿主承担。先用插件拿 1–3 周真机数据，再上 12–22 人周的内置实现，风险最低。

## 不可越过的安全线

1. 远端不误删：空扫描、大批删除、锁失败、清单损坏时宁可停下。
2. 本地不半截：先临时文件/对象，再原子替换；失败保留原文件。
3. 冲突一定两份：不做静默覆盖；冲突副本命名稳定、可读。
4. 迁移可回滚：导入前 dry-run；插件先停用后卸载；卸载前确认 base 已迁移。
5. 不泄露凭据：日志、错误、诊断包不含 token/密码/密钥；E2EE 新连接默认开。
6. 旧客户端仍可读：`/1` 不因 fork 新字段而拒绝；v2 硬切时 fail closed 并提示升级。

## 退出条件

出现一次无法恢复的远端误删或本地丢文件、迁移失败率超过 10%、上游发布可互通的官方多端同步、连续两个上游 tag 的 rebase 需要改同步核心超过 2 人周——任一条件即暂停内置并评估回滚。
