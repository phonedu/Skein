# 裁决 62 — 插件界面令牌桥接宿主开环色

## 决定

**插件的 webview 页面（确认中心、卡片详情等）的配色，桥接到宿主开环色；不自创主题包，不自建桥。**

1. **用现成 API，宿主侧取色**：`appearance.colors()`（无权限，API 1.6+）只在宿主 `textus` 对象上，webview 页面的 `acquireTextusApi()` 没有它——所以由插件 host.js 取色（`appearance.colors()` 的最终渲染值，含主题与其它插件层），经 `confirm-core.hostTokens()` 推导成 frame 变量，**随 state/detail 消息的 `tokens` 字段下发**；已打开的页面另收一条 `type: "tokens"`。`appearance.onDidChange`（换主题/换配色）时重取重发。
2. **页面只落变量**：confirm.js / detail.js 的 `applyTokens(vars)` 把 tokens 写到 `document.documentElement`，不自己取色、不自己推导。
3. **开放色之外自行推导**：`--ui-muted/--ui-border/--ui-subtle/--ui-surface/--ui-hover` 不在开环表里，在插件侧由三大主色 mix 推导（muted 60% 文字、border 16%、subtle 6%、hover 8%、surface=bg）；`--ui-danger` 取 `--tone-red`。
4. **静态档位**：字体栈、字号（body 15/caption 12/title 17…）、间距（4 点网格）、圆角（s 8/xs 4）、条高（bar 40/control 34）按[界面契约](../specs/界面契约.md)桌面档写进注入的变量——这些不随宿主界面大小缩放，是插件的固定档。
5. **CSS 不改架构**：四页样式早已写成 `var(--ui-*)`，此前只是 frame 里没人定义；桥上变量即收敛，硬编码色零容忍（`check-design-values` 口径）。
6. **不做**：与自定义 CSS/主题工坊的深度联动、宿主界面向插件的实时逐 token 同步、插件自设色覆盖宿主（`appearance.setColors` 不用）。

## 理由

插件页面与宿主割裂的根因是沙箱 frame 里没人定义 `--ui-*`，全部 `var()` 落空回退浏览器默认——不是样式写错，是令牌没到。上游 1.6 起就提供 `appearance.colors()` 读宿主最终渲染色（含其它插件层），"先找现成方案"：直接用它，不发明 postMessage 主题包。推导色按宿主文档"边线悬停跟随主色"的口径，在插件侧以透明度 mix 复刻，Slate 深浅两态都成立。

## 影响

- skein-collect 新增共享 `tokens.js`（两页 html 引用），单测覆盖映射与推导；版本 0.6.0。
- 宿主后续新增开环色或改推导口径时，`tokens.js` 随插件更新。
- 其它自带界面的插件可照抄这一桥（写进界面契约 §4 弹层行）。
- 视觉验收：确认中心 + 详情页在宿主 Slate 深浅两态下截图对比，桌面 + 真机。

## 来源

2026-11-23 用户复看插件截图："页面与我们现在的界面两种样式，非常割裂……估计都得重做"；D1u 立项时发现 API 已有 `appearance.colors()`（现成方案优先）。相关：[裁决 59](0059-界面契约成为上游适配基准.md)、[界面契约](../specs/界面契约.md)。
