# 裁决 54 — 上游与日常流程自动化

## 决定

- **上游合并七步都有命令**：`upstream:status` → `upstream:plan` → `upstream:start --apply` → `upstream:clean --apply` → `upstream:verify` → `upstream:record` → `upstream:finish --apply`。读步骤只读；动 git 的步骤必须显式 `--apply`。
- **上游 PR 候选三件套**：`upstream:ticket` 生成工单草稿，`upstream:patch` 导出排除私有路径、CI、`.claude` 和 fork-clean 文件的补丁，`upstream:gate` 手动跑闸门。
- **release note 有命令**：`release:new` 生成 fragment，`release:check` 校验，`release:build -- X.Y.Z` 收进版本文件。
- **日常验证分层**：`npm run verify`（docs + release + check:quick）用于收尾，`verify:full`（check:all）用于发布前；`build:debug` / `android:build` 用于桌面与真机。
- **命令索引生成**：`commands.yaml` 是元数据源，`npm run docs:commands` 生成 `COMMANDS.md`；命令不存在或索引过期即失败。

## 理由

fork 的反复折腾有两类：跟上游 tag 的七步手工 git、以及日常的验证/发布/真机步骤。把它们写成命令后，读的部分一条命令，写的部分默认 dry-run、`--apply` 才执行；命令说明不再散落在对话和记忆里。

## 影响

- 跟 tag 先跑 `upstream:status` / `upstream:plan`；合并期间用 `upstream:clean` 处理 `gate.mjs` 的 `absentPaths`，不再手抄删除清单。
- 上游 PR 的补丁不再手工拼 `git diff` 的 excludes；仍按 `publishing-gate.md` 的全新克隆流程执行，闸门仍是最终裁判。
- `COMMANDS.md` 不手改；`commands.yaml` 加命令，`docs:check` 保证它对应真实的 npm script。
- `verify` 不替代 built app / 真机 smoke；脚本只打印手测清单，证据仍由人写进完成四行。
