# 裁决 56 — 图标全局放大与加粗

## 决定

**图标全局放大并加粗，桌面与手机同一套，不只调移动端**（2026-11-23 用户反馈：图标大小、线条粗细都偏小/偏细，手机上尤其明显；Obsidian 的图标大小合适）。

落地：

1. 新增全局倍率 `--icon-growth`：桌面 **1.1**，手机 **1.3**；与各处的 `--icon-scale`、`--chrome-scale` 相乘，而不是替换它们。列表、设置、工具栏、面板、空态、手机行等原有局部 `--icon-scale` 保留其相对关系。
2. 图标线宽 `ICON_STROKE` 从 **1.15** 提到 **1.5**（绝对线宽，随图标倍率与 chrome 倍率换算；桌面约 2.2px，手机约 2.1px）。这是“线条细”的主因——之前桌面约 1.5px、手机约 1.25px。
3. 覆盖范围：`icons.tsx` 的 `iconSize()`（全部 Lucide 图标）、`iconMarkup()`（块把手 / 表格加号 / 修订对勾等编辑器内图标）、`icon-masks.css` 的 `tx-icon`（插件页与设置页的遮罩图标）、手机手绘的 ActionSheet 图标；插件 webview 通过设计系统 CSS 拿到同一组 token。
4. **不调**：Windows 窗口标题栏的最小化/最大化/关闭（系统约定的 10×10 发丝线，不属应用图标）；文档正文里的图片/表情等内容图形。

## 理由

- 旧值：`ICON_STROKE = 1.15` 配合 `absoluteStrokeWidth`，桌面实际约 1.5px、手机约 1.25px；16px 设计图标桌面绘 21.6px、手机约 17.5px。视觉上确实比 Obsidian 一类笔记工具小一档、细一档。
- 用户是界面裁决人；这次明确要求“全局都调，不要只调移动端”。按 Obsidian 的图标存在感对齐，而不是只放大某一端。
- 用倍率叠加而不是重写每个局部值：FileTree 的密集列表、ActionSheet 的 32px 图标块、手机 56/62 行里的 20–22px 图标都保留各自的设计意图，只是整体抬一档。

## 影响

- 不改变布局结构、行高、点击区域；只改图标绘制尺寸与线宽。局部 24/28/32px 图标块仍容纳得下（手机 32px 块内 20px 图标按 1.1×1.3×10/11 绘制约 26px）。
- 手机壳的计算样式契约测试若断言旧像素值，按新裁决更新；不改测试来掩盖实现错误。
- 插件页与宿主共用 token，不需要插件各自改 CSS；插件若自带硬编码图标尺寸，仍以自身 CSS 为准（后续抽查视觉）。

## 来源

2026-11-23 用户反馈与要求（“图标的大小以及粗细还是好小…调图标一定要全局都调”）；对照 Obsidian 的图标观感。相关：[裁决 36 Slate 皮肤 v2](0036-Slate-皮肤-v2-定稿.md)、[裁决 35 全面 UI 审查](0035-全面-UI-审查后的追加裁决.md)。
