# 裁决 59 — 界面契约成为上游适配基准

## 决定

1. **`docs/skein/specs/界面契约.md` 是上游界面的适配基准**：令牌、桌面/手机模式、图标档位、屏幕索引和每条规则的执行测试都写在里面。裁决仍是最高权威；本文件把裁决落成可查的数值与模式，不改写裁决。
2. **新增 `e2e/ui-contracts.spec.ts` 与 `npm run test:ui-contracts`**：按计算样式与绘制尺寸检查桌面窗口栏、侧栏、标签、格式栏、设置弹窗，以及手机 Today、编辑器条、设置列表；`npm run upstream:verify` 默认执行 `test:phone-shell` 和 `test:ui-contracts`。`phone-settings-shell` 保留为设置壳的深度契约。
3. **上游新增界面先归入契约中的模式**：没有对应模式时先写裁决，再补契约数值、屏幕索引和断言；适配与断言是合并的前置，未适配的界面不合并。
4. **不建手工画板**：截图只作合并记录的证据（裁决 55），不是规范；规范只在本文件、裁决和计算样式测试里。

## 理由

v1.4.6 的回归是运行时被上游选择器压掉：设置行被竖排、组卡双线、代理输入黑框、主题工坊两栏。静态文档和画板不参与构建，拦不住这类回归；只有对最终计算样式和绘制尺寸的断言会在合并时失败。把“该长什么样”与“谁在执行”放在同一份文档里，适配新上游界面时有据可查，也不会出现第二份会漂移的权威。

## 影响

- `upstream:verify` 多跑一个 spec（本机约 15 秒）；合并流程的界面步骤以 `界面契约` 为准。
- 每个上游新屏都要补对应断言；`ui-contracts` 目前未覆盖的库树、Today 改动等，在契约第 6 节标为待补，补上后再进合并门禁。
- `test:phone-shell` 与 `test:ui-contracts` 分工：前者是设置壳的深检查，后者是桌面/手机关键屏的横向覆盖面。

## 来源

用户 2026-11-23：要防止上游界面回归再次发生；需要一份详细的界面样式权威文档与索引，用现有样式基准去适配上游新界面；画板不用了。
