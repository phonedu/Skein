# 裁决 63 — 月度复盘与淘汰周期

## 决定

**把《笔记资产理论》§4 的 7 天规则、§7.5 的淘汰时间线和月度复盘落成一条可执行的周期；两处 30 天的口径以此为准。**

1. **时间线**：
   - active 资产 7 天未调用 → 「未验证」标签（沿用裁决 26）；
   - 30 天未调用 → 「待淘汰」候选，进入当月复盘列表，**不自动改状态**；
   - **连续 3 次月度复盘的未复用名单**里都出现 → 才提议 `deprecated`；弃用走 D1b 的确认流（`requestTransition`），不直接写盘；
   - confirmed 判断 90 天未被任何任务 `source_ids` 引用 → 「复查」标签（不降级，只提醒）。
2. **复盘记录**：每次完成月度复盘，写 `asset-library/_reviews/<YYYY-MM>.md`，front matter 带 `month`、`at`、指标（复用率/复用成功率/台账率）、`unused`（本次未复用 id 列表）、`decided`（本次动作）；正文写三个问题的答案。记录是 md，和卡片一样可读、可 diff；连续周期由这些文件按月份倒推计算。
3. **三个问题与四个动作**：复盘页列出——哪条判断被结果证伪（列出被有偏差任务引用的 confirmed 判断）、哪个资产一次没用过（active 且 `use_count` 0）、哪个字段几乎没人填（各字段空置率）；动作是改判断、删资产、删字段、**修数**。
4. **修数（补记使用）**：绕过工具的真实使用（直接抄文件、无插件时复用）允许人工补记：日期（不得晚于今天、不得早于卡片创建）、场景、结果；写一条 `_usage` 记录并把 `use_count` +1、`last_used_at` 取较晚者，`verified_count` 不动。补记不经过 AI 工具，是插件命令。
5. **口径**：复用率 = 30 天内用过的 active 资产 / 排除观察期（激活未满 30 天）的 active 资产；复用成功率 = 结果为好于/达标的使用次数 / 有结果的使用次数；台账率 = 30 天未复用且无结果的 active 资产 / 同上分母。返工率暂不计算（任务没有返工字段，等 D1 线补字段后再加）。

## 理由

理论 §4 写「7 天标记未验证、30 天降级或归档」，§7.5 写「30 天标记未验证、连续 3 周期 deprecated」，两处冲突会让实现各取一半。月度复盘是理论的执行动作，不落成记录就无法证明「连续 3 个周期」；用 vault 里的 md 记录，既是证据也可人工检查。淘汰必须走确认流：自动改状态违背 D1b「所有状态变更经确认」的裁决。

## 影响

- 插件新增复盘引擎（纯函数：指标、三问、周期计数）、复盘页与「月度复盘」命令、补记使用命令；插件 0.7.0。
- `asset-library/_reviews/` 是新目录：卡片加载与列表要跳过它（像 `_history`/`_usage`）。
- 复盘页是 webview，沿用裁决 62 的令牌桥。
- 返工率留待任务卡有返工字段后补。
