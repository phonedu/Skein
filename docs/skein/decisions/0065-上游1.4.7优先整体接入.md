# 裁决 65 — 上游1.4.7优先整体接入

## 决定

| 事项     | 裁决                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------- |
| 接入方式 | 不再按功能逐项择取；先把上游稳定 tag `v1.4.7` 整体合入 fork，止住基线停在 1.4.6 的分叉债。      |
| 顺序     | 1）slate.11 已发布；2）B8 整体接入 v1.4.7；3）B7 按盘点清单验收与补齐；4）D 组随 1.4.8 稳定版。 |
| B7 口径  | B7 从“择取实现”改为“合并后的验收与补齐”：已有功能记证据，缺的才补，不重复实现。                 |
| 版本     | 不追 `v1.4.8-rc.1` 等 rc；只在稳定 tag 上做同样的整体接入。                                     |
| 删除路径 | `docs/design/`、`docs/images/`、`ROADMAP*` 等 fork 已删内容保持删除，不因合并复活。             |

## 理由

上游 1.4.7 已于 2026-11-25 发布，1.4.8-rc.1 也已经出现。继续逐项择取，每个稳定版都要在 1.4.6 基线上重复解同一批 UI 冲突，差距只会越拉越大。2026-11-25 的试合并显示：574 个上游文件、51 处冲突，集中在 H0/Slate/手机壳层相关的核心文件；这是一次性成本，先付掉比每个版本都付更划算。1.4.7 还带来长文档卡顿修复、44pt 触控、拖放和插件 API 1.10，都是 fork 需要的。

## 影响

- 新增 B8“整体接入上游 v1.4.7”（2–4 天）；B7 改为“上游 1.4.7 界面功能验收与补齐”（1–2 天）。
- 上游基线从 `v1.4.6` 推到 `v1.4.7`；`upstream:verify`、全量检查、桌面与 Android 冒烟是合并完成的门槛。
- 合并分支不夹带新功能；B7 验收中的缺口另记，不把合并变成功能开发。
- 本决定改变 B7 原先“不整体 rebase 到 1.4.7”的口径；0049 的上游跟随总策略仍然有效。

## 来源

2026-11-25 用户口述：按 slate.11 → 整体接入 1.4.7 → B7 验收 → D 组的顺序做，先把 1.4.7 合并了再说；上游更新很快，不尽快做完，1.4.8 出来就更难合并。
