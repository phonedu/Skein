# 裁决 55 — 合并后的代码清理与界面过样式

## 决定

**每次上游 tag 合并，代码清理和界面过样式都是合并的一部分；不通过不合并、不发布。**

代码清理：

1. `npm run upstream:clean -- --apply` 删除 `CONFIG.absentPaths` 里被 merge 带回的 fork-clean 文件，把删除放进 merge commit；上游新增的同类文件先补进 `absentPaths`。
2. `npm run check` / `check:repo` 必须全绿：knip、重复代码、循环、文件尺寸、期望的生成文件都要处理；发现死代码、重复的 settings/phone 组件或上游残留样式，删掉或合并，不把告警当基线。
3. 逐项看上游 UI diff：同一个界面只保留一套实现（例如 settings 行/卡、手机页面），上游新组件若只是另一套做法，先决定承载方（fork 覆盖层或上游组件改造），不把两套并排留在代码里。
4. Rust 命令、插件 API、共享类型有变化时，重新生成 `src/platform/bindings/` 与 `docs/dev/plugins/reference.md`；生成文件不手改。
5. 清理完再提交 merge commit；不要先合并、后补清理。

界面过样式：

1. `npm run test:phone-shell` 必须通过：设置行不竖排、组卡单线、代理输入同轴、主题工坊堆叠、列表末行线和图标尺寸，按计算样式而不是 CSS 文本。
2. 桌面 built app 走：设置弹窗、外观、文档设置、主题工坊、Today/侧栏。
3. Android 真机走：设置列表、文档、模型、对话与写作（含网络代理）、扩展的插件/技能/主题“可安装”、Today 改动、主题工坊。
4. 上游新增的界面功能必须先按 fork 的行/卡/令牌规则适配，并给 `e2e/phone-settings-shell.spec.ts` 加对应断言；适配和截图写进 merge 记录。未适配的上游界面不合并、不直接混进来。
5. 截图和已知偏差写进 `archive/` 合并记录；UI 差异不能只靠“看起来差不多”口头确认。

## 理由

v1.4.6 合并把上游的 mobile 设置行竖排、组卡 `border-bottom` 等规则直接带进来，fork 之前的行形、单线、输入框内缩被压掉；只读 CSS 文本的测试没发现，真机上才暴露。合并门禁必须检查最终计算样式和实际页面，代码清理必须处理上游残留与两套实现。

## 影响

- R5 跟 tag 流程把清理与过样式列成固定步骤，`npm run upstream:verify` 默认跑 `test:phone-shell`。
- 上游壳的组件/CSS 只作参考；fork 覆盖留在 `src/features/settings`、`src/phone` 等 fork 文件。
- 删除文件回归继续由 gate 的 `absentPaths` 拦截。
