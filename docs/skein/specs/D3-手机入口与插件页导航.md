## 2. 范围

- 做：
  - 今天页的插件行（资产库、待确认）与宿主侧的状态项泛化；
  - 插件列表行的可见操作入口（触屏）；
  - 插件页 ⋯ 的收敛；启动器去重；
  - 插件页返回「回到来处」；
  - 冲突的可见入口（页面与动作接 S14/S15）。
- 不做：
  - 系统分享收集（维持「默认不做」，按需进待审）；
  - 桌面小组件 / 通知提醒；
  - 手机第二套插件路由或页面栈；不改「插件页 = 普通标签」（裁决 67）；
  - 文档页的 ⋯ 不内联全部插件命令（低频，仍走「插件」启动器；真用起来觉得绕再议）。
  - 宿主编写资产业务逻辑（仍只显示与跳转）；
  - 插件 webview 页内部的改动（详情/确认中心/复盘的页面自身已是可见按钮）。

## 3. 结论

1. **今天页就是手机的日常入口**：在「当前交付」之后、今日变更之前，按插件分组显示插件的状态行。`skein.collect` 报两行——`N 条待确认`（已有）与`资产 · N 张卡`（新增）；点行即进对应页面。**不改今天页的既有三段，只在中间插入插件组。**
2. **入口机制复用 `ui.statusItem`**，不新增插件 API、不在宿主里写死插件名。H0 已定「宿主今天页与状态条只显示并跳转，不写业务逻辑」（裁决 34），本文件只是把它从 skein.collect 专用改为通用。
3. **资产列表页由插件自己的命令打开**：宿主把 `layout.showSidebarTab` 在插件 list 页上翻成「手机整页 / 桌面右页边」，插件新增 `skein.collect.assets` 命令调用它。官方 9 个带 list 侧栏的插件同样受益。
4. **触屏列表每行有可见的 ⋯**，点开与长按同一个菜单；桌面鼠标仍用右键，不加可见按钮。
5. **插件页的 ⋯ 只放适用项**：该页的 `view/title` 贡献（若有）、命令面板、插件；不再出现大纲/查找/源码/分享。
6. **返回 = 回到打开它的那一页**（仅应用内打开的页签记录来处），没有来处回今天。资产列表 ↔ 详情、确认中心 ↔ 详情、插件页 → 文档都能原路返回；页签不因此关闭。
7. **冲突不静默**：有冲突或上次同步失败时，今天页出现一行「同步：N 个冲突」→ 设置 › 同步（维护区展开）。冲突中心仍是同步设置里的那块，不新造页面；diff/保留/删除随 S14 的冲突副本格式落地。

## 4. 设计 / 实施

### 4.1 今天页的插件行（D3a）

**宿主（今天页）**

- 渲染来源从 `statusItemsSnapshot()` 的 skein.collect 过滤改为**所有插件的状态项**（含 manifest 声明的 `statusItems`，用桌面状态条同一份 `withDeclared`）。
- 按插件分组；组标题用插件显示名（`tx-section-label`），组内行沿用今天行的配方：圆点、状态文本、chevron；`command` 缺省的行不给点击。
- 排序：组按插件安装顺序；组内按插件设置顺序。位置：`当前交付` 之后、`今日变更` 之前。
- 没有文件夹、或插件不发布时，不出现空组。
- 行触控高度沿用今天行（≥44）；长文本单行截断，`aria-label` 用完整文本。

**插件（skein.collect）**

- 新增运行时状态项 `assets`：文本复用 `assets` + `assetCount`（「资产 · 12 张卡」），`command: "skein.collect.assets"`；仅在 `textus.app.platform` 为 `ios` / `android` 时发布，桌面状态条保持现状。
- 插件从此在启动后运行（manifest `activationEvents: ["onStartupFinished"]`）：两行在打开任何插件页之前就存在，不必先点一次页面。
- 新增命令 `skein.collect.assets`（manifest 声明，`%assets%`）：调用 `textus.layout.showSidebarTab("skein.collect.assets")`。
- `pending` 状态项保持；组内顺序按插件上报的顺序，宿主不重排。
- 计数来自插件已有的列表数据；无文件夹不发布；列表刷新时 `update` 两行。

**宿主（打开 list 页）**

- `showSidebarTab(id)`：Textus 自己的视图（`tree` / `outline` / `search`）行为不变；插件的 list 页按表面翻译：
  - 手机 / 折叠：`openPluginTab({ kind: "list" })` 整页；
  - 桌面 / 平板：`openRightPanelView` 右页边（与顶栏目录点开同一落点）。
- 这一条同时修掉官方插件在 H0 壳里 `layout.showSidebarTab` 落到文件树的旧行为；桌面不再"打开插件侧栏 → 结果在文件树"。

### 4.2 列表行的可见操作（D3b）

- `PluginListView` 的行尾加一个 `.plugin-row-more` 图标按钮（⋯）：`(pointer: coarse)` 下常显，行随按钮到 44 高；鼠标下随行的 `:hover` / `:focus-within` 出现（不常驻，右键仍可用）。
- 点击按钮 `stopPropagation` 后打开现有 `ContextMenu`（与长按、右键同一个 `menu` 状态）；长按仍可用。
- `aria-label` 用「{卡片名} 的更多操作」；触控目标 44×44；不改变行高与分组线。
- 宿主通用改动，所有插件的 list 页受益；不改桌面右键。

### 4.3 插件页 ⋯ 与启动器（D3c）

**插件页的 ⋯（手机）**

- 当前标签是插件页（`tab.view`）时，⋯ 不再给文档动作（大纲 / 查找与替换 / 源码模式 / 分享）：
  - 该页的 `view/title` 贡献项（有则显示，label 为行文本，点按运行命令）；
  - 命令面板…；
  - 插件（启动器）。
- 关闭页面仍走标题后的页签 sheet（不重复进 ⋯）；AI 按钮仍只在文档页有意义，插件页保留现状（可开 AI 面板）。
- 文档页的 ⋯ 不变。

**启动器（QuickPick）**

- 页面项在前、命令项在后；**标题与同插件页面标题相同的命令不再单列**（`确认中心`、`月度复盘` 各只出现一次）。规则放在 `surfaces()`，页面列表不变。
- 插件设置仍在最后；搜索仍按原样过滤。
- 桌面/平板共用 `surfaces()` 数据；桌面走右栏目录，不受影响。

### 4.4 返回与页签（D3d）

**记录来处**

- 由应用内页面打开的页签记录 `openedFrom`（打开时在前的页签 id）：
  - `openPluginTab`（启动器、插件 `layout.openView`、页内跳转）；页签已开、被带到前台时也更新为该次打开者；
  - 插件桥打开的文件 / 未命名页（`layout.open`、`openUntitled`，带 `byPlugin`）。
- 用户从今天 / 文件树打开的文档**不记录**来处（返回仍回今天，保持 H0 的书库语义）。
- 页签关闭后 `openedFrom` 失效；恢复不持久化（重开窗口后没有来处）。

**返回**

手机顶栏返回与系统 Back 走同一个函数（现在分成 `onBack` 与 `useBackStep` 两条，合并为一）：

1. 有打开的 sheet / 菜单 → 先关（现状，`src/mobile/back.ts`）；
2. AI 页在前 → 回文档（现状）；
3. 当前页签有仍存在的 `openedFrom` → 激活它；
4. 否则 → 今天（现状）。

- 返回不关闭页签：资产列表 → 详情 → 返回回列表，再返回回打开列表时的文档（或今天）；页签保留，页签 sheet 里可关。
- 打开一个**已经在前台背后**的插件页（页签已是当前标签、手机停在今天）时，只改 active id 不会触发表面切换：宿主另发 `SHOW_PHONE_DOC` 事件，手机据此回到 doc；「今天 → 资产」再进也能走通。
- 页内来源链（详情页自己的 Back）仍由插件页处理；宿主返回不代答页内历史——**已知边界**，真机使用要求再加 `canGoBack` 桥（见 §6）。
- 这一条把裁决 67 的「返回键回 Today」细化为「有来处回来处，否则回 Today」；67 的「不新增页面栈」不变（只记一层来处）。

### 4.5 冲突入口（D3e，接 S14/S15）

- 已有页面：设置 › 同步 › 维护（冲突列表 + 打开），桌面/手机同一页；保持。
- 新增今天页一行：有冲突时显示「同步：N 个冲突」→ 设置 › 同步（维护区展开）；上次失败且未处理时显示失败行。数据来自 `syncStatus` / `sync_conflicts`。
- 桌面：窗口状态条同一行、同一跳转（与 H0「状态条只显示与跳转」一致）。
- 冲突中心的动作仍按[同步方案 §9.3](同步方案.md)：列表、打开、保留 / 删除 / 稍后；手机只读列表 + 处理。diff / 保留 / 删除的具体交互等 S14 的冲突副本格式定稿后实现；D3 先接入口与「打开」。
- 触发点：S14 完成（冲突副本可枚举）→ D3e 施工。

## 6. 决定与未决

**已定（裁决 68）**

1. 今天页组标题 = **插件显示名**（通用、不写死插件）。
2. 返回模型 = **只对应用内打开的页签记来处**；用户从今天 / 文件树打开的文档仍回今天。
3. `assets` 状态项**只在 ios / android 发布**，桌面状态条保持现状。

**未决（实现时按默认，遇到再裁）**

4. 插件页 ⋯ 是否加「关闭页面」：默认不加（页签 sheet 已有 ×，返回也不关页签）；真机觉得绕再加。
5. 启动器去重规则：默认按标题相同去重；出现真实重名（不同命令同标题）再升级为清单标记。
6. 页内返回桥：宿主返回目前不询问插件页「还能不能回」；详情页的来源链靠页内 Back。真机上若要求系统 Back 退一步链路，需要 `canGoBack` / `back` 消息桥（新插件 API），暂不做。
7. 冲突 diff / 保留 / 删除：等 S14 的冲突副本格式与「保留 / 删除」语义定稿；D3 只做入口与打开。
8. Android 平板的桌面 Today（`TodayPanel`）仍按「待确认」标题显示 assets 行：本片只改手机今天页；真用平板再泛化 `TodayPanel` 的分组标题（同本文件 §4.1 的插件名规则）。

## 7. 验收

- **e2e（Chromium，iPhone UA，phone；`e2e/phone-plugin-entry.spec.ts`）**：
  - 今天页出现「N 条待确认」「资产 · N 张卡」两行；各点一次即到确认中心 / 资产列表；
  - 资产列表每行有可见 ⋯，点开菜单三项（查看详情 / 请求变更状态… / 记一次使用…），行本身仍开详情；
  - 插件页 ⋯ 不含大纲 / 查找与替换 / 源码模式 / 分享…；含命令面板…与插件；
  - 启动器里「确认中心」「月度复盘」各一次，页面项在命令项前；
  - 资产列表 → 卡片详情 → 返回回列表；再返回回打开列表的文档（或今天）；系统 Back 同向；
  - 冲突 stub（`syncStatus` / `sync_conflicts` 有值）时今天页出现冲突行，点进设置 › 同步。
- **单测**：今天页渲染所有状态项；`surfaces()` 去重；`showSidebarTab` 的手机/桌面映射；`openedFrom` 返回优先级；`PluginListView` 的 ⋯ 按钮。
- **真机**：Android 返回手势（华为 OXF_AN10 或 Xiaomi AVD）与 iPhone UA Chromium；触控目标 44；横滑今天/文件不受影响。
- **视觉**：只用令牌；十语言补文案；今天行、⋯ 按钮、插件页 ⋯ 的亮/暗截图；`ui-contracts` 与 `phone-shell` 不回归。
- **无回归**：桌面顶栏目录、右页边 list、文档页 ⋯、TabSwitcher、系统返回的 sheet 关闭顺序。
