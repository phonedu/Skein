四份基线文档各管一个真相，本文管第五个：**界面真相**——不是「将来界面应该长什么样」，而是「已经改成什么样、改了多少、依据是什么、还欠什么」。

它与《Textus-改造方案》§7 的分工是硬的：

|                | 面向                                                            | 时间轴            | 产物                   |
| -------------- | --------------------------------------------------------------- | ----------------- | ---------------------- |
| 《改造方案》§7 | 未来的信息架构（今天 / 笔记 / 资产 / Agent / 设置五个一级入口） | 已封存（裁决 29） | 规划、优先级、阶段划分 |

## 0. 一句话版本

> **第一步按画板把既有界面的尺寸对齐（不重新设计）；第二步把设置页作为第一个 Base UI 模块重画成浮层，用它验证「headless 行为 + 自绘皮肤」这条组件库路线；桌面的设置页签与侧栏设置列表随之退役，iPad 保留旧面板。**

## 1. 范围与不在范围

**做**：

1. 既有界面的尺寸对齐——窗口栏、活动轨、侧栏、控件高、文件树行、字号级差；
2. 设置页整体重建——浮层外壳、导航列、行与控件皮肤、搜索、唤起入口；
3. 与之配套的设计语言条款（§5.5 受控例外、§5.7 设置条）、发布说明、截图证据。

**不做（留给后续 pass）**：

- 新 IA 的页面重组（五个一级入口、底部导航）——见《改造方案》§7.2–§7.8；
- 空态 / 载入态、图标统一、深色专项、文案统一；
- 替换 `engine/controls` 里任何既有控件；
- 移动端（手机）布局改动。

> **2026-11-16 主线定档**：上面两栏描述的是**已落地的两个 pass**（界面收尾 + 设置页重建），不再是界面工作的边界。界面主线自即日起转为**逐屏对齐 `boards/screens/` 十屏画板**——十屏就是目标界面，按屏开工，不设"等阶段 0.5"的总门；各屏的数据依赖与开工顺序见《改造任务清单》§4。**2026-11-17 裁决 29 已封存此定档：十屏 IA 推迟，画板非权威、不施工；2026-11-20 旧画板已删除。以下为历史。**

## 2. 第一步：把界面按画板对齐（`ui-alignment`）

### 2.1 原则：画板是尺寸的权威，代码是执行者

对齐不是"再设计一次"，而是把旧画板已经声明的数值落到代码与令牌上。旧画板已于 2026-11-20 删除；本节保留当时落地的尺寸与原则，不再有画板可对照。声明的尺寸优先于平台规范（Fluent / Apple）：**画板是批准过的设计，Textus 保持自己跨平台的控件高度体系**（§5.3）。

### 2.2 对齐后的尺寸表（落地值）

| 项                 | 画板                   | 落地                                              | 落点                                                |
| ------------------ | ---------------------- | ------------------------------------------------- | --------------------------------------------------- |
| 字号级差（Medium） | 34 / 17 / 15 / 14 / 12 | 大标题 34 · 标题 17 · 正文 15 · 列表 14 · 说明 12 | `--text-*` 角色（`src/engine/tokens/ui-sizes.css`） |
| 字号预设           | —                      | Small 28/16/14/13/11 · Large 40/20/17/15/13       | 预设各档保持"一档"的步差，不等比                    |
| 窗口栏高           | 44                     | 40 / **44** / 48（Small/Medium/Large）            | `--window-bar-row`                                  |
| 活动轨宽           | 56                     | **56**                                            | `--rail-width`                                      |
| 侧栏宽             | 316                    | **316** 起（最小 198，最大 528）                  | `SIDEBAR_DEFAULT_WIDTH`                             |
| 控件高             | 34                     | **34**（小号 28；Small 30/24，Large 40/32）       | `--control-height` / `--control-height-sm`          |

### 2.4 材质与令牌纪律

- 不透明面板：不用 blur / `backdrop-filter`，深色也不做半透明层；
- 颜色只走语义 token（`--ui-surface` / `--ui-text` / `--ui-muted` / `--ui-border` / `--ui-accent`），深色由 token 翻译，不另写一套皮肤；
- 文字两档灰（正文 / 次要），不设第三档；
- 圆角只取 `--shape-*`（xs 4 / s 8 / m 14 / l / pill），不发明裸值；
- 一切尺寸落 4px 栅格。

**证据**：`ui-alignment` 分支 8 个任务逐个 TDD 落地（提交 `0247c068` → `90680cb1`）；

`docs/design/design-language.md` 的 §4.2 / §5.3 / §5.4 / §5.6 同步改写；发布说明 `docs/releases/next/ui-alignment.md`。

## 3. 第二步：设置页在 Base UI 上重建（`base-ui-settings`）

### 3.1 为什么是设置页、为什么是 Base UI

**为什么先做设置页**：它是交互最重的一块面（浮层 + 焦点管理 + 下拉选择 + 开关），
headless 库的收益（无障碍、键盘、浮层定位）在这里最值；且它自成一个模块，
动不到编辑器与 `engine/controls` 的任何既有组件。

**为什么是 Base UI 而不是 Radix**（裁决）：

- Radix Primitives 维护停摆，作者转做 Base UI；
- 两者 API 同源，切换成本低；
- `@base-ui/react@1.9.0`，**MIT**，许可证经 npm registry 核实（2026-11-15）。

### 3.2 模块边界（硬约束）

| 约束     | 内容                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------ |
| 引入范围 | **只进 `src/features/settings/`**；别处要引必须先回设计文档增补                                        |
| 引入方式 | 按组件单件 import（`@base-ui/react/dialog` 等），不做统一包全量引入                                    |
| 版本     | `package.json` 精确锁 `1.9.0`（无 `^`）                                                                |
| 懒加载   | 模块经 `src/lazy/lazy-module.ts` 注册（`settings-features`），**只在首次打开设置时载入**，启动层零导入 |
| 预算门   | 构建后 entry chunk 不超 **1,000,000 字节**（`vite.startup-budget.ts`）                                 |
| 不替换   | `engine/controls` 的既有控件一律不动                                                                   |

### 3.3 浮层规格（画板 → token）

| 画板             | 落地                                                                            | 令牌                                         |
| ---------------- | ------------------------------------------------------------------------------- | -------------------------------------------- |
| 浮层 880×556     | `calc(880px * var(--chrome-scale, 1))` × `calc(556px * var(--chrome-scale, 1))` | 不使用 CSS `zoom`（WebKit 弹层指针坐标问题） |
| 圆角 18          | 就近取 14                                                                       | `--shape-m`                                  |
| 阴影 0 34px 80px | 就近取 `--shadow-3`                                                             | `--shadow-dialog`                            |
| 左导航 200       | 200                                                                             | 导航行 32 高、组标题 24 高 / 12px / 600      |
| 内容行 `.srow`   | 标签 + 小字说明（12px muted）+ 右侧值控件                                       | 行间 1px 发丝线，行内距 13 → 12（4px 栅格）  |

旧画板 `ui-d-settings` 已于 2026-11-20 删除；浮层规格以上表为准。

### 3.4 行与控件皮肤

- **行**：`.settings-row` = 标签 / 说明在左，值控件在右；说明用 `--text-caption` + `--ui-muted`；
- **Select**：pill 形制（`--shape-pill`），选中态去边 + accent 字色，弹层 `--shadow-popover`；
- **Switch**：iOS 式不透明开关，accent 填充，**不用半透明**；
- **Checkbox**：16px 方盒（`--shape-s` 圆角），选中填 `--ui-text`、勾为 `--ui-bg`。

四个控件都是**受控件**：值从设置存储读写，写入只经 `setSettings`。

### 3.5 唤起与落地

| 入口                               | 行为                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------- |
| ⌘,                                 | 打开浮层（开着的停在当前页，关着的停在通用）                                           |
| 轨道末端齿轮                       | 同上                                                                                   |
| 原生应用菜单的设置项               | 同上（Windows / Linux）                                                                |
| 深链（`OPEN_SETTINGS_PAGE_EVENT`） | 打开浮层并定位到该页（侧栏搜索结果、插件页）                                           |
| 插件页                             | 插件注册的设置页与内建页同列渲染；插件列表打开的插件专属页也进浮层内容列（不再开页签） |
| iPhone / iPad                      | **门控保留旧面板**（`isIOSApp`），双壳暂时并存，平板 pass 再收敛                       |

### 3.6 退役了什么

- 桌面的**设置页签**（`SettingsTab`）与**侧栏设置列表**（`SettingsNavPanel`）连同其样式表删除；
- 侧栏不再有「设置」项；齿轮不再切换侧栏，直接开浮层；
- 设置页不再占用窗口栏的一枚标签（`doc-tabs.ts` 里的历史标签兜底名保留）。

> 依据：iOS 的规矩是「门控平台做不到的，不藏功能」——旧面板在 iPad 上仍可达，故不删其代码路径；
> 桌面端则是「替换而非共存」：同一时刻只有一个设置界面。

### 3.7 搜索

- 搜索框落在**导航列顶部**，§5.4 的 capsule 形制；
- ⌘F 绑定不变：设置开着时聚焦浮层里的搜索框（开着才归设置）；
- 结果站位内容列，拣选后**跳到该行**（复用引擎既有的 reveal：滚动居中 + 聚焦 + 短暂着色）；
- 合成中的 Escape 归输入法，**不关浮层**（引擎规矩优先于库行为）。

### 3.8 浮层对照（画板 → 落地）

画板画的是新 IA 的七项导航（库与同步 / 模型与 Agent / 插件 / 技能 / 外观 / 快捷键 / 关于），
落地按裁决 1 沿用现有页面清单；**壳、行、控件皮肤与画板一致**（浮层 880×556、左导航 200、行 + pill 值控件）。

设置浮层落地后的截图原存 `04-boards/shots/`，2026-11-16 boards 清理时删除；旧画板 `ui-d-settings` 也已于 2026-11-20 删除。壳与行皮肤的现行实现见 `src/features/settings/` 与本文 §3.3。
