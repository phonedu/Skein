# Textus 主题策略（Skein）

> **状态：契约已定（2026-11-22），阶段 0 只落文档。** 代码改造（锁定皮肤、剥离导入主题的 `--ui-*`）尚未开工；当前版本里导入主题仍沿用上游“派生整套界面颜色”的旧行为。阶段 1 实施后，以本文为准。
>
> 关联：[裁决 37](../decisions/0037-主题策略.md) · [STATUS T1](../STATUS.md) · [插件兼容性](../research/插件兼容性.md)

## 0. 一句话

**界面皮肤由 Skein 自己管，主题只负责文档。** 上游/导入主题继续可用，但只改正文；想做整套界面换肤的主题，必须先被 Skein 选中、完整适配，成为“Skein 皮肤主题”。

## 1. 三层主题

| 层                       | 是什么                                                | 谁维护      | 改什么                                                                           |
| ------------------------ | ----------------------------------------------------- | ----------- | -------------------------------------------------------------------------------- |
| **Skein 皮肤主题**       | 完整适配的主题，皮肤 + 文档一起换                     | Skein       | `--ui-*`、`--doc-*`、玻璃卡/侧栏/选中态/发丝线的实际取值                         |
| **文档主题**             | 上游内置主题、导入的 Typora/社区主题                  | 上游 / 社区 | 只改 `--doc-*` 与 `#write` 的正文样式；界面永远是当前 Skein 皮肤（现阶段 Slate） |
| **自有主题系统**（长期） | Skein 自己的主题包格式，主题可声明“皮肤 + 文档”两部分 | Skein       | 长期目标，现阶段不做                                                             |

### 1.1 现在

- 默认皮肤：**Slate**；
- 文档主题：上游内置的 Paper / Slate / Forest 仍可选用，只影响正文；
- 上游/导入主题仍然看得见、装得上，但按“文档主题”对待；
- Prism 是帧主题（渐变 chrome），与固定皮肤冲突：阶段 1 时要么降级为只保留文档强调色，要么作为第一个 Skein 皮肤主题单独适配。

### 1.2 以后

- 从上游挑几个好看的主题，**内置到分支并完整适配**成 Skein 皮肤主题；候选先从 Paper / Forest / Prism 这类已在代码、许可证干净的开始，社区主题定名单后再查许可证；
- 每个皮肤主题都要过浅/深色、桌面/手机/平板、侧栏、设置、Today、选中态与对比度，不是只换一个色板；
- 不做“所有上游主题逐个反向适配”。

## 2. 技术契约（阶段 1 实施口径）

1. **皮肤主题**
   - 显式声明完整 `--ui-*` 与 `--doc-*`；
   - 玻璃卡/侧栏/选中态/发丝线使用皮肤自己的取值，不再从文档主题推导；
   - 新皮肤必须提交浅/深两套，并有截图证据。

2. **文档主题**
   - 只允许 `--doc-*`、`--tone-*`、`--revision-*` 与 `#write` / `.milkdown` 作用域；
   - **拒绝 `--ui-*`**：导入主题的 CSS 允许列表去掉 `--ui-`，应用侧不再从主题派生全局界面色；
   - 保留从主题推导文档变量（`--doc-*`、`--theme-content-width`）的能力，保证源码视图、代码块、装饰仍有正确颜色；
   - 主题里的 Typora 界面变量（`--side-bar-bg-color` 等）不再映射到 `--ui-*`。

3. **主题选择器**
   - 分组或徽标标明“Skein 皮肤”/“仅正文”；
   - 上游/导入主题选中后，界面不闪、不变色，只换正文。

4. **插件**
   - 用 Textus 控件/页面的插件自动跟随当前皮肤；
   - 自带 webview/硬编码颜色的插件功能不变，视觉需逐插件抽查；
   - `appearance.setColors` 不得覆盖全局皮肤（阶段 1 定具体边界，必要时只允许作用于插件自己的表面）。

## 3. 验收

- 切换任一上游/导入主题：界面 `--ui-*` 不变，正文按主题变化；
- 切换 Skein 皮肤主题：皮肤与正文同时变化，浅/深色、桌面/手机/平板一致；
- 主题选择器能看出哪些是完整皮肤、哪些是仅正文；
- 不给几十上百个上游主题做逐个界面适配。

## 4. 不做

- 现阶段不做自有主题包格式 / 主题编辑器；
- 不做上游主题的全量反向适配；
- 不把 `--ui-*` 的推导留在导入主题路径里。
