# 界面契约

> 这是**适配基准**，不是画板。权威顺序：`decisions/` > 本文件 > 代码与注释。
> 本文件把裁决落成可查的数值、模式和屏幕索引，并指明执行它的契约测试；
> 上游带来新界面时，先在这里找到对应模式，再动手。手工画板不再维护。

## 1. 怎么用

1. 把上游的新界面归类到第 3 节（桌面）或第 4 节（手机）的某个模式。
   没有对应模式时，**先写裁决**，再把新模式的数值、索引和测试补进本文件。
2. 只用第 2 节的令牌和第 5 节的图标档位；不写原始颜色、圆角、字号
   （`scripts/check-design-values.mjs` 会拦）。
3. 跑 `npm run test:ui-contracts` 与 `npm run test:phone-shell`；新屏要加
   自己的断言，不接受“看起来差不多”。断言的是浏览器最终画出的计算样式
   与尺寸，不是 CSS 文本——上游选择器可以在两个文件都没改的情况下压掉
   fork 规则。
4. 桌面 built app 与 Android 真机各走一遍，截图和已知偏差写进合并记录
   （裁决 55）。
5. 一屏只留一套实现：能改上游组件就改，不能就 fork 覆盖；不把两套并排留下。

**适配样例（带说明的设置行）**：v1.4.6 把上游的说明行在窄屏竖排。fork 的承载是
`.settings-phone` 子页里的 `.settings-row`：方向 row、说明在标签下、控件在行尾、
行高写 80（画 72）。改掉上游规则后，在 `phone-shell`（文档页）和 `ui-contracts`
（桌面设置）各加一条断言，截图进合并记录。

## 2. 基础（不可绕过）

- **令牌**：颜色 `--ui-*`（文档内容 `--doc-*`），圆角 `--shape-*`，字号
  `--text-*`，间距 `--space-*`，阴影 `--shadow-*`。组件里没有原始值。
- **皮肤**：界面锁 Slate（裁决 36）；主题只改文档（裁决 37）。
- **圆角**：`xs` 4、`s` 8、`m` 14、`card` 18、`sheet` 22、`pill` 999。
  控件是胶囊或圆；容器是圆角矩形。
- **字号**（桌面 Medium）：caption 12、list 14、body 15、title 17、
  title-lg 22、large-title 34。手机：caption 12、footnote 13、
  body/title 17、large-title 34。界面大小是三档手挑的预设，不是倍率。
- **间距**：4 点网格，`--space-1` 4、`-2` 8、`-3` 12、`-4` 16、`-6` 24、
  `-8` 32。
- **手机 10/11**：构建期把 app 样式里 ≥3px 的长度乘以 `--chrome-scale`
  （`vite.chrome-scale.ts`），所以**代码写 62 是为了画 56**。本文件里的手机
  数值一律写“最终画出的 dp”；代码值 = 画出值 ÷ 10/11。
- **触摸**：按钮写 48、画 44；列表行写 62、画 56。
- **插件 webview 页**：宿主取开环色（含 `--doc-*`）经消息下发，页面只落变量；
  页面背景用 `var(--doc-bg, var(--ui-bg))`，与官方插件页同口径（裁决 62）。

### 3.1 设置浮层行为

| 项              | 定式                                                                  |
| --------------- | --------------------------------------------------------------------- |
| 唤起            | ⌘,；原生应用菜单的设置项；深链 `OPEN_SETTINGS_PAGE_EVENT`（定位到页） |
| 搜索            | 导航列顶部；⌘F 聚焦；结果在内容列跳行（滚动居中 + 聚焦 + 短暂着色）   |
| Escape / 输入法 | 合成中的 Escape 归输入法，不关浮层；引擎规矩优先于库行为              |
| 插件页          | 插件注册的设置页与内建页同列渲染；插件专属页进浮层内容列，不开页签    |
| 退役            | 桌面设置页签、侧栏设置列表不再存在；同一时刻只有一个设置界面          |
| iOS             | 门控保留旧面板，平板 pass 再收敛                                      |

### 4.1 手机原则

1. **纸墨一色**：底色、卡片、输入槽都取纸的色阶；不用纯白、不用灰蓝面板；强调色只有一个。
2. **发丝分域**：用 1px 发丝线与间距分层；阴影只给真正浮起的东西（浮层、FAB、Toast）。
3. **火只标正在发生**：`--ui-accent` 只用于主行动、正在发生、当前选中；破坏性走 `--ui-danger`。

行 / 卡 / 按钮 / 输入 / 浮层的详细规则见
[手机端元素一致性方案](Textus-手机端元素一致性方案.md) §5–§12；数值以本节与第 5 节为准。

## 6. 交互基准

样式和交互一起适配；下面几条是裁决里的固定行为，新上游界面照这个走，
不按上游壳改回。

| 行为     | 基准                                                                                | 出处                     |
| -------- | ----------------------------------------------------------------------------------- | ------------------------ |
| 触控     | 行与按钮写 48 的触摸区；长按 = 行菜单；没有只靠 hover 才出现的操作                  | 34、AGENTS               |
| 手机返回 | Android Back 先关最上层（sheet → 子页 → 列表 → 关闭）；页内返回按钮与系统 Back 同向 | 34、`src/mobile/back.ts` |
| 弹层     | 底部 ActionSheet；确认与取消分开；Escape 关闭（桌面与蓝牙键盘）                     | 22、34                   |
| 桌面入口 | 菜单、快捷键与命令面板指向同一命令；hover 工具不移动行                              | AGENTS、55               |
| 新交互   | 没有现成模式时先写裁决，再补本节、屏幕索引和测试                                    | 59                       |

> 设置页「状态卡」（同步本地/远程版本 + 进度 + 统计行）与右页边「宽度阶梯」（可拖 360–560、窄窗先收左栏再覆盖）是两份候选做法，见 [Tau 可吸收功能清单](../research/Tau-可吸收功能清单.md) P0-1/P0-2；采用前先补裁决、本表和契约测试。

## 9. 维护

- 裁决变了，改本文件对应数值，并说明取代关系；历史裁决不重写。
