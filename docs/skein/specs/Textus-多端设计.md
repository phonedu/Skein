# Textus 多端设计

> 迁移自《Textus-改造方案》§6（2026-11-18 目标稿）。H0 壳、手机端方案与 `decisions/` 已取代其中部分布局；冲突时以它们为准，本文件只留目标形态。

### 桌面端

完整工作台：

- 左栏：收集箱、当前任务、待确认判断、可调用资产。
- 中栏：任务或卡片详情。
- 右栏：原始证据、AI 草稿、来源链、版本对比。
- Agent：侧边常驻面板，不占用主编辑区。
- 支持批量复盘、版本对比、建立关系、拖拽整理。

### 手机端

只做四个高频动作：

1. **快速收集**：一个输入框，直接进 `inbox`，不强迫分类。
2. **查看任务**：今天做什么、卡在哪里、下一步是什么。
3. **复盘确认**：看证据，选择确认、驳回或保留草稿。
4. **调用资产**：搜索 `active` 资产，复制、插入或交给 Agent。

**2026-11-17 裁决 30 已改判**：手机端按成熟移动形态重排（Android 线，iOS 归上游）；下面“第一版不改导航 / 复用抽屉 / 页签”的限制**不再作为实现依据**。四个高频动作保留；320px/44px 仍适用。当前手机任务见STATUS PH1/PH2/PH3/PH4。

### 平板

- 横屏使用桌面布局。
- 竖屏可退化为两栏：列表 + 详情。
- 不单独维护第三套界面。

### Android 存储缺口

问题：

- 用户通过系统选择器打开的目录可能是 `content://`，不是普通文件路径。
- 部分插件文件 API 和元数据索引仍基于 Rust `Path`。
- Kotlin 写入缺少原子替换语义。
- 目前没有完整覆盖新建子文件、目录、版本化写入。

两条路线：

**路线 A：完整适配层（推荐长期）**

统一 `AssetStorage` 接口：

- 桌面普通路径 → Rust。
- iOS 安全作用域 → Swift 插件。
- Android 普通路径 → Rust。
- Android `content://` → Kotlin `ContentResolver` / SAF。

补齐：新建 / 重命名 / 归档 / 版本读取 / 冲突检测 / 尽量安全的临时写入与替换。

无法保证原子替换时，必须明确降级提示，而不是假装有保证。

**路线 B：首版限制存放位置（推荐先做）**

移动端资产库先放在主库（App Documents）内的 `asset-library/` 子目录，验证业务闭环；任意 SAF 目录后置。

**不建议**把"授予所有文件访问权限"作为资产库正常工作的前提。

### 平台门控

新增能力统一从 `src/platform/capabilities.ts` 暴露，例如：

- 是否支持目录选择；
- 是否支持后台 Agent；
- 是否支持系统分享入口；
- 是否支持多窗口；
- 是否具备原子写入。

界面根据能力开关降级，而不是在各处散落 `isIOS` / `isAndroid` 判断。
