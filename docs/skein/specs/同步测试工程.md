# 同步验收测试工程（专用测试项目）

> **状态：草案，2026-11-24。** S3q 收尾时用两个 portable debug 实例做了一次文字 smoke（见 [07-S3-Provider兼容性](../research/同步评审/07-S3-Provider兼容性.md) §3 第 6 条）：设置页真实填写、首次互传、双向编辑、冲突副本、删除收敛都通过。它只覆盖 Markdown 小文件；图片、视频、附件、大文件、多库、多 prefix、并发和远端清理还没有可重复的验收。本文定义专用的同步测试项目。
> **前置**：[同步方案](同步方案.md)、[同步协议 v1](同步协议-v1.md)、[S3 Provider 兼容性](../research/同步评审/07-S3-Provider兼容性.md)。
> **不做**：不替代 crate 单测、协议向量和 CI；不使用真实用户库或正式桶；不在本机跑 Apple 真机；不做弱网/故障注入（归 S5）。

## 1. 现有测试与缺口

已有：

- `textus-sync` 的单元测试、引擎矩阵、scale（20k 文件）、`s3_live`、`kodo_live`、`webdav_live`（真服务默认 ignored）。
- 设置页 vitest（保存/校验/错误文案）与浏览器 e2e（假后端）。
- S3q 文字双实例手工 smoke：两个实例、真实 Kodo 桶、设置页填写、同步按钮。

缺口：

- **媒体与附件**：PNG/JPEG、MP4、PDF、ZIP、含 `0x00` 的二进制、空文件；2 MiB 块边界；32 MiB / 128 MiB 单文件。
- **文件名**：中文、空格、`#`、`%`、emoji、长路径、嵌套目录、大小写重名。
- **多库/多连接**：同连接两个 prefix、不同连接、同库同 prefix 拒绝、连接共享后的编辑、库移动/复制/分叉。
- **并发与保护**：两个库同时同步、双实例同时点同步、空扫描、大批删除、遗留锁恢复。
- **远端清理**：测试 prefix 的对象/块要能删掉；加密库无法从 head 直接核对内容。
- 现有文字 smoke 是手工的，无法在下一轮改动后重复。

## 2. 目标

1. **一条命令**完成：构建 portable debug → 起两个独立实例 → 生成夹具 → 配置 → 跑场景 → 校验 → 出报告 → 清理。
2. 覆盖第 4 节的矩阵；失败时保留最小证据（报告、截图、远端键清单）。
3. 每次运行都使用一次性数据目录和一次性远端 prefix；不碰用户数据，不打印凭据。
4. 报告可复核：路径、大小、SHA-256、每轮 uploaded/downloaded/removed/conflicts、耗时、退出码。

## 3. 项目形态

推荐 **in-repo**，不新开长期 checkout：

```text
scripts/sync-smoke/
  run.mjs          # 入口：--provider --scenario --keep --report
  fixtures.mjs     # 生成/校验夹具（媒体、二进制、特殊名、大文件）
  instances.mjs    # 构建 portable debug、复制实例、启动/停止/记录 PID
  drive.mjs        # WebView2 CDP：设置页填写、同步按钮、读状态
  verify.mjs       # 本地树、远端 head/descriptor、报告
  providers.mjs    # S3 standard / Qiniu Kodo / 本地 WebDAV 的连接描述与清理
```

- **运行数据**：`C:/Project/.scratch/sync-smoke/<run-id>/`（`instA`、`instB`、`vaultA`、`vaultB`、报告）；按 AI 协作纪律 §十二，运行结束或任务关闭时删除。
- **构建**：复用 `TEXTUS_DISTRIBUTION=portable npm run tauri build -- --debug --no-bundle`；debug 无 release 单实例锁，portable 让每个实例的数据在 exe 旁隔离。
- **驱动**：WebView2 CDP；设置页用真实 Settings › Sync（不预制 `sync.json`），只预置语言/引导完成标记。
- **凭据**：新 provider 读取本机 `.tmp-s1-s3/*.local.json`（已在 `.git/info/exclude`），或环境变量 `TEXTUS_SMOKE_*`；永不写进仓库、报告或日志。
- 不在本仓建长期夹具二进制：媒体用生成器生成（ffmpeg 可选；没有时用已生成的固定样本，脚本校验 SHA-256）。

**为什么不单开一个仓**：测试必须跟着当前代码和构建走；独立仓会出现版本错位，还要第二份凭据与 CI 配置。只有出现“非开发者需要独立运行”的真实需求时再拆（U24）。

## 4. 用例矩阵

### 4.1 内容类型

| 类型      | 样本                                          | 验证                                     |
| --------- | --------------------------------------------- | ---------------------------------------- |
| Markdown  | 普通、中文/emoji、长行、嵌套目录、frontmatter | 两端字节一致；远端明文 head 路径/hash 对 |
| 图片      | PNG 1×1、4K PNG、JPEG、GIF                    | 字节一致；附件随主库同步                 |
| 视频      | MP4 1 MB、MP4 32 MB                           | 字节一致；不截断；块哈希全对             |
| 文档/附件 | PDF、ZIP、CSV、空文件                         | 字节一致；空文件可往返                   |
| 二进制    | 含 `0x00`/`0xFF` 的随机 1 MiB                 | 字节一致                                 |
| 特殊名    | 中文、空格、`#`、`%`、emoji、超长名           | 两端路径一致；不产生路径穿越             |

### 4.2 大小

| 大小                                | 目的                                                       |
| ----------------------------------- | ---------------------------------------------------------- |
| 0 / 1 B / 2 MiB−1 / 2 MiB / 2 MiB+1 | 分块边界                                                   |
| 16 / 32 MiB                         | 常规大附件、超时与内存                                     |
| 128 MiB（opt-in，`--large`）        | 协议单文件上限；只在本机跑，报告耗时/峰值（S5 的预算参考） |

### 4.3 场景

| 场景                | 预期                                                                   |
| ------------------- | ---------------------------------------------------------------------- |
| 首次 A→远端→B       | A 上传，B 下载；两端树一致                                             |
| 双向编辑            | 各自上传/下载 1；内容一致                                              |
| 删除                | 一端 removed 1，另一端同步后 removed 1                                 |
| 改名/移动（不修改） | 远端旧路径删除、新路径新增；另一端的同哈希改名识别为 move 时不重复下载 |
| 同时改同一文件      | 1 个冲突副本（`Sync conflicts/…`），两端都有两份                       |
| 改 vs 删            | 修改胜出，删除进历史；不产生两份（内容不冲突时）                       |
| 空扫描保护          | 本地被清空 + base 非空时报 `emptyScan`，远端不删                       |
| 大批删除保护        | 超过阈值报 `bulkDelete`，确认后才删                                    |
| 遗留锁              | 注入 lock.json 后运行报 `locked`；解锁后继续                           |
| 加密仓库            | 两端同密码首次/增量；错密码报错；descriptor 变化拒绝                   |
| 只读 binding        | 不产生冲突副本、不上传（若测试入口可设）                               |

### 4.4 多库 / 多连接

| 场景                                | 预期                                      |
| ----------------------------------- | ----------------------------------------- |
| 一个实例两个库，同连接不同 prefix   | 各自 head/lock；互不下载；状态分别显示    |
| 两个实例各一个库，同连接不同 prefix | 不串库；各自同步                          |
| 第二个库指向同连接同 prefix         | 保存报 `repositoryInUse`                  |
| 连接共享后编辑默认 prefix           | 已绑定的库 prefix 不变；base 按规则重建   |
| 库移动/改名                         | binding 跟随；远端 prefix 不变            |
| 复制库（同 vaultId）                | 保存报 `vaultCopied`；fork 后生成新子仓库 |
| 桌面两个库同时同步                  | 两个 runner 完成；各自锁不冲突            |

### 4.5 Provider 与加密

| 维度                             | 取值为                                                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Provider                         | Bitiful（标准 S3）、Qiniu Kodo（原生 create）、本地 WebDAV                                              |
| Provider（登记，不作为本机验收） | Nextcloud/NAS 等第三方 WebDAV、AWS/R2/MinIO/B2 等标准 S3、境外 WebDAV；坚果云不推荐，只做兼容性抽测     |
| 加密                             | 明文（便于核对远端 head）与加密（只核对收敛与 descriptor）                                              |
| 清理                             | S3 用 ListObjectsV2 + Delete；WebDAV 用 PROPFIND + DELETE；无法列举的桶用唯一 prefix 并打印手工清理命令 |

Provider 的支持口径、未适配清单与“谁来测第三方/境外”见 [08-Provider支持矩阵与测试边界](../research/同步评审/08-Provider支持矩阵与测试边界.md)。本 harness 只把自己的真跑结果写成“通过”；外部测试者的报告记为“外部反馈”。

本机可先加 **MinIO / dufs / rclone serve webdav** 单文件 profile（不需要 Docker）；**Nextcloud / Apache mod_dav** 用容器，需要 Docker Desktop + WSL2（当前机器未装，属用户决定）。家用 NAS、S4 LAN Hub 的路由/防火墙/休眠仍是外部真机项，见 [09-上游同步提案与成熟度门](../research/同步评审/09-上游同步提案与成熟度门.md) §5。

## 5. 判定与报告

- 本地：对两端 `vaultA`/`vaultB` 计算每个文件的 SHA-256 与大小，按相对路径比较；缺/多/不同都算失败。
- 远端（明文）：GET `v1/head.json`，逐路径核对 hash/size；`v1/lock.json` 运行后必须不存在。
- 远端（加密）：GET `v1/head.json` 必须是 descriptor（`format`/`repositoryId`/`kdf`），不尝试解密；两端收敛由本地树判定。
- 报告 JSON + 人读摘要：run-id、provider、scenario、每轮结果、失败的第一处路径、耗时、实例 PID、远端 prefix。
- 退出码：全部通过 0；任一断言失败 1；环境缺失（无凭据/端口/构建失败）2。
- 失败保留 `report.json` + 页面截图 + 远端键清单；成功也保留报告，数据目录按 `--keep` 决定。

## 6. 与现有测试的分工

| 层                    | 负责                                                       |
| --------------------- | ---------------------------------------------------------- |
| crate 单测/引擎/scale | planner 矩阵、锁、历史、分块、加密、并发上限；不碰真实服务 |
| `*_live` ignored      | 单 transport 的真桶首次/改/删/冲突、probe；不驱动 UI       |
| `scripts/sync-smoke`  | 真实桌面双实例、设置页、媒体/大文件、多库、远端清理、报告  |
| 浏览器 e2e            | 只验证页面行为（假后端）；不替代真同步                     |

## 8. 风险与边界

- 真实桶会被写入测试对象：只用专用桶/子账号、唯一 prefix、报告不含凭据；清理失败时打印清单，不静默放过。
- 大文件会吃内存与时间：128 MiB 只在显式 `--large` 时跑，记录耗时/峰值，不并入日常。
- CDP 与窗口：WebView2 版本、端口占用、显示缩放（本机 175%）都会影响坐标；驱动只走 DOM/角色选择器，不用像素坐标。
- 实例：必须 portable debug；release 的单实例锁会把第二个实例变成“交给第一个”。
- 双写纪律：测试数据全在 `.scratch`，不写用户库；`TextusData` 与 vault 都在 run 目录内。
- 多库的 UI 自动化比单库复杂（每个窗口一个 folderRoot）；S3t3 允许用两个实例各带两个库，或一个实例内切换库，实现时选稳定的一种。

## 9. 验收

- `node scripts/sync-smoke/run.mjs --provider kodo --scenario text` 在干净机器上一条命令通过，退出码 0。
- `--scenario media` 覆盖 4.1 全部类型与 4.2 的 2 MiB 边界；两端 SHA-256 全等。
- `--scenario multi-vault` 覆盖 4.4 前四行；`repositoryInUse` 有明确失败信息。
- 运行结束删除 `.scratch/sync-smoke/<run-id>` 与远端测试 prefix；报告可作为 S 组任务的证据。
- 文档给出 provider 凭据位置、命令、报告字段与手工清理步骤。
