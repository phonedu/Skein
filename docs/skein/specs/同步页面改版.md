# 同步页改版与连接模型（S6 / S7）

> **状态：草案，2026-11-24。** 局域网 Hub（S4）完成后，同步页同时承载 WebDAV、S3（含缤纷云/七牛 Kodo）和局域网 Hub，现有单页把所有字段、状态、动作、冲突、历史、库列表和 Hub 面板堆在一起，用户看不出“现在用的是什么、是否正常、下一步做什么”。本文先立任务与边界，界面稿和规则在实施前补齐。
> **不做**：不改同步协议、引擎、Provider 字段语义；不做主题换肤；不在 S6 里实现多连接并行同步。

## 1. 现状问题

- 一页里“连接选择、连接字段、保存/预览/同步、冲突、历史、库列表、局域网 Hub”同等权重，首屏没有主次。
- WebDAV 与 S3 共用一组表单，切换类型只换字段；Kodo 是 S3 内部的一个兼容项，但用户看不出它与普通 S3 的区别。
- 局域网 Hub 既是“连接来源”又是“服务管理”，现在单独一大块，和连接列表割裂。
- 同一库切换连接、复制库、插件 Cloud Sync 与内置同步并存时，缺少一套明说的规则和测试。

## 2. 目标

首屏按顺序回答三个问题：

1. **这个库现在是否在同步？** 当前连接名、类型、上次结果、失败原因、立即同步。
2. **它连到哪里？** 地址/桶/前缀、加密、只读、局域网/云端；需要时再展开细节。
3. **我要改什么？** 切换连接、新建连接、编辑连接、断开；维护动作收进次级区域。

## 3. 信息架构（草案，实施前定稿）

### 3.1 桌面

1. **状态头条**：库名、当前连接（类型徽标 + 名称）、上次结果/错误、`立即同步`。
2. **当前连接**：类型、地址（WebDAV）/桶与区域（S3）/局域网地址（Hub）、远端目录、加密、只读；`切换`、`编辑`。
3. **新建连接**：先选类型（WebDAV / S3 / 局域网 Hub），只显示该类型字段；Hub 的“加入 Hub”是类型内的配对流程，不再单独成块。
4. **可折叠维护区**：冲突副本、云端历史、已同步的库、连接列表。
5. **局域网 Hub 管理**：作为“本机服务”入口放进连接类型/连接列表，不再与连接表单并列；启动、配对码、设备、撤销、清除数据留在该入口内。

### 3.2 手机

单列顺序：状态头条 → 当前连接摘要 → 同步动作 → 折叠的连接设置/维护。新建连接先选类型，再进入该类型的短表单；局域网 Hub 的地址/码/设备名是一屏配对。

## 4. 连接模型与互斥规则（S7）

- 一个 vault 同时只有一个 active binding；连接可以被多个 vault 共享，但每个 vault 的 prefix 必须不同（已有 `repositoryInUse`）。
- 切换连接 = 换 binding：清空旧 base、旧 last、旧锁状态；首轮必须走预览，禁止自动空扫描/大批删除。
- 启动局域网 Hub 不等于绑定；本机 Hub 连接与其他 WebDAV 连接同等，不做隐式切换。
- 插件 Cloud Sync 与内置同步对同一库同时开启：必须阻断并说明原因；已有 `pluginRunning` 只做提示，S7 要补强。
- 复制/分叉 vault、回切旧连接、两个 vault 共用连接、同一 prefix 冲突，都要有明确结果，不靠用户猜。

### 4.1 冲突矩阵

对 WebDAV、S3、局域网 Hub 三种方式，两两覆盖：

| 场景 | 期望 |
| --- | --- |
| 同库切换 A→B | 旧 base 清除；首轮预览；不删除远端 |
| 同库 B→A 回切 | 重新建 base；不把两库内容互删 |
| 两库共用连接、不同 prefix | 各自仓库；互不看见 |
| 两库共用连接、同 prefix | 拒绝 `repositoryInUse` |
| 复制库后绑定 | 走 fork/新 identity，不共用 repository |
| 插件双开 | 阻断并提示关闭插件或内置同步 |
| 局域网 Hub 启停 | 只影响连接可用性，不改 binding/base |

## 6. 测试

- store：切换连接清 base/last、回切、同 prefix 拒绝、复制 fork、插件双开。
- e2e/桌面：三种连接类型各建一次；同库切换与回切；Hub 启停后连接仍可用；维护区折叠不丢状态。
- 手机：新建连接类型选择、Hub 配对、切换后首轮预览。
- 截图：桌面 800/1280、手机 360 宽；改版前后对照。

## 7. 待定

- Hub 是“连接类型”还是“连接 + 本机服务”两个入口；建议类型内配对、服务管理单独入口。
- 首屏是否显示全部连接，还是只显示当前连接 + 管理入口。
- 切换连接是否强制预览，还是只对空扫描/大批删除强制。
- 现有 Cloud Sync 插件导入与内置连接的合并入口放在哪一层。

## 8. 一句话

**同步页先回答“现在怎样”，再让人改；连接方式可以多，active binding 只能有一个，规则先于界面。**
