# 同步页改版与连接模型（S6 / S7）

> **状态：S6a v5 定稿（2026-11-25）：单页内联，无第二层、无面包屑；S6b 已按此实现。** 局域网 Hub（S4）完成后，同步页同时承载 WebDAV、S3（含缤纷云/七牛 Kodo）和局域网 Hub，现有单页把所有字段、状态、动作、冲突、历史、库列表和 Hub 面板堆在一起，用户看不出“现在用的是什么、是否正常、下一步做什么”。§3 是 S6 的界面定稿，评审通过后按阶段施工；§4 的规则由 S7 定稿并测试。
> **不做**：不改同步协议、引擎、Provider 字段语义；不做主题换肤；不在 S6 里实现多连接并行同步。

## 1. 现状问题

- 一页里“连接选择、连接字段、保存/预览/同步、冲突、历史、库列表、局域网 Hub”同等权重，首屏没有主次。
- WebDAV 与 S3 共用一组表单，切换类型只换字段；Kodo 是 S3 内部的一个兼容项，但用户看不出它与普通 S3 的区别。
- 局域网 Hub 既是“连接来源”又是“服务管理”，现在单独一大块，和连接列表割裂。
- 同一库切换连接、复制库、插件 Cloud Sync 与内置同步并存时，缺少一套明说的规则和测试。

## 2. 目标

首屏按顺序回答三个问题：

1. **这个库现在是否在同步？** 当前连接名、类型、上次结果、失败原因、立即同步。
2. **它连到哪里？** 地址/桶/前缀、加密、只读、局域网/云端；需要时再展开细节。
3. **我要改什么？** 切换连接、新建连接、编辑连接、断开；维护动作收进次级区域。

## 3. 信息架构（S6a v5，2026-11-25）

### 3.0 一页到底，面板内联（2026-11-25 用户裁定）

同步页只有**一个滚动页**，没有第二层、没有面包屑。所有操作都在页内展开，`取消`/Esc/系统返回只收起面板，不离开设置：

| 区域         | 内容                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| 状态         | 库名、路径、状态行、唯一主按钮；预览摘要                                         |
| 当前连接     | 徽标 + 远端 + 加密；`切换`、`编辑`                                               |
| 页内面板     | 切换方式、新建/编辑连接、本机服务（桌面）——展开在“当前连接”下面，标题右侧 `取消` |
| 维护与记录   | 折叠                                                                             |
| 库与同步方式 | 多库时的列表（S7）                                                               |

- 打开的同一时间只有一个面板；打开另一个会替换当前面板。
- 面板里的类型是**分段开关**（WebDAV / S3 / 局域网 Hub），不是“先选类型再进下一步”的页面。
- 保存成功后面板收起，页面留在原处，状态头条出预览摘要。

### 3.1 桌面（980×640 设置面板，内容列 680 上限）

1. **状态头条**（无标题卡片）：库名 + 全路径；唯一主按钮；状态行；保存后的预览摘要；插件/锁的提示带。
2. **当前连接**（有标题的卡片）：类型徽标 + 主机/桶/局域网地址；远端目录 + 加密；右侧 `切换`、`编辑`（Hub 连接不显示编辑）。
3. **切换面板**（页内展开，标题右侧 `取消`）：按方式分组的连接列表 + 确认带 + `切换并预览`；不换页。
4. **新建/编辑面板**（页内展开，标题右侧 `取消`）：新建时顶部是类型分段开关；只显示必填字段；`高级选项` 折叠；底部 `取消` 与 `保存并预览` 并排。
5. **维护与记录**（折叠卡片）：预览、冲突副本、云端历史、已同步的库、断开。
6. **本机服务**（页内面板，仅桌面）：启动或二维码/配对码/设备；`返回` 收起。
7. **库与同步方式**（页内小节）：每库一行，方法徽标 + 名称 + 远端 + 该库最近一次同步的状态；当前库打勾。只读；“点开另一个库”的跳转归 S7。

### 3.2 手机

- 与桌面同一个单页：状态 → 当前连接 →（页内面板）→ 维护 → 库列表；单列、单滚动。
- 新建/编辑面板：类型分段在顶部（Hub 可直接扫码）；标签在上、字段全宽；底部 `取消` 与 `保存并预览` 并排一行。
- 切换面板：同样的方式分组；确认带 + `切换并预览`。
- 本机服务不在手机上出现。

| 类型               | 必填（首屏）                                                                                                                                                                                            | 由同步自动解决                                                    | 高级折叠                                    | 从界面去掉                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------- | -------------------------------------------- |

共性：已保存的凭据/密码留空表示保持原值；加密一旦开启并保存不能关闭（现有逻辑）；加密默认**关**，要加密的人在高级里打开并设密码（2026-11-24 用户裁定，见 §7）。

### 3.6 多库与切换（S7 界面）

- **多库时先看库**：页面列出“已同步的库”。每个库一行：方式徽标 + 库名 + 远端（主机/桶 + 目录）+ 最近一次同步（成功时间 / 失败原因 / 尚未同步）；当前库标 `✓`。列表只读；状态已在本页显示，“点别的库 = 打开它”归 S7。
- **切换按方式分组**：`切换`在页内展开方式列表——S3 / WebDAV / 局域网 Hub 三组；不换页，标题右侧 `取消`；组标题右侧是 `＋ 新建`（Hub 为 `＋ 加入`）；组下列已保存的连接。当前项标 `✓ 当前`（不是圆点），要切到的目标项是圆点，整页同时只有一个目标圆点；Hub 组里是 `本机 Hub（运行中）` 与 `＋ 加入`。
- **确认带**：选中另一个方式/连接后，面板底部出现一行确认：`S3 → 局域网 Hub：此库只走 Hub；旧远端文件保留；首次同步先预览。` 主按钮 `切换并预览`。不弹新窗。
- **切完的反馈**：状态行下一次提示 `已切换为局域网 Hub；S3 已停止为此库同步（远端数据保留）`；之后这个库只显示 Hub。
- **文案**：同步页的说明保持一句短句；不在页面上解释整个模型，长解释放帮助/文档。**怎么填不进表单本体**：S3 的填写说明放在字段旁的 `?`，更长的建桶/密钥教程指向在线文档；S3 组标题下只留一行“可用服务商”小字。服务商名（标准 S3 / 缤纷云 / 阿里云 OSS / 七牛 Kodo）在表单、当前连接、切换列表、库列表里始终显示，不退回裸的“S3”。
- **手机**：切换/编辑入口按手指尺寸（40px 高），与桌面同一条确认带；库列表状态与桌面一致。

## 4. 连接模型与互斥规则（S7）

> **2026-11-25 裁决 66 改定**：一个库可以有多个独立后端，每个后端各留自己的 base/last；普通切换不再清空另一个后端的 base。下述 S7 旧“切换即清 base”规则由裁决 66 取代，完整模型见 [单库多后端同步](单库多后端同步.md)。

- 一个 vault 同时只有一个 **active 后端**；连接可以被多个 vault 共享，但每个 vault 在每个连接下的 prefix 必须不同（已有 `repositoryInUse`）。
- 切换后端：只改 active 后端，不清旧后端的 base/last；目标后端已有状态则增量，没有状态则首次对账。“切换 = 清 base、当新仓库”的旧规则不再适用（裁决 66）。
- 首次对账：目标空则上传；两边都有则只传本地独有、只下远端独有；同路径不同内容出冲突副本，不覆盖、不删除；首轮必须预览。
- 启动局域网 Hub 不等于绑定；本机 Hub 连接与其他 WebDAV 连接同等，不做隐式切换。
- 插件 Cloud Sync 与内置同步对同一库同时开启：必须阻断并说明原因。S7 已实现（2026-11-25）：插件运行中，内置同步主按钮禁用；手动调用运行也直接拒绝。
- 复制/分叉 vault、回切旧后端、两个 vault 共用连接、同一 prefix 冲突，都要有明确结果，不靠用户猜。

### 4.0 切换即换后端，不清账（2026-11-25 裁决 66）

- 一个 vault 同时只有一个 active 后端；切换不新增“并行同步”。
- 每个后端是独立仓库，各留 base/last/repository_id；旧后端的连接、凭据、远端数据和 base 都保留，只停止这个库对它的同步。其他库用同一连接的不受影响。
- **只影响本设备上的这个库**；其他设备的 active 后端不跟着变。两台设备选同一后端时才互相看见；一台 LAN、一台 S3 时各同步各的。
- 切回旧后端：使用该后端自己的 base 做增量；本地在其他后端改过的文件按本地变更上传，不是全量重来。
- 首次切到没有状态的后端：空目标上传；非空目标做安全对账并预览；同路径冲突保留副本，不自动删除。
- 切换时正在同步或有锁：先等它结束；切到一个暂时连不上的远端允许保存，首轮同步再报错。
- 目标连接被多个库共用：给本库一个自动子目录；同 prefix 仍拒绝（`repositoryInUse`）。
- 加密：同一库所有后端必须同一加密状态与密码；不一致拒绝切换。
- 插件 Cloud Sync 是另一套引擎：切内置三种方式不会停插件；插件运行中时内置同步被阻断。
- 启动/停止 Hub 服务不等于绑定；服务停了，绑它的库显示不可用，仍可切走。

### 4.1 冲突矩阵

对 WebDAV、S3、局域网 Hub 三种方式，两两覆盖：

| 场景                       | 期望                                                         |
| -------------------------- | ------------------------------------------------------------ |
| 同库首次切换 A→B（B 空）   | 上传本地到 B；保存 B 的 base；A 的 base 保留；首轮预览       |
| 同库首次切换 A→B（B 非空） | 上传/下载/冲突副本；不删除任何一边；首轮预览                 |
| 同库 B→A 回切              | 用 A 的 base 增量；不重建、不全量、不删 B 的 base            |
| 两台设备不同后端           | 各自同步，互不看见；都切到同一后端后恢复互相同步             |
| 两库共用连接、不同 prefix  | 各自仓库；互不看见                                             |
| 两库共用连接、同 prefix    | 拒绝 `repositoryInUse`                                       |
| 复制库后绑定               | 走 fork/新 identity，不共用 repository                       |
| 插件双开                   | 阻断并提示关闭插件或内置同步                                 |
| 局域网 Hub 启停            | 只影响连接可用性，不改 active 后端或各后端 base              |

## 7. 已定（2026-11-25，S6a v5）

- **Hub 的入口**：两个。加入 Hub 是“新建连接”里的一种类型；本机 Hub 的服务管理是“切换 › 本机服务”（仅桌面）。手机只有加入，没有服务。
- **首屏连接**：只显示当前连接 + `切换`、`编辑`；完整列表在“切换”里。
- **首屏动作**：只有一个主按钮；`预览` 收进维护区，保存后自动预览。
- **加密默认**：新连接默认**不加密**，在 `高级选项` 里开启并设密码（2026-11-24 用户裁定，改变 `同步方案` §8 的 E2EE 默认开）。
- **远端目录**：从界面完全去掉，不提供自定义；保存时由后端自动建 `<文件夹名>-<id>` 子仓库（需改 `store::save` 并补测试）。**例外：局域网 Hub 绑定在 Hub 仓库根目录**，否则配对的手机和电脑会各写一个子目录、共享不了同一个库；摘要显示 `远端目录 /`。
- **S3 服务商**：显式选标准 S3 / 缤纷云 / 阿里云 OSS / 七牛 Kodo；兼容方式与路径式随服务商，不再让用户猜；Kodo 区域必选、地址生成；Bitiful 固定地址与 cn-east-1/path-style；标准 S3 从地址识别区域。
- **Hub 加入**：扫码优先，配对码随二维码走；手动地址+配对码是退路。
- **插件导入入口**：放在类型步的底部，仅未配置时出现；不单独成为一个连接类型。
- **设备名称**：不提供输入，默认“此设备”。
- **连接命名 / 备注**：本版不做，连接标签由服务商 + 主机/桶 + 前缀派生。
