# 产品体验与迁移评审（子代理）

> 来源：子代理独立评审，2026-11-18；只读分析，未修改任何文件；未经逐条人工复核。
> 路径缩写：`[T]` = `C:/Project/Textus`，`[P]` = `C:/Project/textus-plugins`。

---

## 1. 结论

**现有 IA 能承载“配置”，承载不了“日常信任”。**

- 设置的壳（浮层 + 行 + 控件 + 搜索）足够容纳一个“同步”页，手机设置也已经是全屏列表 + 推入页的形态（`[T]/src/features/settings/index.tsx:174-190`、`settings-phone.tsx:16`），**不需要新增一级入口**。
- 但同步真正的体验发生在“配置之外”：状态、冲突、历史。这三者在宿主里没有落点——桌面只有窗栏里的一枚插件状态项（`[T]/src/app/frame/WindowBar.tsx:135-140`），手机连窗栏都不渲染（`[T]/src/app/App.tsx:201-224`）。
- 插件今天把“状态”做成 4 个词（`[P]/development/cloud-sync/src/status.ts:24-32`），把“冲突”做成库里的一个普通文件夹（`[P]/.../src/planner.ts:82-86`），把“历史”做成右键菜单里的一个 webview（`[P]/plugins/catvinci.cloud-sync/textus-plugin.json:51-72`）。这三样在手机上全部失效。

**最关键的 3 个体验缺口：**

1. **冲突不覆盖，但也不告知、不处理。** 冲突副本以 `Sync conflicts/…` 普通文件落进库，面板只列路径、没有动作（`[P]/.../src/panel.ts:298-314`），副本还会同步到所有设备，越滚越多。技术上“不静默覆盖”成立，**体验上是“静默复制”**。
2. **手机没有状态面。** 没有窗栏、没有菜单栏、没有侧边栏，插件状态项无处显示；后台作业与通知是桌面专属（`[T]/src-tauri/src/schedule/mod.rs:1-24`、`lib.rs:143-156`），手机只能“打开应用时同步”，却没有任何地方说这件事。
3. **迁移是一次性破坏动作，且没有双开检测与回滚。** 卸载旧插件会删掉本地 base 与凭据（`[T]/src-tauri/src/plugins/install.rs:405-411`；手机无回收站，直接删，`atomic.rs:379-395`），而两个同步同时开启只靠远端锁串行化单次运行，不阻止两边各写各的 base。

另一个近乎 P0 的缺口：**首次连接对非技术用户不可完成**——S3 要填 endpoint/region/bucket/path-style/密钥，只有坚果云有预设（`[P]/.../src/config.ts:24-37`、`panel.html:181-245`），而手机上几乎无法把桌面的连接带过去。

详情（桌面左右、手机分段）：

│ 本机版本    今天 15:42 · 1.2 KB       │
│ 其他设备    Mac 3f2a · 今天 14:10     │

│ │ 本机           │ 其他设备       │     │

- 手机单窗格用分段控件：`本机 | 其他 | 差异`，底部常驻三个动作（≥44px）。

- 与现有 IA 的关系：宿主**没有**“今天/笔记/资产”这些面（`[T]/docs/skein/03-调研/界面现状盘点.md:31,42,46`），所以历史只能挂在“文件”和“同步”上，不做全局历史页；将来资产页真出现时，资产详情的“历史”段（`[T]/docs/skein/02-方案/Textus-改造方案.md:534-536`）再引用同一个按文件视图。
- 必须与 `catvinci.version-history`（本地版本，支持 diff/命名/钉住，`[P]/plugins/catvinci.version-history/textus-plugin.json:13,17-22`）区分命名：**“云端版本” vs “本地版本”**，否则两个“历史”入口互相打架。

### 2.5 首次连接（步骤即页面状态）

1. 前提：当前库（无库 → “先打开一个文件夹”；插件原文 `noFolder`，`[P]/plugins/catvinci.cloud-sync/textus-plugin.json:104`）。
2. 选服务（三张卡，人话）：
   - 坚果云（最简单）：邮箱 + 应用密码；
   - 其他 WebDAV（Nextcloud / 群晖 / 自建）：地址 + 账号 + 密码；
   - S3 兼容（AWS / R2 / B2 / 阿里云）：区域（选择器，不是文本框）+ 桶 + 密钥。
3. 填连接：每个字段给示例占位；地址不允许 http/自签名（现状 `[P]/.../src/config.ts:82-90`），必须提前说清楚。
4. 加密（默认关）：开关 + 密码 + 确认 + 一句“密码丢了就打不开，任何设备都一样”（现文案 `textus-plugin.json:158`）。
5. 测试连接：说明检查了**写入/读取/删除/独占锁**（现状只测不说，`panel.html:33-44`）。
6. 第一次检查（新增，dry run）：将上传 N 个、下载 M 个、冲突 K 个、共 X MB → 确认后才写。
7. 完成后落状态；自动同步默认：桌面开、手机“打开 Textus 时”。

**全局文案原则**（建议写进规格）：

- 一句话 = 发生了什么 + 我该做什么；HTTP 码、协议名、`head.bin`、descriptor 一律进“详情”。
- “已同步”只给真正跑通且无冲突、无 deferred 的一次；其余用“已是最新 / 部分完成 / 有冲突”。
- 冲突不单独说“冲突”，说“两个版本都保留了”。
- 加密不说“端到端加密”当卖点，说“上传前加密，服务商看不到内容与文件名”，帮助里补“仍能看到大小、数量、时间；密码丢失不可恢复，未做独立安全审计”（`[P]/plugins/catvinci.cloud-sync/README.md:177-186`）。
- 手机不承诺后台/实时同步，明说“打开 Textus 时同步”。

## 4. 盲区清单（按严重程度）

### P0：数据信任或不可逆

**P0-1 冲突以普通文件夹落地，没有处理面，还会同步到所有设备。**
证据：`[P]/development/cloud-sync/src/planner.ts:82-86`（`Sync conflicts/名称 (hash8).md`）、`panel.ts:298-314`（只渲染路径列表）、`README.md:31-32`。
后果：用户打开的是“另一个副本”，改错文件；副本被上传，另一台设备再产生副本，数量滚雪球；手机上只会看到一个莫名文件夹。
建议：冲突中心（列表 + 对比 + 三选一 + 批量）；文档打开时若本篇有冲突，编辑器顶部一条横幅；未处理前状态项常驻“n 个冲突”，不因重启消失。

**P0-2 卸载旧插件即销毁本地 base 与凭据，迁移无法回滚。**
证据：`[T]/src-tauri/src/plugins/install.rs:405-411`（`forget_global` + `forget_secrets`）、`store.rs:72-82`、`atomic.rs:379-395`（桌面进回收站，手机直接删）、`files.rs:223-230`（凭据直接删除）。
后果：手机上一旦卸载，base、同步密码、密钥全没；再装回来只能当“新设备”重新比对，可能产生冲突副本（`README.md:266-272`）。
建议：迁移完成前**只停用、不卸载**；内置版提供“导入并接管”，并在首次同步前把旧插件 kv 备份到应用私有目录（只读，迁移标记完成后删除）；卸载确认页明写“本地同步记录与登录信息会删除，云端数据不受影响”。

**P0-3 没有双开检测；两个自动化同步各写各的 base。**
证据：base 键由账号参与计算（`[P]/.../src/settings.ts:160-164`），两个引擎各有自己的 base；远端锁只保证单次运行互斥（`engine.ts:114-128`）；只有 README 里一句警告（`README.md:270-272`）。
后果：冲突风暴、历史里重复版本、两枚“已同步”状态项；用户可能对锁执行“强制解锁”，而另一台其实正在写。
建议：打开库 / 启动 / 打开同步页三处检测（插件已安装且启用 + `kv/config:<sha256(root)>` 存在）；默认关闭内置自动同步；一条横幅，两个按钮（暂停内置 / 停用旧插件）；不自动改插件设置。

**P0-4 `deferred` 被显示成“已同步”。**
证据：`[P]/.../src/status.ts:26-32` 只检查 `conflicts`，不检查 `result.deferred`；`local.ts:103`（目标文件打开或仍在变 → deferred）；面板只列路径（`panel.ts:301-313`）。
后果：一次同步说“Synced: 3”，但被打开的文件一直没更新；用户反复点同步，永远“完成”，最后不再相信同步。
建议：状态词单列“部分完成（n）”，带“关闭并重试”；文档打开时若本篇 deferred，横幅提示。

**P0-5 加密密码丢失不可恢复，但只是一行提示。**
证据：`panel.ts:136-143`（必填 + 确认，仅此）、`textus-plugin.json:158`（“It can't be recovered”）、`README.md:184-186`。
后果：远端全部内容永久失联；且密码必须每台设备一致。
建议：保存前一次明确确认（输入/勾选“我知道丢失后无法找回”），并建议存进密码管理器；手机首连默认关闭加密；更换密码只能“新远端文件夹”（现在也如此，`README.md:214-225`）。

**P0-6 保留期是跨设备的破坏性设置，点一下立即生效、无确认。**
证据：`settings.ts:123-131`（改 keepDays 立即发布，`keepPending`）、`README.md:44-48`（最后一次选择对所有设备生效，过期版本被清理）。
后果：误点“30 天”会在所有设备上不可逆地丢掉旧版本。
建议：选项后加一句“对所有设备生效，缩短后旧版本会被清理”；缩短保留期需二次确认；显示“最早可恢复到的日期”。

### P1：能不能完成、能不能知道

**P1-7 首次连接术语过重，预设不足。**
证据：`panel.html:181-245`（endpoint/region/bucket/pathStyle/token）、`config.ts:24-37`（只有坚果云预填 endpoint）。
后果：非技术用户在第 1 步放弃；“S3 兼容”用户不知道 endpoint/region 填什么。
建议：三选一卡片 + “不确定选哪个”帮助；区域用选择器；path-style 收进高级；桶不存在时给“桶名或权限”而不是 HTTP 码；Nextcloud/群晖/InfiniCLOUD 预设。

**P1-8 手机无法沿用桌面的连接。**
证据：`README.md:20-23` 要求“在另一台设备输入相同的服务、远端文件夹和密码”；宿主没有二维码/导入机制。
后果：在手机上输入 S3 密钥几乎不可行；用户会在手机重新建一个远端，造成两个库。
建议：至少支持“扫码/短码传递地址与远端（不含密钥）”；或明确“S3 请先在桌面设置，手机只支持坚果云/WebDAV 密码类”；或做一次性的加密连接包（需拍板）。

**P1-9 手机没有任何状态面。**
证据：手机不渲染窗栏（`[T]/src/app/App.tsx:201-224`），插件状态项在窗栏（`WindowBar.tsx:135-140`）；后台作业与通知桌面专属（`schedule/mod.rs:1-24`、`lib.rs:143-156`）；手机首页顶栏只有库名、搜索、齿轮（`PhoneHome.tsx:104-136`）。
后果：用户不知道“刚才那条笔记上去了没有”；失败没有任何提示。
建议：首页脚注状态 + 点开同步页；冲突/失败用应用内横幅，不依赖系统通知；明确“只在应用打开时同步”。

**P1-10 错误状态不持久。**
证据：`host.ts:95-102` 只把错误写进临时 message；`refresh()`（`host.ts:103-128`）会把 message 重置为 ready、error 置 false；重启后只恢复 `last`（时间 + 结果）。
后果：一次失败后重开面板/重启，错误消失，只剩“已同步 · 昨天”，用户以为没事。
建议：把“最后一次结果”持久化为状态（成功/失败码/时间），而不是临时文案。

**P1-11 状态词只有 4 个，错误原因不可见。**
证据：`status.ts:24-32`（Synced / Syncing / Conflict / Error）。
后果：分不清密码错、配额满、离线、证书问题；支持成本高。
建议：持久状态对象（码 + 短句 + 一个动作），状态项只显示最可行动的词（“需要处理”）。

**P1-12 没有“暂停”。**
证据：`Config` 只有 `automatic`（`[P]/.../src/model.ts:11-45`），`host.ts:150-157` 据此配 pacer；关自动同步后手动仍可同步。
后果：用户想“先别动”时只能断开连接，代价太大。
建议：暂停（1 小时 / 今天 / 直到我恢复），复用 Textus AI 的暂停形态（`[T]/src/i18n/locales/en.ts:12`）。

**P1-13 SAF 目录每次同步全量重哈希。**
证据：`[T]/src/platform/content-plugin-fs.ts:34-44`（`size: 0, modified_ms: null`）、`[P]/.../src/local.ts:119-146`（mtime/size 相同才走快路，否则整文件读 + 哈希）、`model.ts:8`（20000 文件上限）。
后果：手机上每次同步都像“第一次”，慢、热、耗电；用户以为卡死。
建议：首次同步给“只同步文本”的选项与进度；能拿到 provider 的修改时间就缓存；文案提前说“首次较慢”。

**P1-14 没有附件策略开关，只有 gitignore 文本框。**
证据：`panel.html:48-52`（`exclude` textarea）、`textus-plugin.json:100-102`。
后果：手机用户无法避免把几百 MB 媒体拉下来。
建议：三选一“附件：全部 / 只同步我打开的 / 不同步附件”，映射到 scope；保留高级规则。注意“不同步附件”要说明“附件不是丢了，是没同步”，否则会造成“文件不见了”的恐慌。

**P1-15 没有计量网络/仅 Wi-Fi。**
证据：`[T]/src/platform/capabilities.ts` 无网络类型能力；`Config` 无此字段。
后果：首次同步在蜂窝网络上传/下几百 MB。
建议：加原生网络类型能力 + “仅 Wi-Fi 传附件”；做不到就在第一次检查里显示总大小并要求确认。

**P1-16 自签名/HTTP WebDAV 被当成网络错误。**
证据：`config.ts:82-90` 只接受 https 且拒绝 URL 内凭据；错误落到 `networkError`（`textus-plugin.json:133`，“检查你的连接”）。
后果：自建 NAS 用户永远在“检查网络”，不知道是证书问题。
建议：单列“证书不受信任”状态 + 说明（换受信证书/反代），不做绕过开关。

**P1-17 设备身份不可辨认。**
证据：设备名自动生成 `平台 + 4 位`（`[P]/.../src/history-host.ts:26-35`），不可改；Android 会显示 `android xxxx`；锁只有开始时间、没有设备（`engine.ts:114-117`、`connection.ts:50-62`）。
后果：冲突和历史里“哪台设备”认不出；“另一台设备正在同步”也说不清是谁。
建议：同步页可改设备名；锁对象加 `device`（增量字段，旧客户端可忽略）；历史/冲突统一显示设备名。

**P1-18 历史能力弱：无 diff、无单版本删除、恢复可能写到旁边。**
证据：`history-page.ts:120-150`（列表 + 纯文本预览 + 恢复）、`history-host.ts:38-60`（文件打开或有未同步修改时写到 `名称 (hash).md`）。
后果：用户点了“恢复”却没看到正文变化（多了一个副本）；无法清理某一条历史。
建议：恢复前说明落点；提供“与现在对比”；至少给“删除此文件的历史”（涉及块回收，需拍板）。

**P1-19 两套历史语义冲突。**
证据：`catvinci.version-history`（本地每保存一版，diff/命名/钉住，桌面 + 移动）`[P]/plugins/catvinci.version-history/textus-plugin.json:13,17-22,66`；云端历史是“每次被替换/删除的版本”。
后果：用户分不清“历史”是哪一个；恢复语义不同。
建议：命名分流（本地版本 / 云端版本）；文档 ⋯ 里若两者都在，给一个“版本”入口分两段，或云端历史只放同步页。

**P1-20 默认远端前缀会撞名合并两个库。**
证据：`[P]/.../src/panel.ts:15-22`（默认 `textus/<文件夹名>`）。
后果：两个都叫“笔记”的库指向同一远端，内容被合并——这是慢性的、难察觉的数据事故。
建议：首次保存时若远端前缀已有 `head`，明确提示“这个远端已有内容（来自 X）”，给“合并 / 换名字”二选一，绝不静默合并。

**P1-21 首次同步/迁移没有预演。**
证据：`host.ts:262-330`（save 后直接同步并发布）。
后果：用户不知道会传多少、删多少；迁移时尤其可怕。
建议：加“检查”步骤（只读），给出上传/下载/冲突/大小四项后再确认。

**P1-22 中断留下的占位文件会被新引擎当成用户文件。**
证据：`reservations.ts:15`（占位内容 `Textus pending download <uuid>\n`）、`local.ts:81-110`（先 create 占位再写入）、`README.md:243-246`（靠 reservation 记录续写）。
后果：迁移时若不接管 reservation 记录，占位文件会被当成真实内容参与比对/上传，产生冲突副本，附件看起来“被替换成一行动作”。
建议：新引擎识别该固定前缀并视为“未完成下载”（重下或删除），迁移检查里列出这些路径。

### P2：设计与一致性

**P2-23 设置行缺三种变体。** 状态行（点 + 时间 + 一句原因 + 动作）、进度行、危险行（红色 + 二次确认）。现有行只有“标签/说明/控件”（`[T]/src/features/settings/settings-row.tsx:17-36`、`[T]/src/settings/sections/controls.tsx:23-48`）；手机列表行还没有值槽（`settings-phone-list.tsx:44-56`）。

**P2-24 设置搜索会自动索引动态状态。** 搜索索引直接读渲染后的行（`[T]/src/settings/settings-search.ts:1-3,15`）；“已同步 · 2 分钟前”这类动态文字要标 `data-search-ignore`（同文件 27-29），否则结果里全是会过期的条目。

**P2-25 画板“库与同步”不能照抄。** 它把“资产库位置 / 同步方式（iCloud）/ 打开文件落点 / 手机上只读 / Agent 写操作”混在一页（`[T]/docs/skein/04-boards/screens/ui-d-settings.html:641-647`），其中 iCloud 不是插件支持的服务，其余三项也不是同步。画板已封存（`[T]/docs/skein/02-方案/Textus-界面改造方案.md:322`），应另写规格，只借“行 + 右侧值”的形态。

**P2-26 裁决层面需要一条新裁决。** “内置 Rust 同步”与 §4.6“功能走插件承载”（`界面改造方案.md:320-324`）、§10“不做自建云与账号体系”（`[T]/.../Textus-改造方案.md:725`）、阶段 1“不改同步”（同文 650）字面上有张力；它不是自建云（是客户端），但需要留痕，否则后续代理会当违规。阶段 3 的“同步冲突不静默覆盖”验收（同文 690）也应升级为“冲突有处理面”。

### P3：国际化

**P3-27 字符串负担与术语表。** 十个 locale（`[T]/src/i18n/locales/`，AGENTS.md 规则），`Strings` 由 en 的形状约束（`[T]/src/i18n/strings.ts:16-21`），一次约 45-60 个新键 × 9 种语言；计数要用 `Plural`（同文件 26-28）。需要先定术语：库/文件夹、远端/云端/服务器、版本/历史、同步/备份——现在三套混用（插件用“云端/远端”，宿主用“文件夹/库”）。

## 5. 迁移剧本

### 5.1 可迁移的对象（精确到键）

| 内容      | 键/位置                                                                                                                           | 能否导入                                                                   |
| --------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 连接配置  | `kv/config:<sha256(root)>`（`[P]/.../src/settings.ts:32-34,76-78`）                                                               | 可，明文 JSON，无密钥                                                      |
| 登录信息  | `plugin_secrets.json` → `connection:<sha256(root+identity)>`（`settings.ts:44-46`；`[T]/src-tauri/src/plugins/files.rs:145-155`） | 仅用户同意；插件启用时才可读（`files.rs:174-176`）                         |
| 本地 base | `kv/encrypted-base:<sha256(root+identity+account)>`（`settings.ts:160-164`）                                                      | 可以，但**必须知道账号**；建议“用户重输账号后按键名查找并认领”，避免读密码 |
| 设备名    | `kv/device`（`history-host.ts:32-35`）                                                                                            | 可，保持历史里的设备连续性                                                 |
| 加密指纹  | `kv/vault:<baseKey>`（`host.ts:173-188`）                                                                                         | 可选，导入能更早发现描述符变化                                             |
| 上次结果  | `kv/last:<baseKey>`（`host.ts:318`）                                                                                              | 可选，保持“2 分钟前”的连续                                                 |
| 未完成块  | `kv/pending:<baseKey>`（`pending.ts:112-121`）                                                                                    | 不导入，重新检查更安全                                                     |
| 下载占位  | `kv/pending:<sha256(root)>` + 库内占位文件（`reservations.ts:15`）                                                                | 必须处理（见 P1-22）                                                       |

存储位置：`<app config>/textus/plugins/catvinci.cloud-sync/kv/`（`[T]/src-tauri/src/ai/workspace/layers.rs:8-17` + `store.rs:39-45`），配额 50 MB（`store.rs:12,155-166`）。

### 5.2 正常路径

1. 升级到含内置同步的版本；旧插件保持安装、保持启用；先让插件完成一次同步；提示用户备份库。
2. 设置 › 同步 → 检测到旧插件，横幅“从这个库的旧同步接管”。
3. 展示读到的连接（服务/远端/是否加密）；询问是否沿用登录信息（默认“沿用”，说明会写入本机安全存储）。
4. “检查”（只读）：上传/下载/冲突/大小 → 确认。
5. 暂停旧插件的自动同步（停用开关，不卸载）→ 内置第一次同步 → 有冲突则进入冲突中心。
6. 抽查：打开一个文件 → 云端历史 → 恢复一个版本到副本 → 确认可读。
7. 标记“迁移完成”，提示停用旧插件；观察 1-2 天。
8. 可选卸载：明确“本地同步记录与登录信息会删除（手机永久），云端数据不受影响”。

### 5.3 半途失败

- 第 3 步读不到配置（键不存在/JSON 坏）：当新连接，不写任何东西。
- 第 4 步检查失败（认证/权限/配额/证书）：停在检查，旧插件照常；给出分类原因。
- 第 5 步同步中断：发布前 base 不推进（`README.md:235-237`、`host.ts:318`），可续跑；旧插件保持停用；若回退，预期一次“对账”同步与少量冲突副本。
- 第 5 步发现占位文件：列为“未完成下载”，重下或删除，不参与上传。
- 第 6 步恢复写到旁边：说明这是保护（`history-host.ts:38-60`），不算迁移失败。
- 迁移后才发现密码错：不覆盖远端；给“重试”与“改用新的远端文件夹（全量上传）”两条路。

### 5.4 双开

- 检测点：应用启动、打开库、打开同步页。
- 判据：插件已启用，且其全局 kv 存在当前 root 的 `config:<sha256(root)>`（宿主可直接列目录，绕开 `plugin_store_keys` 的“插件必须开启”限制，`store.rs:38-40`）。
- 处置：默认关闭内置自动同步；一条危险横幅；两个按钮（暂停内置 / 停用旧插件）；**不自动卸载、不自动改插件设置**。
- 未处置时：每次自动同步前再查一次，仍双开则跳过自动同步（手动同步允许）——“宁可慢，不可乱”。

### 5.5 回滚

- 卸载前：停内置 → 重新启用插件 → 跑一次 → 接受冲突副本（两个 base 不同，属正常），确认插件状态正常。
- 卸载后：重装插件 → 重输连接与密码 → 首次当新设备加入（`README.md:266-272`）；base 不在（手机永久删；桌面在系统回收站），会全量比对；远端数据不受影响。
- 数据保证：不写新远端格式、不删远端对象、历史保留；这也是“先保持 v1 兼容”的价值所在。

## 6. 需要用户拍板的体验取舍

1. **首连目标用户**：坚果云优先（3 步完成）还是三服务平权（S3 收进高级）？手机上是否允许配置 S3？
2. **手机如何拿到桌面的连接**：手动重输 / 扫码传地址与远端（不含密钥）/ 一次性加密连接包。三者安全性与工作量差一个量级。
3. **冲突默认语义**：保留双方 + 冲突中心（推荐）；是否允许“全部保留远端”这种批量危险动作；是否把冲突副本移出库（移到应用私有区）——移走会失去“另一台设备也能看到”的语义。
4. **历史删除**：v1 是否做“删除单个版本/清空此文件历史”（涉及远端块回收），还是只给保留期。
5. **与 version-history 插件的关系**：两个入口，还是一个“版本”页分本地/云端两段。
6. **手机自动同步的默认**：每次打开 / 保存后（前台）/ 关闭；以及附件默认全同步（与桌面一致，避免“文件不见了”）还是仅文本。
7. **是否允许内置读取旧插件的 `plugin_secrets.json`**：这决定迁移能否“无痛认领 base”，也决定隐私边界怎么写。
8. **裁决落档**：内置同步 = 客户端（不建云、不建账号），与“插件优先 / 不做自建云”的关系；同步更新 `[T]/docs/skein/02-方案/Textus-改造方案.md:650,690` 与 `[T]/docs/skein/02-方案/Textus-界面改造方案.md:320-324`。

另附一条给 spike 的建议：**spike 只验证引擎**（前台同步、SAF 读写、锁、冲突落盘、占位恢复），不要在插件 webview 上做手机信息架构——插件的侧栏、菜单、状态项在手机上都不存在，而内置版迟早要替换它们；手机 IA 直接按上面的同步页 + 脚注设计。
