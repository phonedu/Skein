## 当前结论（一句话版）

- **方向成立**：先保持远端格式 `textus-cloud-sync/1` 兼容；先把插件做成手机可用（spike → 多端插件），再迁移为 Rust 内置同步服务；主要 WebDAV + S3。
- **上一版方案有四个硬错误**，已在 `00` 修正：CDC 不能进 v1；锁租约不是 v1 兼容的并发方案；文本合并需要本地 base 内容缓存；手机不是“加 platforms”。
- **多库**：数据层**一库一仓库**（各自 head/history/lock/base）；连接层可以共享一个连接配置；服务层一个同步服务管多个 runner；**绝不能让所有库共用一个清单**。
- **已定（2026-11-18）**：连接默认共享；新库默认子仓库；同步密码**每库一个**；桌面 2/手机 1；库副本默认分叉；**资产库作为主库子目录**，随主库自动同步；LAN/S3/WebDAV 是三种 transport，共用一套协议（详见 `06` 的讨论记录）。
- **下一步**：先写协议规范 v1 + 裁决记录 + spike 计划；**spike 数据回来前不写 Rust 协议层**。
