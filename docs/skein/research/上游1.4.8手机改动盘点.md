# 上游1.4.8手机改动盘点

## 问题

我们投稿的 #772（标题即 tab 切换器）和 #774（库即抽屉）在 2026-11-26 被上游合并；同一天的 1.4.8-rc.6（#829）又把两者收回，随后 #830、#833 对手机/平板做了更大的改动。需要记下上游的最终形态、从这两个 PR 里保留了什么，以及以后把 1.4.8 合进 fork 时的冲突点和取舍。

## 证据

### #829：收回的方式

提交信息原文的要点：“a phone keeps the desktop's parts (rail, sidebar, tab row) and adapts them, rather than swapping them for a drawer and a tab switcher. What they brought that isn't phone-only stays: one tab menu for every tab row (`documentTabMenu`), Read Only as a toggle.”

具体删除/回退：

- `src/mobile/TabSwitcher.tsx`、`TabSwitcher.css` 删除；`App.tsx` 去掉 TabSwitcher 的 lazy 与 `tabSwitcher` 属性，`tabsInBar` 恢复为不排除手机。
- `WindowBar.tsx`、`DocumentIslands.tsx` 的 `tabSwitcher`/`tabsInBar` 手机分支回退。
- `Sidebar.tsx` 的抽屉头部 tabs 回退为标题；`useSidePanels.ts` 的 `railShown` 恢复手机也显示 rail；`mobile/styles/sidebar.css` 的 `--rail-width: 0` 与抽屉宽度回退。
- `docs/dev/ios-code-map.md` 改写为“手机=桌面部件的适配”。
- 两份 release note（`phone-tab-switcher.md`、`phone-library-drawer.md`）删除。

同批 #829 保留下来的、不是 phone-only 的成果：

- `src/app/tabs/tab-menu-items.ts` 的 `documentTabMenu`：所有 tab 行共用的一份菜单（路径、Read Only、pin、批量关闭）。
- Read Only 在菜单里作为 toggle（`toggle: true`），不是一次性的命令。
- 手机 tab 行的列表按钮显示 tab 数量（`tab-bar-list-count`），列表末尾接当前 tab 的 `documentTabMenu`（`TabList.tsx` 的 `activeMenu`）。
- 关闭 sidebar 时焦点回到 `window-bar-sidebar-toggle`（`Sidebar.tsx` 的 `focusBackToToggle`）。
- 开始页按钮统一命名：New File / Open File / Open Folder。

### #830：手机/平板 polish（在收回后的桌面部件的形态上）

- **Interface Size 五档跟随系统文字大小**：iPhone/iPad 读 WebKit 的 body style，Android 读 `MainActivity` 的 font scale；未手选时用系统档，Extra Large / Largest 为新增的触摸专用档。文字、图标、行高、间距一起变；bar 止于 Large；文档按主题字号跟随。Android WebView 不再二次缩放文字（`textZoom = 100`）。
- **菜单挂在按钮上**（HIG pull-down / Material 默认）：点菜单外部只关闭菜单，不触发底下那一下；打字时打开的菜单把键盘还回去；Back 先收子菜单。
- **大字号布局**：开关与长中文名并排；值和 chevron 作为一个整体；两个最大档时设置行堆叠、菜单标签换行；文档边距止于 Large；竖屏平板在 Extra Large/Largest 采用手机布局。
- **平板 44pt 点击目标**：格式栏、tab 行、resize grip、搜索框、下拉、设置行。
- **CSS 收敛**：触摸规则统一挂 `data-touch`（原先 iOS/Android + `pointer: coarse` 的选择器写了 29 次）；手机档位独立 `ui-sizes-phone.css`，脚本读它而不是复制一份刻度。
- 新 e2e：`tap-sizes.spec.ts`（手机/平板每个档位的点击尺寸、不出屏、开关并排、菜单标签不截断、正文行可读）、`phone-menus.spec.ts`；iOS 模拟器 + Android 模拟器手验最小/默认/最大系统字号。

### #833：菜单分组与 Search

- tab 菜单第一组最多三行：路径的几种用法收进 `File Location` 子菜单（HIG 的 context menu 分组要短）。
- Search 面板增加 “In this document”：当前文档的标题，点一条跳过去。
- #830 复核：boot 脚本的 size step 与 app 对测；bars 里插件字号止于 Large；composer 拖高不越窗。

## 结论

上游手机最终仍是“桌面部件 + 适配”：有 rail、sidebar、tab 行；没有抽屉，也没有标题切换器。我们的两个 PR 在形态上被否，但其中非 phone-only 的部分留了下来（`documentTabMenu`、Read Only toggle）。

对 fork 的取舍：

1. **不跟随收回**。fork 的手机形态由裁决 67 定：页签在文档名后（TabSwitcher，cherry-pick `pr/tab-switcher`，不整支 merge）。上游 #829 删掉的 `TabSwitcher`/抽屉接线，在 fork 里要保留。
2. **吸收与形态无关的成果**：`documentTabMenu`（若 fork 的 cherry-pick 里还没有）、Read Only toggle、tab 列表数量按钮 + 当前 tab 菜单、关闭 sidebar 焦点回 toggle、#833 的菜单分组与 Search 标题。
3. **#830 按项评估**。它是上游在“桌面部件适配”形态上的字号/菜单/点击目标方案，和 fork 的 H0/PH 系列手机线有重叠（PH5 胶囊、PH13 页面转场、PH14 橡皮筋）。字号阶梯、菜单挂按钮、44pt、`data-touch` 这些可独立吸收；涉及 token 刻度和 `ui-sizes-phone.css` 的部分要和 fork 现有 chrome-scale 方案对齐后再取。

## 适用边界

以后合 1.4.8 时，冲突点集中在 #829 的收回：

- `src/app/App.tsx`：`tabsInBar` 的 `&& !phone`、`TabSwitcher` 的 lazy 与 `tabSwitcher` 属性。
- `src/app/frame/WindowBar.tsx`：`tabSwitcher` prop。
- `src/app/islands/DocumentIslands.tsx`：`tabsInBar` 的手机分支。
- `src/app/frame/Sidebar.tsx`：抽屉头 tabs（保留）与 `focusBackToToggle`（吸收）。
- `src/app/frame/useSidePanels.ts`：`railShown` 的 phone 分支（保留 fork 行为）。
- `src/mobile/styles/sidebar.css`：`--rail-width: 0`、抽屉宽度（保留 fork 行为）。
- `src/app/tabs/tab-menu-items.ts`、`src/engine/controls/tabs/TabList.tsx`：保留并吸收上游的菜单分组/数量按钮。

处理原则：以 fork 的手机形态为准解冲突，把 #829 之后“非 phone-only”的成果并进来；#830/#833 尽量整取，但逐项对照 fork 的 PH 系列，避免把已经真机验过的手机行为改回上游的桌面适配形态。合并后跑 `touch-devices`、`sidebar-panels`、`ai-tabs`、`tap-sizes`、`phone-menus` 的 e2e，再上华为真机走一遍今天的手机主路径。

## 附：上游节奏观察

- 从 #772/#774 合并（11-26 上午）到收回并发布 1.4.8-rc.6（同日），再到 1.4.8 正式版（11-28），约两天。上游对手机形态的调整很快，而且会在合并后再改设计；fork 跟 release tag 时要把“合并后的收回”当作正常情况，不能假设合并即定稿。
- 上游的 e2e 覆盖面在手机线上增加得很快（`tap-sizes`、`phone-menus`），以后 fork 合上游时这些用例可以直接用作回归。
