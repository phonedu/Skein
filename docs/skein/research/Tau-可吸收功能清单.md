## 0. 结论先行

**一句话：Tau 的「色值层」不能借（暖纸 + 陶土橙 vs 我们的 Slate 冷灰蓝），「机制与交互层」有 11 项值得吸收，其中 3 项现在就能落。**

Tau 的强项恰好补在 H0 之后最缺细节的地方：右页边只有「有/无」两态、设置页只有表单没有「状态」、编辑器的表格与历史是空白。Tau 把这些做成了体系，但它的审美与我们的 Slate 玻璃卡不同源，所以只借结构、不借皮肤。

## 2. 逐项说明

### 2.1 设置页分区状态卡（#1，P0）

- **借什么**：同步这类「有远端、有进度、有失败数」的分区，要有一张能一眼读懂的卡：两个大数字（本地版本 / 远程版本，远程用 accent）、一条进度条（已处理 373/549 68%）、一行统计（上传 126 / 下载 18 / 跳过 229 / 失败 3），下面才是动作按钮。
- **Tau 怎么做**：`apps/desktop/mockups/settings/index.html` 的「方案 A 第三版」；规范里对应「状态卡」——`ok/warn/danger` 只作状态点与失败数字，图标一律中性墨，卡片用 surface + shadow-card 不描边。
- **我们怎么落**：`src/settings/pages/SyncPage` 在 `SyncStatusHeader` 之后加一张状态卡，数据取现有 `syncStatus` / `syncLast`（本地/远端版本、已处理数、失败数若 IPC 已带则直接用，缺的字段补到 `ipc-sync`）。Slate 下用 `--ui-surface` + `--shadow-card`，accent 只给「远程版本」与被点亮的进度段。
- **代价**：小。若 IPC 缺统计字段，需要同步引擎补几个计数（S3q 顺手）。

### 2.2 右页边宽度阶梯（#2，P0）

- **借什么**：不是「340 固定」，而是三级：可拖 360–560（默认 400、宽度记忆）→ 空间不足先把左栏收成 58 图标列 → 仍不足才退化为覆盖浮层，Esc/后退先收页边。
- **Tau 怎么做**：`src/app/assistLayout.ts` 的 `MAIN_MIN_OVERLAY = 560`；`shellStore.ts` 的 `ASSIST_MIN_W 360 / ASSIST_MAX_W 560 / ASSIST_DEFAULT_W 400`；`Sidebar` 收起 58；`ui-interaction.md` 写明「页面可接管自己的对话（`useOwnAssist`）」。
- **我们怎么落**：`src/app/frame/app-shell.css` 现在是 `--right-column: 340px`，`data-right-panel-overlay` 直接覆盖。改成：①打开时按窗口宽度决定「正常 / 收左栏 / 覆盖」三档（收左栏复用现有折叠态）；②可选把 340 改成可拖（需裁决，见 §3）；③页面接管先不做，等有第二个宿主（插件页）再议。
- **代价**：中。涉及壳层断点与小裁决；只做「先收左栏再覆盖」也可以，不动宽度。

### 2.3 表格行列手柄与合并（#3，P0）

- **借什么**：悬停格子时列顶/行左出现手柄 → 点击选整行/列并开菜单（上下左右插入、对齐、清空、删除）→ 按住手柄拖动调序；表右侧/底部「+」追加；跨格拖选后浮出「合并 3 格」，合并后可「拆分单元格」。
- **Tau 怎么做**：`apps/website/content/docs/editor.md`「表格」一节；设计稿 `apps/desktop/mockups/table/`（含 `merge.html`）。
- **我们怎么落**：Milkdown 表格现在只有基础编辑与粘贴拆合并。按 ProseMirror 表格命令做手柄与菜单；合并/拆分用 `addRowAfter` 等同类表格 command（`mergeCells` / `splitCell`）。导出 Markdown 时不保留合并（与 Tau 同口径：Markdown 表格无此写法），复制/导出 HTML 保留。
- **代价**：中。表头手柄的命中区域与滚动容器要单独测，触屏端另做长按菜单。

### 2.4 编辑历史时间轴 + 逐条撤销（#4，P1）

- **借什么**：工具栏时钟 → 正文旁时间轴（按天分组）；点一条，正文里着色标出新增/修改/移动，「撤销这次编辑」「恢复到此版本」都走确认并作为新修改入历史；共享正文按作者筛。
- **Tau 怎么做**：`docs/architecture/desktop/data-baseline.md` 与用户文档「编辑历史」节；实现是版本化正文 + 逐次编辑记录（设计稿 `docs/notes/2026-11-19-edit-history-redesign/`，含 rail / margin / time-travel 三个方向）。
- **我们怎么落**：宿主目前没有编辑历史，且「逐条撤销」依赖每次编辑的 diff 记录，不是简单快照。先做**只读时间轴 + 版本恢复**（成本低，复用现有快照/版本对比能力），逐条撤销作为二期。落点建议与 D1t（时间线）、D1f（词条/复查）一起裁，避免两套「历史」。
- **代价**：大。存储与 diff 口径要先定，不要一边做 UI 一边改数据。

### 2.5 AI 回答引用到正文（#5，P1）

- **借什么**：把一条回答「引用到正文」——行内引用（显示对话标题，悬停预览该轮问答，点击在右栏打开并定位到那条消息）或「作为摘录块插入」（原文快照，对话删了文字还在）；也可复制引用链接，粘回正文自动变成引用。
- **Tau 怎么做**：`ui-interaction.md`「聊天引用」——行内节点 `chat-ref`（存会话 id + 该轮 user entry id + 标题/轮次快照，**不存正文**）、摘录块 `chat-quote`（存原文快照）；剪贴板用 `tau://chat/<sessionId>?entry=<entryId>` 深链，粘回时 ingest 认领；导出 Markdown 为 `:chat-ref[…]`。
- **我们怎么落**：新增一个 Milkdown inline 节点（宿主扩展），存 `{ sessionId, messageId, title, turn }` + 可选 `quote`；点击经 AI 侧边栏打开对应会话与消息。Markdown 表示要单独立规则（不能丢往返），导出可写成普通链接 + 引用块。
- **代价**：中。节点、导出、剪贴板、右栏定位四处要一起做。

### 2.6 确认行/洞见行解剖（#6，P1）

- **借什么**：一行一条「发现」，左边一个小图标 chip，标题加粗，右侧一行元信息（类型 · 范围 · 日期），下面一句说明与 1–3 条证据（引用图标 + 原话），底部三个动作（主动作、次动作、不相关）；底部「还有 N 条」。
- **Tau 怎么做**：设计稿 `apps/desktop/mockups/home-insight/index.html`；证据的原话来自笔记片段，点开定位到块。
- **我们怎么落**：今天页的待确认（`TodayPanel` 的 skeleton 裸行）与 `skein.collect` 的确认中心共用这套行解剖：图标 chip 用插件图标，右侧元信息用「资产类型 · 来源 · 时间」，动作按确认动作生成（接受 / 查看来源 / 忽略）。
- **代价**：小到中。主要是行样式与动作插槽，不动数据。

### 2.7 块菜单补移动与剪切（#7，P1，小改）

- **借什么**：块菜单除「转换成 / 副本 / 复制 / 删除」外，还要「上移 / 下移 / 剪切」（列表项按项移动，普通块按块交换）。
- **Tau 怎么做**：`editor.md`「拖拽和块菜单」；实现里 `transform` 与 `block.move-up/down/copy/delete` 是稳定的命令 id，插件菜单也按同一套聚合。
- **我们怎么落**：`src/editor/blocks/block-menu.ts` 追加两项与对应命令（已有 `block-commands.ts` 的移动/删除原语可用）；快捷键沿用编辑器键表。
- **代价**：小。

### 2.8 移动端面板占键盘位置（#8，P2）

- **借什么**：点 Aa / ＋ 时，先 `reserve(面板高度)` 再收键盘；面板 `fixed` 在视口底部、高度等于预留，页面高度不变；面板里搜索时面板移到键盘上方，预留变成 `max(面板高, 键盘高 + 220)`；切回键盘先聚焦再关面板。
- **Tau 怎么做**：`docs/architecture/mobile.md`「编辑器配件栏与键盘预留」——`KeyboardViewportProvider` 对外只给「有效值 = max(真实键盘, 预留)」，`useKeyboardReservation()` 提供 reserve / releaseWhenKeyboardShown / releaseNow。
- **我们怎么落**：PH1 已有「就地面板」与 `keyboardCovered()` 快照；补的是**预留**：开面板时把 `--keyboard-height` 之外再维护一个 `--panel-reserve`，面板高度 = 预留，关面板回键盘时按「0.9 倍预留或 600ms」释放。先只给文本/插入两个面板做，别扩到全套上下文。
- **代价**：中。iOS/Android WebView 的键盘事件差异要真机验（我们已有华为与模拟器两条线）。

### 2.9 源码⇄预览块四态口径（#9，P2）

- **借什么**：所有「源码⇄渲染」块（Mermaid、公式、Typst、TikZ、HTML）共用一个容器规范：悬停出工具条、编辑态有明确边界、渲染失败整块红字给解析错误、空块显示「点击编辑」。
- **Tau 怎么做**：设计稿 `apps/desktop/mockups/preview-editor/index.html`（现状问题：操作条不随主题、编辑态无边界、分隔太重 2px + 20px 内缩）；方案是「源码在 track 底上、预览在下、中间一条发丝线」。
- **我们怎么落**：不新建组件，先把现有 `pendingDiagram` / 公式预览 / 图片预览统一到一份「预览容器」样式与状态约定，写进 ED1 的规范；错误态用 `--ui-danger` 文字 + 等宽字体显示解析错误。
- **代价**：小（规范）到中（统一容器）。

### 2.10 理论行为三条（#10，P2）

- **借什么**（不是 UI，是可执行的产品规则）：
  1. **观点 = 卡片 + 长文的「节」**：长文按「出现两次以上的最高级标题」断节，节可以参与链接、检索、图谱；**不把段落当单元**，也**不提供「从文章抽一段成卡片」**。
  2. **洞见默认给问题不给答案**：提示「这里可能缺什么/和哪篇呼应」，一键展开才看 AI 的看法；出现在阅读时（页边淡标记），可关闭、有数量上限。
  3. **对话 = 过程不是产物**：只把**用户的提问**当意图信号（「问了但没写」），AI 回答是外部材料；对话不做图谱节点、不参与「我的关注」统计。
- **Tau 怎么做**：`docs/notes/2026-10-01-knowledge-loop-product-direction.md` §2、§3.2、§4.4。
- **我们怎么落**：写进《笔记资产理论》的规则层与 D0.5 的验证口径；D1f 复查时按这三条检查词条与洞见。
- **代价**：无代码，改文档与验证口径。

### 2.11 脉络四形态（#11，P2）

- **借什么**：同一份「关联」在正文里有四种呈现，按「关联多少」选择：完整分区 / **脚注一行**（正文后一行小字，点开就地展开，没有关联时不出现）/ **页边批注**（右缘小字，窄窗自动退回脚注）/ 元信息入口（计数 + 浮层）。四形态共用视觉重点：把「对方那句话」原样摆出来，自己的标题在句中被点亮。
- **Tau 怎么做**：设计稿 `apps/desktop/mockups/context-panel/index.html`（B 脚注一行 / C 页边批注 / D 元信息入口三方向对比）；实现上「被引用」来自索引，部分关联来自 AI。
- **我们怎么落**：卡片详情已有来源链/使用记录；正文层先做**脚注一行**（只显示「被 N 处引用 · 也在 X」），点开进右侧页边或浮层；页边批注作为宽窗增强。与 D1f 的「复查」共用同一份关联数据。
