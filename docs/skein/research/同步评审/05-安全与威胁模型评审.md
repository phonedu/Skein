# 安全与威胁模型评审（子代理）

> 来源：子代理独立评审，2026-11-18；只读分析，未修改任何文件；未经逐条人工复核。
> 路径缩写：`CS/` = `C:/Project/textus-plugins/development/cloud-sync/src/`，`TX/` = `C:/Project/Textus/src-tauri/src/`，`TP/` = `C:/Project/Textus/src/platform/`，`DOC/` = `C:/Project/Textus/docs/dev/`。

---

## 1. 结论

| 维度        | 评级   | 理由                                                                                                                                                                                                             |
| ----------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E2EE 密码学 | **B+** | AES-256-GCM、HKDF 分离、AAD 绑定逻辑键、descriptor pin 都做得扎实；但无重放/回滚防护，KDF 固定且无轮换/恢复，元数据泄露                                                                                          |
| 传输        | **B**  | 强制 HTTPS、host grant、重定向逐跳检查、超时/大小上限；但重定向会转发 body 与 `x-amz-security-token`，无证书固定，私有 CA 不可用，无整次同步 deadline                                                            |
| 凭据        | **C**  | 插件间隔离、UI 掩码、不写入远端清单；但 `plugin_secrets.json` 明文含同步密码，进 OS 备份/漫游，无 Keychain/Keystore，插件代码可直接读，断连后残留旧身份凭据                                                      |
| 本地/移动端 | **B-** | 路径校验和原子写基础好；但无每段长度/NFC 规范，Android SAF 的删除与二进制写当前直接导致整次同步失败                                                                                                              |
| **综合**    | **B-** | **最大风险一句话：密码学本身没有明显破绽，但默认关闭 E2EE、没有回滚/重放防护、同步密码与服务器凭据以明文文件落盘，且插件本身持有明文和密码——失陷服务器或恶意插件更新无需破解加密即可读取、回滚或删除用户数据。** |

最优先的五件事：P0 签名 head + 本地 lastRevision；P0 新连接默认 E2EE 或强制二选一；P1 服务器时间只用于排序并 clamp；P1 修复锁创建在 `try` 之外导致的孤儿锁；P1 凭据迁 Keychain/Keystore 并清理断连残留。

### 关键缺口展开（按严重度）

1. **回滚/重放是当前最大的“加密外”风险。** 攻击序列：A 设备已同步文件 F（hash H1，base B1）→ 服务器重放旧 head R1（F 为 H0 或不存在）→ A 同步时，若 R1 有 H0，`l===b` 触发 `download`，用 H0 覆盖本地 H1；若 R1 无 F，`l===b` 触发 `deleteLocal`，把 F 移入 Trash，然后基于 R1 发布新 head。`CS/planner.ts:41-50`、`CS/engine.ts:318-340`。E2EE 只保证“这段密文没被改”，不保证“这是最新一段”。必须加 signed head + 本地 lastRevision + `prev` 链；ETag 不能替代。
2. **服务器时钟可以直接清空历史/回收站。** `Date: 2036` → `skew` 巨大 `CS/transport.ts:89-90` → `now` 为 2036 `CS/engine.ts:156` → `cutoff` 过滤掉所有旧 trash `CS/engine.ts:160-163` → `origin.at` 也是 2036 `CS/engine.ts:403-406` → `thin()` 把所有版本判过期 `CS/history.ts:123-124` → `dropped` 进入 `clean()`，`unusedBlocks` 认为不再被引用 → 删除历史块 `CS/publish.ts:109-134`。整个过程不需要破解加密。修复：保留策略用本地时钟或单调 seq；服务器时间只做排序并 clamp。
3. **孤儿锁。** S3 `PUT If-None-Match:*` 已成功但响应丢失/503 → `request` 重试 `CS/transport.ts:91-101` → 412 → `create()` 返回 false `CS/transport.ts:160-168` → `synchronize` 在 `try` 之前抛 `locked` `CS/engine.ts:121`（`try` 在 135 行）→ 锁永远留着，直到用户手动 unlock。修复：create 返回 false 时读回 LOCK，若等于自己的 owner 则接管；把 create 放进带清理的 `try`；DAV MOVE 响应丢失同理。
4. **凭据/密码落盘与残留。** `settings.save` 把 `{account, secret, syncPassword, sessionToken}` 写进 `ctx.secrets` `CS/settings.ts:80-83,125`；Rust 写入 `plugin_secrets.json` `TX/plugins/files.rs:146-164,192-221`；0600 只在 Unix `TX/atomic.rs:71-83`。`forget()` 只删当前哈希 key `CS/settings.ts:140-144`；换过 endpoint/prefix 后旧 key 无法枚举删除；`vault:`/`base:`/`pending:`/`last:` 也不清。Android 默认备份、iOS Application Support 默认备份、Windows `%APPDATA%` 可能漫游。
5. **移动端删除/二进制当前是硬阻断。** `contentPluginFs.trash` 直接抛 `TP/content-plugin-fs.ts:137-141`；Rust `user_file_to_trash` 在非桌面直接报错 `TX/atomic.rs:400-416`；`local.remove` 抛错会让整次 sync 中止（`CS/engine.ts:318-325`）。`contentPluginFs.write` 对 base64 直接抛 `TP/content-plugin-fs.ts:108-114`，`Workspace.createBinary` 用 `files.write(bytes)` `CS/local.ts:81-111` → 任何二进制附件下载都会失败。计划中的 app trash 和 SAF 流式写必须作为 spike 的验收项。
6. **删块无自愈。** `known` 来自远端清单 `CS/engine.ts:188-191`，`upload` 对 known 块直接跳过 `CS/engine.ts:88-98`；服务器删掉一个块后，拥有本地文件的设备同步时不会重传，base 照常前进；新设备/历史恢复才在 `download` 报 `integrityError` `CS/engine.ts:56-70`。需要 `integrityError` 时从本地重传 + verify/repair。
7. **prefix/首次连接。** 默认 `textus/<folder>` `CS/config.ts:14`、`CS/panel.ts:17-22`；共享桶里两个同名文件夹会撞。明文模式 `openPlainStore` 接受任意 head `CS/plain-store.ts:7-18`，base 为空时 `plan` 会把远端所有文件当 download `CS/planner.ts:41-50`，没有确认。E2EE 密码能挡住，但默认未开。
8. **S3 ListBucket 与 404。** `get`/`has` 只把 404 当缺失 `CS/transport.ts:144-155`，403 一律 `permissionError` `CS/transport.ts:103-110`；AWS 在没有 `s3:ListBucket` 时对缺失 key 返回 403，`putBlock` 对新块先 `has` `CS/engine.ts:102-104`，首次上传可能直接失败。README 的“只需 read/write/delete” `plugins/catvinci.cloud-sync/README.md:132-136` 需要修正为“prefix 条件化的 ListBucket”。

## 4. 安全验收标准（可测试断言）

**P0**

1. 回滚：给定“上次 head R2、本地 base H1”的设备，store 重放 R1（F 为 H0 或缺失）时，同步必须以新错误 `remoteRolledBack` 停止；断言：本地 F 未被覆盖/未进 Trash，未发布新 head，base 未前进。当前代码会失败（`CS/planner.ts:41-50`、`CS/engine.ts:318-340`）。
2. 签名 head：篡改 `revision/seq/prev/files` 任一字段、或把 `prev` 指向非上次 revision，验签失败；旧 head 的签名在新设备上可验证但被 `lastRevision` 拒绝；用固定向量测试 HMAC/Ed25519 的规范序列化。
3. 服务器时间：store 返回 `Date: now+10y`，同步后断言所有 history versions 和 trash entries 仍在，未调用 `remove(blockKey(...))`；`updatedAt` 为非法/超范围时拒绝或 clamp。
4. 锁归属：一个 `create(LOCK)` 在服务器端写入后返回 503（重试得到 412）的 store，同步结束必须没有 `LOCK` 残留；一个 `create` 抛网络错误的 store 也不能留锁；`openEncryptedStore` 同样。
5. 新连接默认：`normalizeConfig({})`/全新 profile 的 `Config.encrypt` 为 `true`，或 UI 必须强制用户二选一并显示“服务器可读全部内容”的警告；测试断言不存在“默认 false 且无警告”的路径。
6. 凭据：`plugin_secrets.json` 的 schema 不包含 `syncPassword`（或它只存在于 Keychain/Keystore 的测试替身）；Unix 上文件 mode 为 0600；Android manifest 有 `allowBackup=false` 或 dataExtractionRules 排除 secrets；iOS 有 `isExcludedFromBackup`。
7. 断连：`Settings.forget(root)` 后，`ctx.secrets` 中不存在该 root 的任何 `connection:*`，`ctx.storage.global` 中不存在该 root 的 `vault:*`/`base:*`/`pending:*`/`last:*`；用两个不同 endpoint/prefix 的 identity 测试。
8. 重定向：Rust `plugin_http` 对 307/308 跨 origin 的行为断言：不发送 `Authorization`、`x-amz-security-token`、不重发 body；或同步层直接拒绝重定向。当前 session token/body 会泄漏。
9. 同步 deadline：一个每块 sleep 超过 60s 的 store，同步必须在配置的总 deadline（如 5 分钟）内失败并释放 LOCK；`net.fetch` 必须收到 AbortSignal。

**P1**

10. 删块自愈：从 store 删除 manifest 引用的块 X，设备 A 有本地文件 F；A 同步后断言 X 被重新 PUT（或明确报 `repairRequired` 并列出文件），不能静默成功。
11. 移动端删除：模拟 `files.trash` 抛错（Android SAF / iOS 非桌面）；同步必须把该文件标记为 `deferred`/移入 app trash，其他文件继续，远端删除仍发布；不能整次 abort。
12. 移动端二进制：SAF 根上写入二进制要么通过流式 API 成功，要么返回专用 `unsupportedBinary` 且不留下 marker/半文件；不能 `localWriteError` 后整次 abort。
13. 路径规范化：remote 提供 NFC `é.md`，模拟 macOS 本地返回 NFD；断言只产生一个逻辑路径，不同步出 `caseCollision`；300 字符的单段路径被 `invalidManifest` 拒绝；bidi/零宽路径被拒绝。
14. 首次加入：本地 base 为空、远端已有非空 head 且 `encrypt=false` 时，必须要求用户确认“加入已有远端”；未确认不得下载/上传；确认后显示文件数量与前缀。
15. repositoryId：prefix 中已有 `repositoryId=A` 的 marker，本地 pin 为 B；同步以 `repositoryChanged` 拒绝，不写入。明文模式也要有 marker/首次确认。
16. S3 403-missing：模拟“无 ListBucket、缺失 key 返回 403”的 S3；错误必须是可操作的 `listBucketRequired` 或明确提示，而不是笼统 `permissionError`；IAM 文档包含 `s3:ListBucket` 的 prefix 条件。
17. 隐藏文件：`isHiddenFilePath(".obsidian/plugins/x/data.json")` 返回 false（拒绝），或必须走 `plugin_app_settings` 白名单；`plugin_read_resource` 对非当前 view 的 resource 在 Rust 层拒绝。
18. 资源上限：`plugin_secret_set` 的 value 超过 N 字节被拒绝；`plugin_http` 的 request body 超过 N 字节被拒绝；`plugin_store` 已有 50MB quota。
19. 打开文件：Windows/macOS 大小写不敏感路径上，tab 打开 `A.md`，同步路径 `a.md`，`apply` 必须 defer，不写盘；跨窗口打开也要检测。
20. 历史保留：`keepDays=0` 时 history 不被 `thin` 删除；`keepDays=90` 时只删过期；`MAX_VERSIONS=200` 生效；`unusedBlocks` 不删除仍被 `remote.trash` 引用的块（或明确回收旧 trash 块）。

**P2**

21. ETag 快进：伪造 304/ETag 的 store 不得让客户端跳过解密/验签；若跳过下载，只能使用“上次已验证 head”，且不得基于它发布而不重新校验。
22. KDF：固定向量（password、salt、repoId、明文 → verifier、AAD、HMAC 名）在 JS 与 Rust 实现间逐字节一致；`iterations < 600k` 拒绝，`iterations` 上限拒绝；v2 新 KDF 与旧 600k 并存。
23. 可选字段：在 descriptor 增加 `extensions:{...}` 不改变旧/新客户端的 pin；在 manifest 增加未知字段不改变旧客户端解析。
24. GC：过期 trash 块的块最终被回收（或文档明确不回收）；`MAX_TRASH` slice 后不产生永久泄漏；`clean` 不删除任何仍被 next/remote/history/next.trash 引用的块。
25. `parseHistory` 拒绝非安全字符集的 `previous/head`（如 `../`、超长），不再让 `publish` 抛 `invalidPath` 整次失败（`CS/publish.ts:62`）。
26. `parseManifest` 拒绝 `updatedAt` 非 ISO/超范围、`revision` 非安全字符集；`RemoteStore`/`EncryptedStore` 的 snapshot key 只接受安全 revision。
27. SQLite 索引：用文档中的唯一标记字符串写入后，索引文件/WAL 中找不到该标记（若做全文索引则必须加密）；断连后索引被清空。
28. 备份：Android `allowBackup`/dataExtractionRules 与 iOS 排除属性有 CI/静态检查；文档列出“备份包含 plugin_secrets、base 路径，不含明文远端内容（E2EE 时）”。
29. 隐私：`ext_stats` 只发送 kind/id/version/event，不含设备/内容；同步代码无 analytics/telemetry 调用；崩溃报告不采集内存。
30. 错误脱敏：store 返回包含 secret/body 的 500，UI、`ctx.log`、`last` 存储中都不出现该 body；只出现 code/status/本地路径。

## 5. 需要用户拍板的安全取舍

1. **自签名/私有 CA**：推荐“按端点证书 SHA-256 指纹固定 + 首次连接用户确认”，而不是全局关闭证书校验；如果目标用户主要是自建 WebDAV，这是必须支持的能力；如果只支持公共 CA，要在 UI 明确写“自签名证书不可用”。
2. **内置阶段的凭据存储**：Keychain（macOS/iOS）、Keystore/EncryptedSharedPreferences（Android）、DPAPI/Credential Manager（Windows）、Secret Service（Linux）优先；Linux 无 Secret Service 时回退 0600 文件并明确警告。是否允许“锁屏后必须重新输入密码才能自动同步”（Keychain ACL/生物识别）会牺牲自动同步体验，需要拍板。
3. **同步密码是否必须保存**：当前为了自动同步把密码存进 secrets（`CS/settings.ts:62-66,80-83`）。可选：(a) 继续存（自动同步，但落盘）；(b) 只存 Keychain/Keystore 包装的 DEK（自动同步且不存明文）；(c) 每次会话手动解锁（最安全，最不方便）。推荐 (b)。
4. **密码恢复/轮换**：当前无恢复、无改密码（README:183-186）。推荐 v2 采用“随机 DEK + 密码 KEK 包装”，支持改密码/设备撤销；是否提供 recovery key（用户抄写）由产品决定；默认“无恢复”要显著提示。
5. **默认 E2EE**：当前新连接默认 `encrypt:false`（`CS/config.ts:22`）。推荐新连接默认开启，或强制二选一并明确“关闭后服务器可读全部内容和文件名”；明文远端首次加入必须确认。
6. **共享桶/prefix 策略**：默认随机 prefix（如 `textus/<uuid>`）还是保留 `textus/<folder>`；是否允许两个用户共享同一个 prefix（当前不支持，应明确拒绝）；`repositoryId` marker 是否进入 v2 路径。
7. **远端保留与“彻底删除”**：`keepDays` 默认 90、可选 0（永久）。是否提供“立即清除远端历史/回收站”的锁内操作；S3 桶版本化/Object Lock 下应用层无法真正删除，是否在 UI 警告并建议关闭版本化。
8. **SQLite 索引内容**：只索引路径/hash/元数据（隐私好、搜索弱），还是加密全文索引（搜索强、复杂度和密钥管理上升）。
9. **备份策略**：Android `allowBackup=false`/排除 secrets、iOS `isExcludedFromBackup`、Windows 排除 `%APPDATA%` 漫游；这会牺牲“换机自动恢复”，需要产品拍板。
10. **插件阶段供应链**：是否要求插件包签名/更新二次确认；是否把 `network:*` 改为“保存端点时记录 host”的动态授权；是否因为插件持有明文+密码而提前结束插件阶段、直接做 Rust 内置。
11. **重定向策略**：同步请求完全禁止重定向（最安全，部分 S3 兼容服务会受影响），还是仅允许同源；跨 host 必须剥离 `x-amz-security-token` 且不重发 body。
12. **移动端删除语义**：app trash（可恢复、仍占空间、需显示占用/保留期）还是永久删除（省空间、不可恢复、需二次确认）；远端 history 默认保留期是否因移动端而缩短。
13. **TLS 根**：继续用 webpki roots（企业私有 CA 不可用、抗 MITM 强），还是改用系统根（企业代理可用、但 TLS 终止代理可读明文与 Basic 头）。推荐默认 webpki，企业场景用显式端点指纹，不切换全局根。
