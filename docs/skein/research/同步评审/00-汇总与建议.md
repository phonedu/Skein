## 1. 评审推翻了上一版的四个判断

| 上一版说法                    | 评审发现                                                                                                                                                                                        | 修正                                                                                                           |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| CDC 每块 ≤2MB 就向后兼容      | 旧客户端还有 `blocks.length <= 64`；CDC 1MB 下限会让 >64MB 文件及其历史整份 `invalidManifest`，不是跳过该文件，是整个仓库读不了（`textus-plugins/development/cloud-sync/src/content.ts:37`）    | **v1 固定 2MB**；CDC 留 v2                                                                                     |
| 锁租约 + head CAS 是 P0       | 旧客户端只认“锁存在”，不认 `expiresAt`；人工解锁可能删掉活跃租约；`history` 是先写的另一个对象，CAS 只护 head 会造出 `head ≠ history.head`（`publish.ts:92-96`）                                | 租约只做**自愈/体验**，按 provider 探测；正确性靠 **signed head + local lastRevision + 读侧一致性**；v1 不强制 |
| 文本三方合并改 `planner` 即可 | `Base` 只存 hash；`history` 会被 `thin`/`fit`/保留期淘汰，不能当稳定 base 来源                                                                                                                  | 需要**本地 base 内容缓存**；缺失就冲突副本；只合并 Markdown 正文，front matter/YAML/二进制不合并               |
| 手机加 `platforms` 就能用     | Android 默认库**不是** App Documents；SAF `content://` 在宿主入口就被拒（`src/plugins/host/scoped-root.ts:15-21`）；路径拼接、隐藏文件、二进制写、trash、mtime 全缺；**空扫描还可能把远端清空** | 手机前置是**宿主改动**；spike 先走 App Documents 普通路径                                                      |

## 2. 盲区清单（按严重程度）

| #   | 盲区                              | 为什么要紧                                                                                                                                                        | 设计里怎么落                                                                                                                                      |
| --- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **空扫描误删远端**                | `base` 非空、本地 scan 返回 0（SAF 路径 bug/授权失效）时，planner 会把“远端等于 base”判成 `deleteRemote`，直接发布删除（`planner.ts:41-50`、`engine.ts:311-317`） | **P0 保护**：base 非空而 scan 为 0 → 中止；删除超过阈值（如 >20% 或 >50 个）→ 二次确认；插件和内置都要                                            |
| 2   | **空 base 迁移可能永久卡死**      | 双方都不同 → 每个文件一个冲突副本；副本计入 20k/8MB，可能让 `publish` 永远 `tooManyFiles`，而且本地已经写入了副本                                                 | 迁移先 **dry-run**；优先导入插件 base；给出“远端优先/本地优先/逐文件”；预检冲突数/清单大小                                                        |
| 3   | **手机文件层是硬前置**            | 默认库不是 App Documents；SAF 被 gate 拒；`files.trash` 在所有移动端直接报错（`atomic.rs:409-415`）；`content://` 不能写二进制、没有 mtime、隐藏文件不可达        | 手机默认 **App Documents 普通路径**；“所有文件访问”可选；SAF 第一版只文本；**App 管理 trash**；打开文件走 open-docs 注册表                        |
| 4   | **history/head 不是原子提交**     | 崩溃或锁被接管时可能 `history` 已换、`head` 未换；下次 publish 基于旧 history 会污染版本/误删块                                                                   | v1：publish 前重读 head+history，校验 `history.head === head.revision`，不一致先修复再发布；v2：per-revision commit 对象                          |
| 5   | **孤儿锁**                        | `create(LOCK)` 在 `try` 之外（`engine.ts:121`）；S3 已写入但响应丢失、重试得到 412 → 永久 `locked`，只能人工解锁                                                  | 把 create 放进带清理的 `try`；412 时读回锁，owner 是自己则接管；**无 `expiresAt` 的锁绝不自动抢**                                                 |
| 6   | **块不自愈**                      | `known` 直接信任远端清单（`engine.ts:188-198`），服务器删块后上传方不会重传；新设备/历史恢复才报 `integrityError`                                                 | `integrityError` 时从本地重传；P1 加 verify/repair；GC 改 mark-sweep + 宽限期                                                                     |
| 7   | **回滚/重放没有防护**             | 失陷服务器可重放旧 head，让本地覆盖或把文件移入 Trash；E2EE 只保证“这段没被改”，不保证“是最新一段”                                                                | v1 best-effort：本地存 `lastRevision` + 已知 revision 集合 + 大批删除确认；v2：**signed head + prev/seq + 本地 lastRevision**，严格模式只接受签名 |
| 8   | **服务器时间能清历史**            | `Date: 2036` 会让 trash/history 全部“过期”，`clean` 删掉历史块                                                                                                    | 保留策略用本地时间或单调序号；服务器时间只排序并 clamp ±15min                                                                                     |
| 9   | **安全外围**                      | `plugin_secrets.json` 明文含同步密码；Android 默认备份；默认 `encrypt:false`；重定向可能转发 `x-amz-security-token`/body；插件 `network:*` 供应链面大             | 内置阶段 Keychain/Keystore 或 owner-only + 排除备份；新连接**默认 E2EE**；同步层禁重定向或仅同源；插件阶段至少 `allowBackup=false`                |
| 10  | **UX 是“静默复制”，不是“不覆盖”** | 冲突落成 `Sync conflicts/` 普通文件，没有处理面；`deferred` 被显示成“已同步”（`status.ts:26-32`）；手机没有状态面；首连要填 endpoint/region/bucket                | 冲突中心 + 横幅 + 状态计数；“部分完成”单独状态；手机首页脚注（FileTree `ViewFoot`）；三张服务卡 + 预设 + dry-run                                  |
| 11  | **两套实现必然漂移**              | 插件 JS 是 `/1` 的唯一规范；Rust 重写没有 spec/向量/差分测试，冲突命名、删除语义、加密 AAD 任何一处不同都会互相制造副本                                           | 冻结 `/1` + 写规范 + 插件生成 golden vectors + Node CLI 对同一 fixture 跑 engine + Rust 差分测试                                                  |
| 12  | **文档裁决冲突**                  | fork 现写“不改同步”“同步=深度分叉、不建议”“自建最后”（`Textus-改造方案.md:650,742,772`）；不先改裁决，实现本身违反唯一真相源                                      | **P0：先写 supersede 记录**，明确“用户自有 WebDAV/S3 的内置客户端”不是自建云/账号，并补 patch 清单                                                |

## 3. 多库同步：先给结论

完整分析见 [06-多库同步设计.md](06-多库同步设计.md)。结论：

- **数据层：一个库一个仓库。** 每个库自己的 `head/history/lock/base`，自己的 `repositoryId`。**绝不能让多个库共用一个清单**——路径会撞、一个库的扫描 bug 会删到另一个库、一个加密密码/上限/历史会互相牵连。
- **连接层：可以共享一个连接配置。** 同一个 S3/WebDAV 账号与端点下，每个库有自己的远端前缀（推荐新库 `<prefix>/<库名>-<id8>/`）；不同服务商/不同同步密码的库用不同连接。
- **服务层：一个同步服务管多个 runner。** 全局状态、全局暂停、队列、网络策略；每个库一个 runner，远端锁按仓库而不是按连接。
- **并发**：桌面最多 2 个库同时同步，手机 1 个；库内块并发沿用现有参数。
- **迁移**：按库迁移；从插件来的库沿用原 prefix，不要求重新上传；可以批量迁移，但每个库独立成败。
- **副本/分叉**：同一库的副本要能识别（同 `vaultId`），默认提示“分叉成新库”，避免两个本地库同时同步同一远端仓库。

**用户已定（2026-11-18）**：连接默认共享；新库默认子仓库；同步密码**每库一个**；桌面 2/手机 1；库副本默认分叉；**资产库作为主库子目录，随主库自动同步**。详见 [06 的讨论记录](06-多库同步设计.md#讨论记录2026-11-18部分已定)。

- **三种同步方式**：LAN / S3 / WebDAV 是**三种 transport，共用一套协议**。LAN 的第一版建议做成“内置 Hub”（桌面跑本地 WebDAV 服务，手机连它），真 P2P 不做 v1；如果对方本来就是 NAS/WebDAV，那就只是 WebDAV。

## 5. 协议规范 v1 的写入不变量（“先兼容”的核心）

- `format` 仍是 `textus-cloud-sync/1`；`inScope` 路径白名单、`KEEP_DAYS` 枚举**不变**。
- 每个 Entry 必须满足：`1 ≤ block.size ≤ 2MB`、`blocks.length ≤ 64`、`sum(blocks.size) == size`。
- 不依赖 **Entry 级**新字段——旧客户端上传时会重建 Entry，只保留 `{hash,size,blocks}`。
- 只有 **head/history 顶层可选字段**是安全的；旧客户端会 spread 保留，但旧客户端写回时会丢掉，所以不能作为正确性依赖。
- 任何改变路径接受范围、块布局、加密参数含义的改动 → **v2 硬切**，旧客户端 fail closed，并给“请升级”错误。
- `history` 与 `head` 的兼容镜像由内置维护；v2 的 commit 对象只作为新键，不覆盖 `/1`。

## 6. 插件 spike 之前先修的 7 个小补丁

这些不管内置做不做都值得修，而且能让 spike 的数据可信：

1. **空扫描/大批删除保护**（0.5 天）——最危险。
2. **锁 create 放进 `try`，412 读回 owner**（0.5 天）。
3. **移动端 App 管理 trash**（3–5 天，宿主）。
4. **Android 默认库指向 App Documents**（2–3 天，宿主）。
5. **状态修正**：`deferred` 不算“已同步”；最后一次结果持久化（0.5 天）。
6. **S3 403-missing / ListBucket 文档**；同步层禁重定向（1 天）。
7. **打开文件**：干净 tab 允许 `FILE_WRITTEN_EVENT` 原地重载，脏 tab 继续 defer（1–2 天）。

## 7. Spike 三条轨（华为真机）

- **轨 0（1–2 天）**：App Documents 普通路径。验证数据通路、原子写、mtime、附件、WebView crypto；预期除 trash/后台/状态条外全通过。
- **轨 A（2–3 天）**：所有文件访问 + 用户文件夹。验证授权持久化、跨卷 move、华为“所有文件”页面。
- **轨 B（1–2 天，只验边界）**：SAF `content://`，先不解禁 gate，确认插件被拒、提示出现、重启后 grant 是否还在；**不要**在路径未修时解禁，否则空扫描可能清远端。

通过标准：不出现远端误删、不出现本地半截文件、冲突一定两份、不支持的操作用明确错误呈现、桌面端不升级仍可读写同一远端。

## 8. 内置架构：评审后的推荐形态

```
src-tauri/crates/textus-sync/     纯 Rust，无 Tauri
  model / content / config / scope / planner / history / publish
  engine / crypto / transport(ObjectStore) / local(LocalFiles trait)
src-tauri/src/sync/               薄适配：service / commands / secrets /
                                  fs / events / lifecycle / migrate
src/features/sync/                lazyModule：设置页 / 状态 / 冲突 / 历史
src/platform/ipc-sync.ts
```

关键取舍：

- **核心放 `crates/`，不做 Tauri 插件 crate**：需要复用 `atomic`、`net`、`app_dirs`、`json_file`、`trash`，放 `src-tauri/plugins/` 会复制一套并绕过 500 行检查。
- **P1 不上 SQLite**：20k 文件上限内，`base/cache/pending/status` JSON 足够，还能直接导入插件 base；避免 C 编译、移动端交叉编译、WAL/损坏恢复。SQLite 留到 >50k 文件或全文检索。
- **加密用 `ring`**（已在 lock）：PBKDF2/HKDF/HMAC/AES-256-GCM 都有；不要引 `aws-sdk`，SigV4 手写约 200 行 + AWS 测试向量。
- **P1 不引 `rusqlite`/`notify`/`aws-sdk`/`diffy`**；`uuid` 移到共享依赖（现在只在 desktop）。
- **协议所有权只有一个**：内置发布后，插件冻结为 `/1` 参考实现，只修安全；不要长期双维护。
- **启动只读一次 config**；`src/features/sync` 走 `lazyModule`，Settings 页 `lazyComponent`；预算按 **1.00MB**（`vite.startup-budget.ts:7`，文档里的 1.25MB 已过期）。
- **宿主新钩子**：open-docs 注册表（path + kind + revision）、`file-saved` 事件、sync→window 文件事件（复用 `FILE_WRITTEN_EVENT`）、folder identity（`.textus/` 里的 vault UUID，避免 SAF/普通路径切换丢 base）、前后台 `Resumed`/`visibilitychange`、双开检测。
- **patch 清单要补**：`Cargo.toml`、`lib.rs`、`invoke_handler.rs`、`bindings.rs`、Settings 页注册、locale；现有“薄 fork 五个接入点”不够。

## 10. 需要拍板的默认（建议）

| 决策       | 建议默认                                                                 | 理由                                                                |
| ---------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| 手机库位置 | **App Documents 普通路径默认**；“所有文件访问”可选；SAF 后置             | 无需权限、原子写、mtime、附件全可用；SAF 的坑最深，先不承诺         |
| 删除语义   | **App 管理 trash**（桌面仍系统回收站）                                   | 移动端没有系统 Trash；可恢复；不改变远端 v1 语义                    |
| E2EE       | **新连接默认开**；旧明文远端保持可读                                     | 明文模式服务器可读全部内容/文件名；旧远端不能强制改                 |
| 后台       | **v1 仅前台**；后台单独立项                                              | 插件层做不到；Rust + WorkManager/前台服务是 4–8 周，且 iOS 仍无保证 |
| 迁移       | **dry-run → 导入 base/凭据（用户同意）→ 先停用插件、后卸载**；双开阻断   | 卸载会永久删插件 base/secrets；空 base 首同步可能卡死               |
| 插件命运   | 内置发布后**冻结为 `/1` 参考实现**，只修安全                             | 双维护必然漂移；也给回滚留路                                        |
| 多库       | **一库一仓库；连接可共享；服务可统一；默认子仓库布局；加密密码每库一个** | 见 `06`                                                             |

另外三个技术默认，除非反对：**P1 不上 SQLite**；**v1 不做 CDC/签名强制/KDF 升级**；**同步层禁重定向或仅同源**。
