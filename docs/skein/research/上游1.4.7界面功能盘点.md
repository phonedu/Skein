# 上游 1.4.7 界面功能盘点

## 问题

本仓基于上游 v1.4.6（合并 `457f6693`），上游 1.4.7 已到 rc.4。用户问两件事：文件侧面板的“刷新 / 排序 / 还有一个”要不要加；上游还有哪些界面功能是本仓没有的、哪些值得搬到现在的 H0 界面。

## 证据

上游 `git fetch upstream --tags` 后，`v1.4.6..v1.4.7-rc.4` 共 18 个提交（含合并）。界面相关集中在：

- `178d9561` Textus 1.4.7 round：drop files、file tree copy、path completion、custom endpoints、plugin icon themes and code languages（#786）。
- `7dbc1e1c` 1.4.7-rc.3：plugin pages by touch、plugins on phones、store categories（#798）。
- `6dd45067` rc.2 修复：phone menus（插件页菜单选择丢失）、AI 改写结构、Bases/ghost text。
- `1cddeb12` / `59ce6437`：清理轮次 + Mac 红绿灯全屏、转场/手机/卡死/内存修复。

### 侧面板工具栏（用户问的那三个）

本仓 `src/files/FileTree.tsx` 的 `.tree-toolbar` 代码里有：上级文件夹面包屑、新建文件、新建文件夹、打开为文件夹（未开文件夹时）、排序、关闭文件夹、刷新。**但 H0 壳层把整行隐藏了**：桌面侧栏 `.sidebar-body .file-tree .tree-toolbar { display: none }`（`src/app/frame/sidebar-frame.css`），手机文件页 `.phone-home .tree-toolbar { display: none }`（`src/phone/PhoneHome.css`）。当前实际可达的只有：桌面菜单 / 快捷键“新建文件”，手机 + 号（新建文件 / 文件夹）与库切换；**排序、刷新、打开为文件夹、关闭文件夹、上级面包屑没有任何入口**（2026-11-24 用户找过，确认看不到）。

上游 rc.4 同一工具栏的按钮集合与隐藏前的这一行一致，差异只是按钮类从 `tree-tool` 换成 `tx-icon-button`（1.4.7 的共享控件样式），没有新增功能。**结论：不是“已有、不用加”，而是“有实现、无入口”。** 要不要把排序 / 刷新（以及打开为文件夹、关闭文件夹）露出来，是独立于 B7 的一个小决定：桌面可放回文件页头部，手机可进 ⋯ 表。

## 本仓没有、值得考虑的界面功能

状态一栏：有 = 本仓已实现；无 = 本仓 v1.4.6 基线没有。

### A. 文档写作（桌面）

| #   | 功能                              | 上游做什么                                                                                                            | 本仓                                                                                          | 建议                           |
| --- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------ |
| A1  | 拖系统文件进文档（#777）          | 落点在左右缘→分屏，标签栏→新标签，正文→插图（预留大小）或附件链接；Finder/Explorer 的文件复制到文档旁；Shift 恒为打开 | 有“按落点打开/分屏/加链接”的基础（`fileDropOnDocuments`），无正文插图、附件链接、复制到文档旁 | **做**：最贴合写作；只影响桌面 |
| A2  | 系统文件拖进文件树 = 复制进文件夹 | 确认一次 + “不再询问”；设置›通用›文件                                                                                 | 无                                                                                            | **做**（桌面）                 |
| A3  | 路径补全 + 文件树“插入链接”       | `![](` / `[文字](` 补全当前文件夹文件；文件树右键插入链接                                                             | 无                                                                                            | **先做**：高价值、低风险       |

### D. 稳定性与观感（随上游同步）

崩溃页 → 报告问题（带出错位置）；编辑器卡死/内存；启动、主题、侧栏转场首帧；Mac 红绿灯全屏；Linux 滚动性能。

## 结论

按用户 2026-11-24 的决定，全部按建议登记，**不在本会话实施**，等后续会话做：

1. 先做一批：A3 路径补全、A4 图表错误原因、B3 商店“仅电脑可用”标记与分类、C2 插件页菜单选择修复。
2. 下一批：A1 拖文件进文档（正文插图/附件链接/复制到文档旁）、A2 文件树接收系统文件、文件树“插入链接”、C1 插件页触控三项。
3. 视需要：B1 文件图标主题、B2 插件代码语言、B4 多 AI 端点、C3 手机插件能力核对。
4. 不单摘：D 组，等上游 1.4.7 正式 tag 随同步一起拿。

实施方式：按“上游改动不重写”的纪律，摘对应上游提交；整体同步仍走 `upstream:*` 流程。

## 适用边界

- 上游版本以 rc.4 为准；1.4.7 正式版若有增减，以正式 tag 的提交为准。
- A 组只影响桌面；手机没有系统级文件拖放。
- B1/B2 会动插件 API 版本（上游 1.10），摘取时需同步 manifest 校验与文档。
- D 组与手机壳层、窗口转场强耦合，单独摘取风险高于收益。
