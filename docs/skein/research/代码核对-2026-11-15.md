**核对中发现的两个额外事实（方案没写，但直接决定阶段 1 怎么做）：**

1. **插件可以直接给 Textus AI 贡献工具。** manifest 的 `contributes.aiTools` + `ai.tools` 权限，调用经事件回流到插件窗口执行（`contributions/ai-tools.ts`）。**契约阶段 1 的「插件实现七工具」有现成通道，不需要自建工具总线**——七工具写成一个 folder 插件即可。
2. **Textus AI 已自带「提案-确认」机制。** 内置工具 `propose_edit`（"an edit the writer accepts or rejects"）、`ToolContext.undecided`（未决提案）、`ProposalLedger`（一次请求内的提案账本）、每请求工具预算器（`budget.rs` 的 CHECK_BUDGETS）、margin 审阅（`src/ai/margin/` 的 own-revisions / review-notes）。**契约的 propose_patch / request_confirm 不是从零建，是把资产状态机接到这台既有提案机上。**

**Android CI 非阻塞核实**：`ci.yml` android job `continue-on-error: true`，注释原文 "Not a required check while the Android port is young"——§1.3 的判断成立，阶段 0 必须真机补证。

### 3 从墨契（Moqi）吸收清单

**B.3.2 方法论（方案已在用，补个名字）**

- **数据优先流程**（模型卡 → 交互卡 → 迁移 → 领域测试 → UI）：资产域正是「动数据模型」的功能。阶段 1 开工前拿墨契五条模型不变量（实体/值分开、引用只有一种边、作用域唯一、视图是查询、历史是操作日志投影）把 `CardDocument` 过一遍——**它天然合格**（稳定 id + revision = 实体；sourceIds 只追加 = 唯一引用边；触发检索 = 查询不复制；审计 + `_history` = 操作日志投影）。过一遍是确认，不是返工。
- **交互卡方法**：确认中心（确认/驳回/稍后）动手前先把键盘闭环写清（Tab 走到哪、Esc 退到哪、diff 怎么聚焦）。
- **文档门两层**：Doc-Impact 行 + 反向行为门。fork 是长期仓，第一天就挂，成本极低。
- 验收清单：附录 A 已是「触发步骤 × 预期结果 + 自动化不得记作实机验收」的形态——方法已迁移，剩的是给 fork 立册。

**B.3.3 Android 真机会再踩的坑（墨契已交过学费）**

1. Android WebView 整体拒 `navigator.clipboard` → 剪贴板降级链（插件 API → `execCommand`）；
2. IME：`isComposing` 守卫 + 键盘顶起的 inset 处理；
3. 触控命中面 ≥44px 要落在每个具体控件（20×20 真机点不到的教训，§6.2 的检查别停在原则层）；
4. **浮层不是块**：若「使用记录 / 来源链」用浮层做预览，浮层高度要回写宿主、hover 要桥接，否则宿主的块标与选中框失灵。

**B.3.4 测试语料**

`md-corpus`（17 类 Markdown 语法，含 CRLF / BOM / 无结尾换行 / 1MB）是测试数据不是代码，无许可负担——Textus 保真测试现为 8/8，可用语料把用例扩到脚注 / 公式 / callout。

**B.3.5 不借清单（和借清单一样重要）**

- **块树 / 双链反链引擎**：资产工作台是文件 + FrontMatter 形态，搬了就把轻量 fork 变重；
- **oplog 自建同步**：2026-11-19 改为 S 组内置客户端（沿用 /1 协议，不做 oplog）；
- **语义检索 / RAG / 向量**：理论明确不做向量库，契约只要关键词检索；
- **主题体系、Lexical、属性注册表**：架构不同，搬不动也不需要；
- aicompat 方向是**反的**：Textus 的 AI 基建更强，将来墨契 AI 主线反过来抄它。

### 4 文档级修正建议（回写正文用）

1. **契约 `ResolveAssetsForTriggerInput.taskType` 没有对应字段**：`CardType` 只有 task / judgment / asset，卡片上只有 tags——要么删掉 taskType，要么定义它匹配 tags 的约定前缀（建议后者，如 `type:报价`）。
2. **契约 `CardType` 缺 `theory`**：理论 §7.2 的理论卡进不了工具系统——建议声明「理论卡不走工具、是纯文件手写」（低频，不值得扩类型）。
3. **「七行」口径两处不一致**：理论 §5.4 示例八项（情境/动作/预期/实际/偏差/边界/形态/触发）写着「七行」；本文 §0.5 列七项（无形态）。行数是 §8.4 记录癖的纪律工具，必须定死一处。
4. **契约 §8 的 `files.process` 名称**：插件 API 是 `files.process`；`files.processRead/processWrite` 是宿主 broker 内部名，不要写进契约。
