# 视频笔记与媒体宿主能力

> **2026-11-28 用户定方向**：把比较困难、比较通用的能力做进宿主，衍生的功能做成插件。本文把“视频笔记”按这条线拆成两层：宿主提供媒体引擎，插件做笔记与 AI。本文只定分工、边界和验收，不排期；等 `later` 里的 VID1 / MED1 被点名。
>
> 插件系统的现有边界见 [plugin-api.md](../../dev/plugin-api.md) 与 [plugins/permissions.md](../../dev/plugins/permissions.md)；界面按 [界面契约](../specs/界面契约.md)。

## 1. 结论

| 层 | 归属 | 原因 |
| --- | --- | --- |
| 笔记层：时间戳、字幕、截图、AI、文件关联、播放位置 | **插件（VID1）** | 编辑器 API 齐全，可开关、独立迭代，不碰核心 |
| 本地媒体引擎：解码、长视频流式读、截帧 | **宿主（MED1）** | 插件只能整文件读进内存再 Blob，几百 MB 是上限；宿主可用 Range/自定义协议流式 |
| 在线媒体引擎：B 站/YouTube 播放、登录、取当前时间、seek | **宿主（MED1）** | 插件页面是 opaque origin，平台播放器在里头起不来；只有原生 webview 能正常跑并受控 |

一句话：**界面在编辑器/插件页，媒体引擎在宿主。**

### 1.1 关键实测（2026-11-28）

- 插件 webview 固定 `sandbox="allow-scripts"`（`src/plugins/host/frames.ts` 的 `sandboxedFrame`）。嵌套 iframe 会继承这个标志：B 站外链播放器在里头 `window.origin === "null"`，`localStorage` / `cookie` 抛 `SecurityError`，画面全黑；同一页面里普通 iframe（正常 origin）正常播放（`readyState 4`，`duration 213`，`currentTime` 在走）。
- `webviewCsp()` 的 `media-src` 只有 `data: blob: textus-plugin:`，远端 https 的 `<video src>` 也会被 CSP 拦掉。
- 本地链路已验：`Uint8Array → postMessage → Blob → <video>` 在同一 CSP + sandbox 下可播、可 seek（`readyState 4`，`duration 3`，`currentTime 1.5`）。
- 证据截图：`C:/Project/.scratch/video-notes-spike/shot3.png`（仓库外，任务关闭时删）。
- 结论：在线播放器这一层**不是代码没写，是安全边界不允许**。不要为了它放宽插件 sandbox；`allow-same-origin` 一加，插件页面就能碰到宿主窗口。

## 2. 范围

- 做：
  - 宿主媒体视图原语（MED1）：本地文件流式播放、在线原生网页内嵌、播放状态与截图等受控操作。
  - 本地优先的视频笔记插件（VID1）：代码块内嵌播放器、视频文件编辑器、时间戳、字幕、截图、位置、AI。
  - 在线视频的两阶段：先 `layout.openWebPage` 原生标签过渡；MED1 落地后接内嵌。
- 不做：
  - 放宽插件 webview 的 sandbox 或 CSP。
  - 在插件页面里自绘第三方平台播放器。
  - 本地/云端 ASR 的具体实现（只留接口位置）。
  - 把视频做成核心编辑器的媒体节点（除非 MED1 落地后另裁）。

## 3. 为什么在线播放不能留在插件

插件现在能拿到的媒体能力只有“读文件 → 内存 → Blob 播放”：

1. **沙箱**：所有插件页面都是 `sandbox="allow-scripts"` 的 opaque origin；平台播放器依赖自己的 origin，B 站实测黑屏，YouTube 同机制下大概率一样。
2. **CSP**：`media-src` 不允许远端 https；直链视频即使能下载也放不进 `<video>`。
3. **无 Range**：`files.read` / `document.readFile()` 是整文件；大视频只能整段进内存。
4. **无进程、无 cookie**：插件不能起本地代理、不能读登录态；`net.fetch` 不带 cookie，平台接口（字幕、清晰度）大多拿不到。
5. **不能控制原生标签**：`layout.openWebPage` 能开真 webview（可登录、可高清），但插件没有 `navigate/evaluate`，拿不到 `currentTime`，也截不了帧。

所以在线播放必须由宿主提供“可控原生表面”；插件只负责笔记。

## 4. 宿主媒体视图原语（MED1）

### 4.1 能力

在现有 `webPages.show(id, url, { x, y, width, height })` 的原生网页标签定位能力上，抽出一个**媒体表面**：宿主持有原生 webview 或本地播放器，插件/编辑器只给一个矩形和媒体源。

- **本地源**：打开文件夹内的媒体文件，或用户显式打开的文件；宿主用自定义协议/Range 流式读，不再整文件进内存。
- **在线源**：宿主原生 webview 加载平台页面（B 站/YouTube），宿主注入最小控制脚本，读取播放状态并执行 seek。
- **表面嵌入**：媒体表面跟随一个 DOM 占位元素的位置与尺寸（分栏、滚动、全屏、缩放都要跟）。
- **状态**：`currentTime` / `duration` / `playing` / `buffered`，变化事件。
- **截图**：本地源可直接截帧；在线源由宿主侧截图（是否可行单列验证，见 §8）。

### 4.2 草案 API（名字待定）

```ts
// 只在宿主内部与插件 broker 之间；不向插件暴露 DOM/cookie/任意 eval
textus.media.open({
  source: { kind: "file"; path: string } | { kind: "web"; url: string },
  element: HTMLElement,        // 占位元素，表面跟随它
}): Promise<MediaHandle>

handle.play(): Promise<void>
handle.pause(): Promise<void>
handle.seek(seconds: number): Promise<void>
handle.state(): Promise<{ currentTime; duration; playing; buffered }>
handle.screenshot(): Promise<Uint8Array>   // PNG
handle.onDidChangeState(listener): Disposable
handle.close(): Promise<void>
```

实现要点：

- 原生 webview 的定位复用 `webPages.show/hide` 已有的矩形同步与遮挡处理（`useNativeWebPage`）。
- 本地媒体走 Tauri 自定义协议，响应 `Range`；WebView2 / WKWebView 的 206 行为要先验证。
- 在线控制脚本只读 `video.currentTime` / `duration` / `paused`，只写 `play/pause/currentTime`；不把页面对象交给插件。
- 插件侧的权限沿用 `network:<host>`；本地文件沿用 `files.read` 的文件夹边界。

### 4.3 安全边界

- 插件拿到的只有播放操作与状态，拿不到页面 DOM、cookie、登录态。
- 在线源只允许用户/清单认可的站点；`network:` 授权仍逐 host 展示。
- 媒体表面是宿主画的，不是插件 HTML；插件关闭/卸载即销毁。
- 截图只返回像素，不返回页面内容；在线截图先验证再承诺。

### 4.4 不做什么

- 不做通用的“插件内嵌任意网页 + 脚本注入”能力；媒体是收窄的用例。
- 不做第三方平台的下载/去广告/绕过登录。
- 不把媒体表面变成第二个浏览器标签体系。

## 5. 视频笔记插件（VID1）

### 5.1 两种形态

1. **代码块 ` ```video `（主形态）**
   笔记本身就是“在前的文档”，所以“插入当前时间”可以直接进光标处，不需要拆窗。块内画播放器、字幕列表和按钮；块的 fence 保存视频路径与可选参数。
2. **视频文件的自定义编辑器（辅形态）**
   文件树里双击 `.mp4/.webm/.mov` 打开大播放器标签，记住上次位置；像 pdf-viewer 一样用 `customEditors` + `document.readFile()`，支持 `#t=` 定位（前提见 §5.5）。

### 5.2 功能

- 播放、暂停、倍速、快捷键、音量、全屏、播放位置记忆（`storage.global`）。
- **插入当前时间**：`editor.insertText` 写 `[00:12:34](视频路径)`；代码块页面按钮 + 全局命令/快捷键两种入口。
- **正文时间戳跳转**：
  - 插件内：字幕/笔记列表点哪跳哪。
  - 正文：先用 `editor.registerDecorations` 的 `gutter` + `command`（边栏播放图标）绕开；若核心把文件链接的 `#t=` 透传（见 §5.5），再改成直接点链接。
- **字幕**：导入 `.srt/.vtt`，逐句点击跳转、搜索、自动滚动、复制带时间的引用。
- **截图**：本地视频 canvas 截帧 → `files.write` 写 PNG → 插入 `![](相对路径)`。
- **AI**（有字幕/文稿时）：`ai.model` 生成章节、总结、要点、问答；`aiTools` 让 Textus AI 在聊天里查“12:00–15:00 讲了什么”。无字幕只能基于用户笔记，或等 ASR。
- **在线过渡**：`layout.openWebPage` 打开 B 站/YouTube 原生标签，时间戳用 URL `?t=` 打开到对应时间；MED1 落地后换成内嵌表面。

### 5.3 权限与平台

- 权限：`files.read`、`files.write`、`editor.read`、`editor.write`、`ai.model`、`ai.tools`、`project.data`。
- 平台：先 `desktop`（Windows/macOS/Linux）。手机后续单独评估：大文件 Blob 内存、iOS 无 Textus AI、触屏播放器交互都要重做。
- 文案十语言；图标与控件用 Textus 的 token。

### 5.4 限制（写进插件的说明，不藏）

- 本地视频必须在打开的文件夹内；文件夹外的文件只能作为独立文件标签打开。
- 没有 MED1 时，本地播放是整文件 Blob：建议 ≤300–500MB；1–2 小时 1080p 可能 1GB+，有内存风险。
- 没有本地 ASR：无字幕的视频，AI 只能处理用户提供的文稿或笔记。
- 在线字幕抓取待验证（`net.fetch` 无 cookie；B 站/YouTube 接口可能拿不到）。
- 在线截图、在线取当前时间依赖 MED1。

### 5.5 需要核心配合的小改（可与 VID1 同批或单独立项）

1. **文件链接 `#t=` 透传**：`src/editor/markdown/link-target.ts` 目前对非笔记文件只返回 `{ kind: "file", path }`，`follow()` 也只传 `{ linked: true }`，fragment 被丢掉。改完后正文时间戳可直接打开播放器到时间，PDF 的 `#page=` 也顺带受益。
2. **大文件流式读取**：MED1 的自定义协议/Range；在此之前 VID1 用 Blob。
3. **媒体表面**：MED1 本体。

- P1 只在“本地 MVP 真实用过、在线需求反复出现”后启动；不先为想象的需求做核心改造。
- 若本地 MVP 无人用，VID1 停在插件层，不进入核心。

## 7. 验收

### VID1（本地）

- 30 分钟本地 mp4：播放/暂停/seek/倍速/全屏；关标签再开回到上次位置。
- 光标在正文，点“插入当前时间”得到 `[00:12:34](相对路径)`，撤销一步。
- 100 条 SRT：逐句点击跳转、搜索命中、自动滚动；时间格式正确。
- 截图：当前帧 PNG 写到笔记旁的附件目录，插入后富文本/源码/导出一致。
- 300MB 文件可播放；超过阈值有明确提示，不静默 OOM。
- AI：用一段 SRT 生成章节/总结，写入笔记；`ai.available()` 为 false 时按钮禁用并说明。
- 桌面三平台冒烟；无控制台错误；插件页可正常关停。

### MED1（宿主）

- 2GB 本地视频流式播放，内存不随文件大小线性增长；seek 正常。
- B 站视频内嵌：可播放、可 seek、可读 `currentTime`；登录态正常；表面跟随分栏/滚动/全屏。
- 插件只能拿到播放状态，拿不到 DOM/cookie；关闭即销毁。
- WebView2（Windows）与 WKWebView（macOS）都过；Linux 走网页标签降级。

## 8. 未决与触发点

- **在线截图**是否可行：宿主侧截原生 webview 的平台差异；不可行就只做本地截图。
- **在线字幕抓取**：B 站/YouTube 在无 cookie 下能拿到什么；拿不到就走“用户导入 SRT/粘贴文稿”。
- **ASR**：用哪家、key 存哪、是否只在桌面；未定前不做。
- **手机**：VID1 是否进 Android/iOS；iOS 无 Textus AI，播放器交互要另设计。
- **是否升级为编辑器媒体节点**：若 MED1 证明稳定，再裁是否把视频做成核心节点（而不是插件页/代码块）。
- **上游合并成本**：MED1 是核心改动，跟 tag 时要单独核对；不把 fork 的媒体实现当上游 PR。
